# Bundled font and mapping data provenance

The 14 files under `fonts/*.pfb` are byte-identical to the corresponding files in
the Debian-distributed upstream archive
[`gsfonts_8.11+urwcyr1.0.7~pre44.orig.tar.gz`](https://deb.debian.org/debian/pool/main/g/gsfonts/gsfonts_8.11+urwcyr1.0.7~pre44.orig.tar.gz).

Verified on 2026-10-13 with `cmp` for every PFB. Archive SHA-256:
`9f2a598998bf05e023546ac981aa2a857aa1635d2e0e3020a3c3004ad564dc00`.
No bundled font binary was replaced.

The upstream archive contains GPL version 2 in [COPYING](licenses/gsfonts-COPYING),
and describes its document-embedding exception in [README](licenses/gsfonts-README).
[README.tweaks](licenses/gsfonts-README.tweaks) is also retained. Text is copied
without substantive changes; the missing final newline in upstream README is
normalized in this repository.
Copyright notices remain in each font, including URW++ and Valek Filippov.
These files are not relicensed under the repository's root LICENSE.

This is a source/notice inventory, not a blanket statement about downstream
licensing obligations. Modern URW font releases are not the provenance reference
for these historical binaries.

## Adobe Core 14 AFM metrics

All 14 `afm/*.afm` files match the corresponding Apache PDFBox comparison
files with whitespace/blank lines ignored (`diff -w -B`). No metric differences
were found. Comparison commit: `7e6236667447bf17b9ab3bc5191ed6b04388a8cc`;
[upstream directory](https://github.com/apache/pdfbox/tree/7e6236667447bf17b9ab3bc5191ed6b04388a8cc/pdfbox/src/main/resources/org/apache/pdfbox/resources/afm).
The repository copies have different whitespace/blank-line formatting; this is
not a byte-identical provenance claim. Existing Adobe copyright notices remain.
The accompanying upstream [MustRead.html](licenses/Adobe-Core14-MustRead.html)
is retained without changing its permission paragraph. It is not the PFB license.

## CMap data: verified-source replacement

On 2026-10-13, 11 standard CMaps without embedded permission statements were
replaced with byte-identical copies from Adobe's official
[20190730 release](https://github.com/adobe-type-tools/cmap-resources/tree/ecd209bb8c9b7d9a4a7e58900df179cefb92abbb),
commit `ecd209bb8c9b7d9a4a7e58900df179cefb92abbb`, under BSD-3-Clause.
Their original Adobe notices are retained; the accompanying
[license](licenses/Adobe-CMap-LICENSE.md) is copied without changes.
[cmap-provenance.json](cmap-provenance.json) records every replacement's upstream
path and SHA-256, plus the license hash and pre-replacement behavior fingerprints.
The historical release was selected to preserve existing mapping behavior rather
than introducing mapping updates in a license repair.

The other 54 CMaps retain their existing Adobe notices, whose distinct verbatim
blocks are collected in [Adobe-CMap-NOTICES.txt](licenses/Adobe-CMap-NOTICES.txt).
All 65 current CMap files have Adobe copyright and redistribution statements.
Binary distributors must include the applicable copyright, conditions and
disclaimers (both CMap notice/license files above); `build.rs` strips comments
from generated byte arrays. This does not relicense the whole project as BSD.

The five nonstandard factoring helpers `GBK-X`, `UniCNS-X`, `UniGB-X`,
`UniJIS-X` and `UniKS-X` were removed. The 11 standard replacement maps are
self-contained, and no bundled map still refers to those helpers. Standard
horizontal/vertical names remain available, including inherited half-width
variants. Direct use of the removed nonstandard helper names is no longer
supported; callers should use the corresponding standard encoding.

Run `python3 docs/check-cmap-data.py` from the repository root to verify hashes,
notices, dependencies and the 24 affected standard encodings' effective CID
mappings, codespaces and WMode. The Rust CMap regression independently checks
the same fingerprints through the production parser. The Python checker is not
a general PostScript interpreter; it covers the registered CID mapping subset.

Previously, the 16 unannotated files matched MuPDF commit
`a8afa1d1ad5db3809ad3aaca185dc0f1476e9a27`. The current-tree repair replaces or
removes all 16 rather than assuming their license from that match. Historical
commits were not rewritten, and their licensing status is not retroactively
changed. The repository root license and unrelated font programs are unchanged.
