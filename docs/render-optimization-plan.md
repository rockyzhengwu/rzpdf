# 渲染失败与性能优化清单

更新日期：2026-10-26。依据[首轮实测](benchmark-baseline-2026-10-26.md)与本地
`output/benchmark-combined-20261026/` 原始记录。以下保留最初的问题与实施边界；
当前已完成的修复、收益和仍存差异见[优化验收](render-optimization-results.md)。

后续实现状态以优化验收记录为准，以下表格保留发现问题时的数值。
首轮 MuPDF 适配器的非空 separations 构造已证实会进入额外转换通路，其耗时与
颜色列只作为历史记录；修正后的完整对比位于 `output/benchmark-optimized-20261026/`。

14 类输入、28 个样本／DPI 组合，16 个通过三方图像检查。其余 12 个中：
7 个是 rzpdf 明确报错，5 个是能够渲染但图像差异超过门槛。252 次计时试验中
231 次成功、21 次报错，没有 trap 或超时；失败次数不等于独立缺陷数。

所有性能数据均为原生 Release，含 owned RGBA 输出，不含 PNG 编码。当前没有
CPU 采样或逐函数分配证据，下面的排查方向是候选原因，不是已经确认的根因。

## 一、失败与输出差异

| ID | 优先级 | 输入／DPI | 已观察到的现象 | 状态 |
|---|---|---|---|---|
| RF-01 | P1 | `text-sparse`、`text-dense`、`text-multipage`，72／144 | Type1 字体报缺少可绘制字形；6 个组合、18 次计时报错 | 待定位兼容性问题 |
| RF-02 | P1 | `curves`，144 | `canonical curve coverage work`；1 个组合、3 次计时报错 | 待分析工作量及预算 |
| RF-03 | P1 | `jpeg-scan`，72／144 | RGB 平均误差超限，72 DPI 与 MuPDF 的墨迹面积比也低于门槛 | 待确认采样／颜色差异 |
| RF-04 | P2 | `cjk-dense`，72／144 | 三套引擎两两比较均超过 RGB 误差门槛，墨迹位置基本一致 | 待判定字重／抗锯齿差异 |
| RF-05 | P2 | `rectangles`，72 | rzpdf／MuPDF 与 MuPDF／PDFium 的 RGB 误差超限；144 DPI 通过 | 待判定细描边覆盖差异 |

### RF-01：嵌入式 Type1 字体

错误为 `font 'Nimbus Sans L Regular' has no drawable glyph for character code 49`。
输入使用仓库已有的 `font-data/fonts/n019003l.pfb`，由 PyMuPDF 嵌入；MuPDF 和
PDFium 均能渲染。不能据此宣布所有 Type1 都不支持。

- 排查 PDF Encoding／Differences、字符码→glyph name／GID、嵌入程序和后端
  typeface 创建、空轮廓判断。入口：`render/src/render_device.rs` 的缺失字形错误分支，
  再沿对应字体解析和映射路径追踪。
- 保留原始失败输入，并缩减成至少包含字符 `1`、正常可绘制字符及空格的最小例子。
- 验收：三个原始输入在 72／144 DPI 均可渲染；字符形状／位置正确，空格不误报，
  无替换字体掩盖映射问题；相关字体定向回归及独立像素检查通过。

### RF-02：密集曲线的覆盖计算

输入包含 1,000 条三次贝塞尔曲线。72 DPI 可完成，144 DPI 超预算。
`render/src/render_device.rs` 的 canonical coverage 路径包含全局 cell、轮廓点和
采样工作量计费；具体是否过度计费或确有大量工作，需要计数和采样确认。

- 记录路径数、轮廓点数、访问 cell 数、采样面积、工作预算消耗以及实际耗时。
- 检查每个 cell 是否重复处理整条大路径、不可见范围是否仍参与计算，以及可复用
  的覆盖／描边结果。缩减输入时保留 144 DPI 失败特征。
- 验收：原始输入在默认预算下完成 144 DPI 渲染且无 trap；若经分析属于合理拒绝，
  必须记录成本证据和明确支持边界，不能当成已经修复。保留超复杂输入的有界拒绝测试。
- 必须保留整页／分块一致性、描边／裁剪／透明合成语义；不以提高预算代替分析。

### RF-03～05：图像差异需要先判定原因

- 扫描图：逐项检查 JPEG 解码尺寸、降采样、PDF `Interpolate`、采样坐标、颜色转换，
  使用局部放大图／差异图与简单独立图案验证。144 DPI 的 RGB 平均误差约为
  rzpdf／MuPDF 0.041、rzpdf／PDFium 0.033（门槛 0.03）。
- 密集中文：先检查字符位置、轮廓、缺字与字体替换，再隔离 hinting、灰度覆盖和
  抗锯齿差异。MuPDF／PDFium 自身也未通过当前门槛，不能单凭门槛认定 rzpdf 错误。
- 细矩形：检查线宽、像素中心、半像素定位、色彩和覆盖；比较 72／144 DPI。
  不把“看起来更淡”直接等同于颜色空间错误。
- 验收：每组形成可复现的归因和局部对照证据。语义错误补确定性回归后修复；合理
  后端差异单独记录。若需改图像门禁，应使用独立正负例校准、记录规则变化并重算
  原有质量结果，不为纳入速度统计直接放宽阈值。

## 二、性能优化点

以下表格均来自通过质量检查的输入；耗时单位为 ms。倍数仅用于排列调查优先级。

| ID | 优先级 | 场景 | rzpdf | MuPDF | PDFium | 候选排查方向 |
|---|---|---|---:|---:|---:|---|
| RP-01 | P1 | 曲线，72 DPI 重绘 | 157.96 | 40.05 | 7.94 | cell 遍历、轮廓重复栅格化、覆盖 span 提交 |
| RP-01 | P1 | 矩形，144 DPI 重绘 | 150.05 | 39.49 | 16.25 | 简单描边是否走昂贵通路、路径批处理 |
| RP-02 | P1 | 小 JPEG，144 DPI 重绘 | 154.91 | 47.00 | 40.30 | 图片采样、颜色转换、后端图片创建／重复转换 |
| RP-02 | P1 | Flate 图片，72 DPI 重绘 | 141.19 | 17.72 | 10.94 | 公共绘图路径、逐像素转换及缓存复用 |
| RP-03 | P2 | 空白页，144 DPI 重绘 | 11.65 | 2.64 | 2.22 | surface 创建／清空、白底合成、RGBA 分配／读回 |
| RP-04 | P2 | TrueType 文字，144 DPI 首次页面 | 62.74 | 81.13 | 12.95 | 字体首次加载、typeface／glyph 缓存、准备成本 |
| RP-04 | P2 | TrueType 文字，144 DPI 重绘 | 11.54 | 30.82 | 4.89 | 基础画布成本、字形回放及 owned RGBA 输出 |

### RP-00：先补可解释的测量

- 在独立诊断模式拆分 prepare、replay、RGBA 输出；必要时细分字体创建、图片解码／
  转换、路径覆盖、surface 创建与清空。诊断开关默认关闭，性能总计时保留原边界。
- 对 RP-01／02／03 分别做 CPU 采样，记录运行参数和主要栈；不让采样／日志计时
  混入正式基线。先确认当前环境可用工具，再决定是否安装依赖。
- 记录分配次数／字节及缓存命中信息时，区分估算、实际分配和 OS RSS。
- 首次文字样本的现有分阶段数据提示：耗时主要落在首次 raster 阶段，不能简单
  归咎于 PDF 文件打开。例如 TrueType 144 DPI 三次试验的阶段中位数约为
  open 1.91、prepare 11.25、raster+RGBA 50.08 ms；不同阶段中位数不必相加等于总中位数。

### RP-01：矢量覆盖路径

和 RF-02 联合分析。评估局部轮廓／覆盖复用、减少重复 cell 工作、简单图形通路及
draw call 数量。只有在效果等价得到证明后才引入快路径；不能破坏 canonical
全局采样所维护的整页／分块一致性，也不能无条件替换成后端默认栅格路径。

### RP-02：图片绘制与重绘复用

入口包括 `pdf/src/page/pdf_image.rs` 及 `render/src` 的图片转换和绘制路径。
JPEG 与无损 RGB 图片都慢，说明值得优先检查公共回放路径；这不是已确认的根因。
显式保留 PreparedPage 后仍然慢，也不代表缓存必然没有命中。

评估已解码数据／后端图片的有界复用、重复颜色转换消除和批量处理。缓存必须具备
文档身份／revision／色彩／DPI 等正确键，限制字节和生命周期，可清理；不能通过
长期保留大量 RGBA 换取分数。降采样须先满足 RF-03 的正确性要求。

### RP-03：基础画布与输出开销

空白页揭示可独立测量的固定成本。`SkiaRender::to_rgba()` 当前包含 owned Vec
分配／初始化与 `read_pixels`，但其在 11.65 ms 中的占比尚未测得。
先分离 replay 和读回，再评估 buffer／surface 复用和重复清空消除。保持完整 RGBA
输出、白底、alpha、行布局及资源预算；改变为借用 buffer 的 API 必须另行说明，
不能直接和 owned 输出结果混比。

### RP-04：首次字体成本

先区分字体解析、后端字体创建、字形映射及首次回放。评估文档内可复用对象，保留
字体替换规则与修订失效策略。后续扩充多字体／复杂脚本输入后再决定跨页缓存范围，
不以当前重复短句样本外推任意文字性能。

## 三、实施顺序与验收

1. **正确性与测量**：RF-01、RP-00；定位 RF-02／RP-01，并调查 RF-03。
2. **主要热点**：完成 RP-01、RP-02；以 RF-02 的资源限制和 RF-03 的图像差异约束实现。
3. **公共成本**：完成 RP-03，再依据采样处理 RP-04；并收敛 RF-04／05 的差异分类。
4. **复测与扩展**：原有 28 个组合重新检查，比较同一批输入的前后耗时及内存；
   再补真实许可样本、高 DPI 区域和浏览器 Worker 测试。原生结果不能代替 WASM 验收。

每个实现单独提交，写明输入、改动、前后指标和剩余限制。修复前将最小重现补入
确定性回归，原始大样本继续保留；不能只让简化样本通过。

性能验收建议使用同机安静环境、至少 5 次独立试验，继续保留 raw 数据、默认预算、
owned RGBA 和质量门禁。以热点场景 **中位数降低至少 20%** 作为首轮优化目标，
这是待验证目标，不是交付承诺。其他代表场景如出现超过约 10% 的退化，应复测
并解释噪声／取舍；不将单次抖动作为自动失败，也不承诺一步追平 PDFium。

## 四、复现入口

环境安装和 release 构建见[基准指南](benchmarking.md)。生成完整样本后，例如：

```sh
python3 scripts/prepare_benchmark_corpus.py output/benchmark-corpus
python3 scripts/benchmark_pdf.py \
  --manifest output/benchmark-corpus/manifest.json \
  --output output/benchmark-investigation \
  --case text-sparse curves jpeg-scan --dpi 72 144 \
  --trials 3 --warmup 2 --repeats 10
```

使用已安装依赖的 Python 环境，输出目录需为新目录。原始输入和输出保留在 ignored
目录，仓库内的生成器及固定字体可重建样本。文档整理不新增通过数，也不修改阈值。
