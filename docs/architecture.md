## 判断

保留 `pdf`（核心）、`render`（Skia 后端）、`font-data`（字体数据）的工作区结构。对象模型、解析器、内容解释器和 Device 抽象可继续使用。需要优先调整对象状态、页面树、资源生命周期和输入源耦合；高级编辑需要独立内容模型。暂不全面重写或拆成大量 crate。

### 本次架构评审结论

需要调整，但应沿现有实现渐进迁移。当前 `PDFContext` 已有可选 parser，并持有独立 `DocumentState`（ObjectStore、Trailer、源 Header 版本、身份、修订与事务深度）；新建和打开文档共用状态结构，`DocumentStore` 已有变更记录。PageTree、统一最新对象解析及保守解除引用已有实现，应保留并扩展验收。

主要风险不是模块数量，而是状态、预算和编辑语义尚未完全统一：事务快照克隆成本随修改量增长，Limits 不是聚合计费器；公共 Reader 泛型仍传播到文档服务；跨文档引用缺少文档身份契约；渲染结果不能保留完整可编辑来源信息。

架构落地任务及逐项退出条件见 [TODO 架构实施工作包](../TODO.md#架构实施工作包) 的 AR-01～AR-06。优先收口文档状态、事务修订、聚合预算和流/版本策略，再做对象图导入与内容编辑。只有出现明确性能或依赖隔离需求时，才进一步采用 Arc 快照、暂存变更集或拆分 crate；这些优化不是当前功能交付的前置条件。

## 目标分层

### 调整优先级与边界

- 必须优先收口：最新对象可见性、PageTree、事务与共享资源的复制后修改；这些是读写编辑正确性的前提，已有部分实现仍需按 TODO 验收。
- 下一阶段补齐：独立 DocumentState、文档身份/修订号、操作级预算状态、明确的原始/解码流状态。新建入口已经不依赖输入源，但公共泛型尚未隐藏；引入派生缓存时必须同时实现失效规则。
- 内容编辑开始前必须增加 ContentProgram 与来源映射；不能反向编辑 DisplayList 或直接替换任意 UTF-8 字节。
- 暂缓：大量拆 crate、全面重写、提前引入线程安全和增量保存。先完成全量创建/保存及常用页面编辑闭环，再根据性能与部署证据决定。

文档中的目标类型与分层属于迁移设计，不表示这些模块均已存在。近期工作包及退出条件见 TODO 的“近期交付优先级”。

```text
公共 API：创建 / 读取提取 / 页面编辑 / 内容编辑 / 保存
    |
文档服务：PageTree / ResourceManager / ObjectGraphCopier / Transaction
    |
文档状态：ObjectStore / Trailer / 版本 / 变更记录
```

核心不依赖 Skia。解析、写出与内容解释共享对象模型和解析限制，但读取源不成为新建文档的必需条件。

## 1. 将文档状态与读取源解耦（P0/P1）

现有 `PdfDocument<R: Read + Seek>` 和 `PDFContext<R>` 绑定 parser、xref、缓存和修改记录，新建文档必须绕过读取流程；相关泛型也传播到 Page、Font、Color 等模块。

建议引入可选读取源的 DocumentState/ObjectStore，分别提供打开文件和创建空文档的入口。先统一存储抽象，再决定用泛型内部 Source 或 `Box<dyn ReadSeek>` 隐藏读取源；公共文档 API 尽量不传播 R。是否需要 Send 应由实际线程需求决定，当前 RefCell/OnceCell 模型不承诺多线程共享。

已落地内部 `document/state.rs`：不含 Reader 泛型或 Parser，统一持有 ObjectStore、Trailer、源版本、文档身份和修订/事务状态，PDFContext 的状态操作均委托该结构；源 xref、懒加载 OnceCell 和解析器仍属于读取侧。版本来自打开时实际读取的 Header，新建固定 1.7；有效版本继续查询最新 Catalog。旧公开创建/读取/编辑入口保持签名不变。非泛型 facade 的兼容决策与无源初始化已通过 AR-01 原定退出条件；所有底层服务的泛型消除和进一步分离不计作已完成。

迁移初期保留 open/from_bytes/from_reader 与旧类型的兼容入口，逐步减少底层公共模块暴露，避免一次性大范围 API 破坏。

兼容方案已选择渐进 facade：新增 `pdf::document::Document`，内部使用 `PdfDocument<Box<dyn DocumentReader>>`，统一新建/文件/字节/拥有所有权 Reader 的公开文档类型；旧 `PdfDocument<R>` 保留，不破坏现有推导和借用 Reader。`Document::new` 共用无输入源状态构造，不创建空 Box Reader。通过 Deref 委托页面/资源/保存服务，事务闭包显式接收 `&Document`。拥有所有权输入要求 `'static`，不承诺 Send/Sync；借用源仍走旧 API。底层 PdfPage/ResourceManager 等类型暂仍带擦除 Reader 参数，后续逐项收口而非宣称全 API 已隐藏泛型。

无源初始化：`PdfDocument::new/new_with_options` 与 `Document::new/new_with_options` 直接初始化 Catalog/Pages/Trailer，不创建 Reader 或解析模板。旧入口保留 `PdfDocument<Cursor<Vec<u8>>>` 兼容类型参数，但内部无 Cursor 实例；新 facade 统一公开 Document 类型。Trailer 由 DocumentState 持有，打开时从解析 xref 移交，不额外克隆，之后根访问与保存均读取同一状态。缓存修订标记已提供，统一缓存层和所有底层类型消除泛型仍待后续推进。

## 2. 统一对象解析与变更记录（P0）

原有 `resolve_object_id` 读取原始缓存、owned 入口优先读取 DocumentStore，曾产生两套可见性语义。P0-05 已统一普通解析入口读取最新状态，并提供显式原始快照入口。

规定普通 resolve/get 始终读取最新状态：修改优先于原始对象，删除返回错误。读取原始版本必须使用单独命名的接口。统一入口需要同步处理 root、page、resource、font 等调用链。

不能继续直接返回可能被修改的缓存对象的长期借用。可先采用 owned 对象保证正确性，再按性能证据使用 `Arc<PdfObject>` 快照减少克隆；更新替换快照。缓存按文档修订号失效，页面、解码流、DisplayList 都不能复用旧版本结果。

保留 Added/Modified/Deleted 变更分类和原始位置，为增量保存准备数据，但 P0 不实现增量输出。

## 3. PageTree 成为单一服务（P0）

原有 PageTree 是空结构，Catalog 与 Document 编辑各自遍历页面。P0-03 已统一读取和编辑的页面遍历、继承解析及校验。后续把插入、删除、重排、祖先定位和 Count 更新进一步收口到同一服务，避免公共入口再次分叉。

页面顺序统一为按 Kids 顺序深度优先。MediaBox、CropBox、Rotate、Resources 等属性按继承规则解析；跨文档导入时显式化必要属性。加入路径循环检测、深度限制和一致性检查。移除或委托 Catalog 中未实现的增删接口。

## 4. 对象图与资源生命周期（P0/P2）

PDF 是可共享、可循环的对象图。删除页面应先解除页面树引用；替换内容应先替换 Contents 引用。共享内容流、字体、图片不能依据局部操作直接删除。

P0 使用保守保留策略，避免误删。P2 提供显式从 Trailer/Root 等文档根出发的可达性扫描与清理，保留未知扩展引用。增量模式不删除历史字节，脱敏需求另用全量重写与残留检查。

ResourceManager 负责字体/图片注册、名称分配与同文档复用。ObjectGraphCopier 负责跨文档 ID 映射、循环处理、继承属性、资源冲突；同一次导入用映射表保留共享关系。复制后的共享资源编辑采用复制后修改策略。

已提供文档身份迁移入口 `PdfDocument::identity()` 和 `object_handle(id)`。身份采用保活的进程内分配标记，不写入 PDF；同一文件重新打开产生新身份。`resolve_handle`/`update_handle`/`delete_handle` 和 `ResourceManager::register_handle` 在操作前验证文档归属，即使外来对象的号码与本地对象相同也拒绝。裸 ObjectId 接口为兼容保留，仍由调用方保证归属，不能声称所有入口已自动隔离。句柄表示文档内地址、跟随后续更新，不是不可变快照或对象生命周期令牌；事务内新建句柄不得在提交前外泄，回滚后 ID 可能重新分配。对象图复制和稳定的分配生命周期契约仍待实现。派生缓存键应组合文档身份、修订号和对象/页面地址。

## 5. 修改事务（P0/P2）

页面操作会同时修改 Kids、Count、页面和内容流。P0-11 已通过修改记录快照实现错误与 unwind 回滚及嵌套事务。后续按性能证据演进为暂存变更集，在验证通过后一次提交；引入派生缓存时配套文档修订号与失效机制。

Info 编辑已将 Trailer 纳入同一事务快照，错误/unwind 同时恢复 Trailer 和对象分配；当前依旧以克隆快照实现，不代表操作级内存计费或统一派生缓存已经完成。

修订号迁移入口为 `PdfDocument::revision()`：它是文档内单调的可见状态失效标记，不是提交计数或文档身份。低层插入/更新/删除及 Trailer 替换成功后推进；读取与保存不推进。事务内写入也立即推进，错误或 unwind 回滚后再推进，绝不恢复旧号，避免临时状态缓存与恢复状态使用相同标记。空成功事务不推进，失败事务保守失效；计数耗尽前拒绝修改，活动 savepoint 预留回滚号段。后续派生缓存必须同时绑定文档身份与此标记，不能把跨文档同号当作命中；当前尚未新增统一缓存层或提交次数 API。

先覆盖页面增删和内容替换，再扩展到导入、合并与高级编辑。低层任意对象修改仍需文档校验，明确哪些接口保证结构一致性。

事务快照、回滚守卫、嵌套 savepoint 及修订号额度预留已迁入无 Reader 泛型的 DocumentState；PDFContext 的事务入口仅委托状态服务。独立状态可直接执行事务，不需构造解析器。对象存在性及源对象计数检查仍需结合读取侧信息，尚未全部迁入状态；快照克隆成本和操作级预算也仍待收口。

新增独立提交标记 `commit_revision()`：事务外每次成功低层写入推进一次，嵌套事务内写入只在最外层成功且有保留的修改时推进一次。错误、unwind、只读事务不推进；内层回滚恢复外层的 dirty 状态。提交容量在编辑前检查，失败不执行编辑。它不是缓存键：事务中可见的临时状态与回滚仍以 `revision()`/DocumentStamp 失效。新文档初始化的低层写入也计数，因此调用方应捕获基线后比较差值，而非假设新文档计数为零。

## 6. 分开可编辑内容与渲染结果（P3/P4）

当前预算检查分层如下，各层没有共享一个跨组件峰值额度池，AR-03仍未完成。

| 层 | 计数与上限 | 时机与释放 |
|---|---|---|
| 源内容解释 | 操作数、字符数及源路径段等既有限额 | 解析/解释时检查 |
| q/Q状态栈 | 活跃裁剪段副本累计 ≤ max_path_segments | q克隆前检查，Q出栈释放 |
| DisplayList收集 | 对象数 ≤ max_objects；图片/软蒙版样本＋Unicode实际字节 ≤ max_decoded_bytes；几何＋裁剪副本段累计 ≤ max_path_segments | 提交成功后计入，集合销毁释放实际对象 |

Device的默认放行只读preflight_draw让内部TraceDevice在文字/路径图形状态克隆前、图片解码前检查对象数/留存段；事件回调仍复核。图片和Unicode载荷需生成后准确检查，字符码长度不能代替Unicode字节数。五段裁剪留存在两图片对象中需十段留存额度；反复qQ只按活跃栈副本计费。

内部DisplayList收集不构建未使用的调试XML，Vec增长采用可失败分配；公开TraceDevice::new仍保留XML跟踪，不自动继承文档限额。尚未统一计费字符串/Vec容量、来源/字符/状态结构、字体及映射缓存、解码临时峰值、replay克隆和原生渲染内存，不把这些局部检查称为完整Budget。

### AR-03 接入顺序与所有权要求

预算字节所有权转移入口统一为既有into_reserved_parts：移除保存侧重复的into_owned_parts，压缩载荷、对象流、字体和解析路径共用同一内部(Vec, MemoryLease)转移约定。转移不复制载荷或释放capacity额度，接收者必须将租约与数据一起拥有，并在错误/unwind时先销毁数据；此方法仍不作为公共无租约Vec导出。地址/容量/共享池身份与重新包装释放回归提供此原语证据，不代替所有调用路径或AR-03整体验收。

BudgetedDictBuilder的同池契约补强：insert在查找/覆盖/扩容前检查键和值租约属于构建池，即使异池租约为0字节也拒绝；OperationBudget的共享克隆仍视为同池。待插入条目从函数入口按键/值/键租约/值租约字段顺序一起拥有，使异池、条目上限及扩容失败均先释放载荷再释放额度；覆盖旧值亦先销毁旧载荷再交换租约。拒绝不改变已有绑定/表容量与邻居额度，finish仍按原规则移动条目并合并租约，无重复深克隆。此为内部容器所有权收口，不表示整个AR-03完成。

Compressed/ObjStm完整内部保存回归新增合法xref流样本：Catalog/Pages/Page/大字符串四对象压缩存于ObjStm，覆盖原始与Flate编码、Preserve与FlateUnencoded四种组合。冷保存小额度拒绝后根/大字符串/源ObjStm缓存均未发布、额度归零且修订号不变；随后更新压缩对象，再以充足额度保存，源缓存成功展开但编辑视图仍优先，字节与独立普通保存一致，严格重开保留页面与修改值。结果仅持有输出capacity额度，释放后持久源缓存可保留。此为固定合法样本验收，不代替完整PDF兼容性、持久缓存总量或编码器后端私有内存约束，AR-03仍未完成。

冷源全量保存验收补充：真实保存字节经严格模式打开，未被Catalog引用的64 KiB源流仍保持未加载；仅测试缓存观测方法确认小额度保存被拒绝后该对象未发布、额度归零且修订号不变。充足额度重试在Preserve/Flate策略下与独立普通保存字节一致，结果存活仅保留输出capacity额度；源缓存成功后转为持久内存，释放结果后缓存可保留，普通/预算再保存和页面内容读取一致。此用例覆盖普通xref条目对应的流对象冷加载，不代替Compressed/ObjStm完整保存、持久缓存总量或后端私有内存验收，AR-03保持未完成。

压缩暂存工作区继续收口：核对锁定flate2 1.1.9的zio Writer发现其另有32 KiB Vec；预算路径改用低层Compress和显式32 KiB固定容量Vec暂存区，先同池预留再分配并校准实际capacity，在创建编码器前持有该额度，通过total_in/out推进并检查无进展/完成状态。输出仍使用几何预算缓冲，避免高层适配器的隐藏暂存Vec；普通保存保留原编码路径。miniz_oxide 0.8.9的CompressorOxide/Huffman/LocalBuf等私有状态仍分配在后端，不能仅凭外层size_of估算为已计费；AR-03与公共预算保存门槛保持未完成。下方段落为此前阶段记录。

Font 内部统一预算编码分派现供顶层整串、TJ 单项、单字符串/跨 TJ 范围及嵌套 Unicode 编辑使用：Simple 与 Type0 均在编码前预留输出请求容量，后者与现有编码器一致按 Unicode 标量数乘 4 请求容量，即使实际输出较短仍按留存 capacity 计费。两者均返回携带租约的只读 BudgetedBytes。页面编码入口显式接收同次操作的预算句柄，不再返回裸 Vec；字体临时表及后续对象/解释/提交组件仍未合计计费。

SimpleFont Unicode 编码先预留按标量数请求的输出容量，再返回 BudgetedBytes；多标量映射可能输出更少字节，但 Vec 仍保留请求容量。Simple 映射数组/字符串及后缀表未计费。实际分配器额外容量仍在分配后核对，不构成瞬时分配峰值保护。

顶层 `replace_page_text` 与 `replace_page_text_array_item` 经页面预算编码入口取得 BudgetedBytes，并保留至内容提交结束。此接入覆盖既有字体整串 Unicode 替换的返回载荷，不覆盖编码器内部临时分配或后续 ContentProgram/事务峰值；额度不足在修改文档前返回 ResourceLimit。

跨 TJ 范围结果现返回私有 `BudgetedTextReplacements`：结果数组槽位、所有选中字符串容量及租约统一所有权，仅暴露只读切片；底层接受外部租约的构造函数已收为模块私有。顶层保留该所有者至提交返回，嵌套保留至链提交返回，借用表仍独立持有同池额度。此项取代下文较早记录中的“跨 TJ 数组采用外层独立租约”，但不覆盖其他未计费组件。

单字符串范围结果以 `BudgetedBytes` 持有：计划长度在分配前预留，内部 Vec 转移构造不复制载荷，核对实际 capacity，缓冲与租约保留到提交结束。跨 TJ 数组由专用结果所有者持有租约。字体源结构、ContentProgram、Form 链和事务等尚未贯通，不能据此宣称完整峰值预算。

跨TJ项入口现也计费选中字符串的结果缓冲容量：规划总长度先预留，再逐项核对实际capacity，编码与所有替换缓冲共享同池；调用方持有结果租约至顶层/嵌套提交返回。未选字符串只是借用，不重复计费。结果数组元数据与借用表均按槽位容量计费并一次预留，字体/源码/对象/缓存/保存成本仍待贯通；早期“跨TJ只计编码”的记录由此更新，但并非完整操作峰值保护。

嵌套单字符串范围生成新结果时旧编码缓冲仍计费，赋值销毁旧所有者才释放额度；新所有者保留到 commit_nested_edit 返回。跨 TJ 结果数组及借用表也已计费，Form 链/重建源码/对象克隆仍未接入。

各已接入 Unicode 编辑入口每次创建一个 Limits 操作池，并在该调用内部共享；池不跨独立调用合并。解析、字体源结构和完整编辑/保存管线尚未接入，现有局部限制不是端到端峰值保证。

Limits现提供独立max_operation_bytes（默认512MiB）及operation_budget()工厂。该字段不替代max_decoded_bytes/max_cached_stream_bytes；同次操作必须创建一次并传递共享句柄，反复调用工厂会生成独立池。旧解析/编辑/保存入口尚未自动执行此额度，不能仅配置该字段就宣称端到端峰值受控。新增Limits字段意味着下游完整结构体字面量需补字段，使用..Limits::default()的调用保留默认行为。

`budget::BudgetedBytes`现将私有Vec与租约绑定，返回/移动不会提前释放，try_clone为副本另行预留同池额度；仅提供字节只读访问，不提供丢失租约的裸Vec转换。复制先预留请求长度，分配后按实际capacity核对；分配器超额容量的核对晚于分配，因此它是留存容量限制，不证明分配器瞬时或整个进程峰值。try_extend_from_slice在增长时为旧/新缓冲共存另行计费，容量内追加不分配，失败保留原所有者。其他可增长容器以及字体/编辑/缓存/保存接入尚未完成。

字符码边界/数量校验已使用Font/CMap受限访问器，Type0编码读回也不再保留完整字符数组；这些优化减少临时分配，但不提供跨组件峰值约束。现有ExecutionBudget仅累计一次解释树的工作量，不能用于可释放的活跃内存计费。

实施顺序如下；共享池、配置及上述局部接入已有专项证据，完整调用链仍待验收：

1. 增加独立的操作活跃字节额度及共享预算状态，与max_decoded_bytes等单项配置分开。提供可失败的额度预留及不可复制的所有权租约；释放只由租约析构执行，预留失败不能改动计数。
2. 先贯通文字编辑：操作入口创建预算，字体加载/编码、ContentProgram改写和嵌套Form复制传递同一实例。返回缓冲携带租约，返回值仍存活时不可在被调用函数结束处提前释放；克隆必须另行计费，不能复制同一租约冒充独立所有权。
3. 扩展到流解码、图片转换和对象事务快照。计费Vec/String容量及结构数组，不只计len；增长前预留、失败撤销预留，旧/新缓冲共存时分别计费。持久缓存需转入文档级额度或继续持有可追踪租约，不能随操作结束遗漏。
4. 接入保存序列化和渲染缓冲。事务失败及unwind析构释放临时租约，但回滚后仍存活的源/结果对象额度不被错误归零。原生后端不可计费内存单独记录观测方式与限制，不以Rust缓冲额度宣称完整进程峰值。

验收需包含两个单项分别合规但共存合计超限、精确上限、克隆/扩容期间旧新同时存活、返回值转移、嵌套失败与unwind后额度恢复、缓存保留及保存失败。预算原语自身通过测试不等于上述调用链已接入；当前没有可据此勾选的操作级预算交付。

`budget::OperationBudget::new(maximum)`建立单线程共享活跃字节池；克隆预算句柄共享同一计数。`reserve(bytes)`返回不可Clone的MemoryLease，移动租约不释放额度，Drop仅释放自身预留；resize失败保留计数和租约原值。若扩容时旧/新缓冲共存，应为新缓冲另建租约再释放旧租约，不能仅resize模拟共存峰值。原语不自动观察分配、不与Vec绑定、不计Rc管理结构或原生分配；调用方仍须在分配前预留并将租约与实际所有者一同转移。配置及真实操作入口尚未接入。

当前页面 DisplayList 每次调用都重新计算尺寸并解释最新内容，尚无可复用的页面解释缓存；不能将源对象 OnceCell 与派生缓存混为一谈。`PdfDocument::stamp()` 封装文档身份与修订号，`is_stamp_current` 统一判断来源状态是否仍有效；标记不复制/冻结对象，不代表缓存已实现。未来缓存键还必须包含页面/对象地址与操作选项。持有同一个 PdfPage 的编辑及回滚回归用于验证重复解释不会沿用临时内容或尺寸。

现有缓存持有方、生命周期、回归证据与对象流解码依赖隔离缺口见 [缓存生命周期审计](cache-lifecycle.md)。

DisplayList 是绘制结果，不能完整表达原始操作符、流边界、资源使用与未知内容。保留 DisplayList 给渲染和提取，增加 ContentProgram 表示解析后的操作符与操作数，并保存来源映射和必要原始片段。

编辑器修改 ContentProgram，序列化为内容流；Interpreter 将其转换为 DisplayList。对于未知操作符或不支持编辑的内容，保留原内容或明确拒绝编辑。文本编辑必须结合字体编码、字宽、变换与布局约束，不能直接替换 UTF-8 字符串。

已落地的文字/单次图片/路径编辑共用来源快照检查与变化流事务COW提交；图片变换将目标Do替换为明确四操作隔离块，内容拼接比较全部新操作及邻接操作/操作数，不以操作总数相等代替保留性证明。资源注册与内容写回处于同一事务，提交时读取最新页字典，避免覆盖刚注册资源。DisplayList不反向重建编辑源；顶层绘制来源由Interpreter直接记录，私有PageSourceProvenance统一报告/DisplayList与ContentProgram的文档/页/修订配对，当前性另行检查。

图片已有显示空间几何候选查询及显示仿射反算；它们不证明裁剪/透明/遮挡可见性，也不覆盖文字路径命中或Form/内联来源。显示编辑使用已解释的图片矩阵与来源索引，目标源码仍由ContentProgram替换。文字局部编辑直接以有效字体/CMap检查解码字符码边界，不依赖整页绘制，不将Unicode或原始转义字节误当字符码边界。布局补偿、真实字体矩阵、稳定句柄及操作级聚合预算仍待完成。

P4 扩展 DisplayList 的裁剪、组、透明度、软蒙版和 Shading 表达，避免当前 Form/Shading 占位被静默忽略。具体事件设计应由回归样本和渲染状态需求驱动。

## 7. 数字、流与保存模型（P0/P1/P5）

P0-07 已修复 writer 使用经验证的原始数值表达，拒绝非法数值及 NaN/Infinity，并保留源版本。后续新建数值逐步区分整数与实数，整数不经 f32；数值计算接口仍需单独评估精度，不能把序列化修复视为所有计算精度问题已解决。

流模型明确区分原始编码字节和解码内容。修改解码内容时同步更新 Filter/DecodeParms/Length，不能保留与新字节不一致的过滤器信息。未修改的流尽量保留原编码；解码和缓存受 Limits 与修订号约束。

已提供迁移入口 `PdfStream::with_decoded_data`：消费旧流、移除 Filter/DecodeParms/DL，并根据新字节生成精确 Length。`PdfDocument::replace_stream_decoded_data` 在更新间接对象前检查原始与解码字节限额；失败不更新对象。外部文件流（F/FFilter/FDecodeParms）明确拒绝。该接口不自动修改图片尺寸、颜色空间等语义属性，且会影响所有共享引用；页面局部修改仍使用页面内容替换入口。保存时可重新选择 FlateUnencoded，不修改内存中的流。内部已增加 StreamDataState::RawEncoded/Decoded，raw 构造表示按字典编码，解码构造与替换表示无编码参数的新内容；dict/data/state 私有，状态转换保持一致。新建页面内容与 Metadata 共用解码入口，保存读回重新属于 RawEncoded；状态不是 PDF 数据，不参与对象内容相等比较。未建立统一解码缓存或聚合预算；版本特性扫描及完整保存验收仍待推进。

FlateUnencoded 保存时按最新上下文解析 Filter 的连续引用：指向 null 视为未编码，真实非空 Filter 保留原始字节和引用；候选未编码流的间接 null DecodeParms 在输出副本中清理。非空 DecodeParms 不自动猜测含义，仍拒绝压缩。外部文件流不改写；Preserve 的压缩准备不额外解析编码引用，但低版本输出的功能检查会解析Filter。`into_raw_parts` 消费流拆分原始字典/字节，输出准备不必另克隆原始载荷；不代表聚合峰值已受限。

`PdfStream::decode_data` 遇到F/FFilter/FDecodeParms任一字段明确返回UnsupportedFeature，不把内联占位字节冒充外部文件内容，也不读取文件或发起网络请求。该边界与现有替换/压缩策略一致，当前包括字段为null的保守拒绝；不表示实现了外部文件流读取。保存仍保留这类流的字典和原始字节。

Serializer 集中处理名称/字符串转义、数值、xref、Trailer、版本与流长度。SaveOptions 明确全量或增量、压缩和加密策略。P1 优先全量可靠保存，P5 才实现依赖原始字节与变更集的增量保存；签名能力在此基础上独立设计。

原子文件保存内部动作拆分为write/sync/replace，正常入口仍使用write_all、File::sync_all与同目录rename。测试注入同步及替换返回错误，分别覆盖新建/已有目标：sync失败不进入replace，替换失败前已完成sync并关闭写句柄，错误后目标保持不存在或原字节，临时文件清理。File局部绑定晚于路径清理守卫声明，Rust unwind时亦先关闭句柄再清理路径；新建/已有目标在写入、同步及实际rename之前注入panic的六组合回归通过。不承诺成功rename后撤销，也不证明abort、真实磁盘故障、断电目录持久性、Windows替换或并发协调；P1-08整体保持未完成。

保存结构校验要求流是独立间接对象，容器/Trailer/流字典内部只允许间接引用而非直接嵌入流，遵循 [PDF流对象语法](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.4.pdf)。低层构造可以暂存这类对象，但保存会在调用Writer之前明确拒绝；调用方应先插入流对象，再在容器中使用PdfReference。不自动提升为间接对象或改变文档修订号，也不据此声称所有对象图符合性已校验。

保存版本策略已与 effective_version 收口：默认保留 Header 和最新 Catalog /Version，显式 Header 选项不得低于有效版本；压缩最低版本检查也计入 Catalog 覆盖。未知或非法 Catalog 版本在写出前拒绝。此规则只验证版本声明，不代表自动扫描所有对象并完成各版本功能转换；流状态模型与全部特性最低版本检查仍属 AR-04 后续工作。

## 8. 错误、诊断与后端边界（P0/P4）

### 元数据一致性契约（P1-07）

Info 与文档级 Metadata 默认独立编辑，任何一侧的单独修改均不隐式覆盖另一侧。显式 set_info_and_metadata 将两侧修改纳入同一事务，保证失败时一起恢复；语义一致性不由原始字典/packet 接口保证。当前不解析或展开 XML 实体、不自动重写未知命名空间属性。后续若引入字段同步，应明确映射、多语言/多作者及日期规则，默认保留未知属性，并将冲突作为诊断或显式策略，而不能悄悄择一覆盖。

扩展 PdfError，区分格式错误、不支持功能、密码错误、引用错误和资源超限，并携带对象 ID、页号或字节位置。保留底层错误原因。

P0-11 已将 Device 回调改为返回 PdfResult。P0-09 已提供未知/未实现操作符诊断和严格/兼容策略；内联图像因无法安全跳过暂时显式拒绝。ParseOptions/Limits 已部分接入，SkiaRender::with_limits 已可接入同一 Limits 并限制单页表面；整个对象图聚合预算、原生后端开销及多个缓冲区共存时的峰值预算仍未完成。其他字体、颜色与解析内部的输入触发 panic 继续按 P0-08 清理。

Skia 保持独立后端；字体和图像解码的原生依赖可逐步通过 trait/feature 隔离。拆成独立 crate 应基于实际替换与部署需求，不作为前置工作。

## 迁移顺序

### 实施前需要锁定的架构契约

以下为待实施决策，不表示现有代码已具备这些能力：

- **文档身份与缓存**：DocumentState 的 `revision()` 在可见写入及回滚时推进，`commit_revision()` 单独表示成功提交；缓存必须绑定文档身份与 `revision()`，不能仅绑定提交计数，否则事务临时状态可能命中回滚前缓存。页面、资源、解码内容和 DisplayList 的缓存不得在回滚后继续复用临时状态。是否采用细粒度失效，待性能数据证明后再决定。
- **对象 ID 分配**：由 ObjectStore 统一处理打开文档和新建文档的 ID 分配，检查溢出、代次和冲突；不能将现有 `next_obj_num += 1` 直接作为新建/导入的安全分配策略。
- **流状态**：区分未修改的原始编码数据和已修改的解码内容；保存时统一生成 Length，并按输出策略更新 Filter/DecodeParms。禁止编辑器自行拼装不一致的流字典。
- **资源作用域**：ResourceManager 管注册与同文档复用，页面资源名称属于具体资源字典；跨文档复制必须重新映射对象 ID。内容编辑共享资源时，默认复制后修改，不全局改动其他页面。
- **预算生命周期**：Limits 是配置，不是聚合计费器。后续增加文档/单次操作级预算状态，明确缓存保留、临时解码、克隆、序列化输出分别何时计费和释放；失败及回滚恢复计费状态。原生后端内存仍需独立观测。
- **保存失败语义**：文件路径保存使用同目录临时文件及替换，明确平台差异；`save_to_writer` 不能承诺失败后回滚调用方 Writer，文档中必须说明可能已写出部分字节。增量保存与签名不复用未经验证的全量保存假设。

对应决策入口见 TODO 的 A1–A4；优先完成文档状态解耦，随后资源与保存，最后内容编辑模型。不要求一次重写现有核心，也不提前承诺线程安全。

## 校准颜色显示策略（2026-10-07）

Type4 函数现在编译为扁平只读指令，过程仅引用指令区间，不复制过程体。解析与执行使用独立显式帧；执行不依赖原生递归、不调用外部 PostScript 引擎。每次 eval 拥有独立操作数/执行栈，类型检查与有限运算错误返回 FunctionError，步骤/深度/存储耗尽返回 ResourceLimit；copy/roll 消耗额外工作量。整数计算超出 i32 时提升 f64，bitshift 采用 32 位逻辑语义；输入 Domain 与输出 Range 裁剪在公共函数入口统一执行。各缓冲有限额但未接入共享 OperationBudget，不能声称聚合峰值验收；Pattern/Shading 不因 Type4 可求值而完成。

补充：普通 Separation/DeviceN 也接入 packed 浮点转换，Decode 端点改为按分量数分配的 Vec，预留前校验端点字节限额，容量纳入 retained_sample_bytes。六分量图像已有逐行采样/末分量反转/严格保存回归；混合 None 仍传完整 tint 数组，全 None 由 PaintingDevice 抑制。不实现原生色版与叠印；本节下方早期四分量端点和专色尚未接入的描述由本段更新。

普通 CalGray/CalRGB/Lab/ICCBased 图像保留解码流的 packed 采样和 `(位深, Decode端点)`，不提前归一化到设备字节。RGBA 转换逐行处理填充位与 16 位大端样本，f64 插值后将浮点空间分量交给既有颜色转换；Lab 默认端点来自 L/a/b 范围，ICC 来自 Range。分量工作数组仅分配一次并复用，输出沿用可失败预留和 RGBA 限额，保留载荷仍由 display payload 字节计数统计；这不是 OperationBudget 全链路验收。

`PdfImage::data()` 的表示随采样路径而异：设备空间返回显示用 8 位分量，Indexed 返回解码后的索引，校准/ICC 空间返回保留精度的 packed 载荷。消费者应通过 `rgba_buffer()` 获取统一显示格式，不能把全部 data() 当作 RGB 字节。提取原始编码、图像字典与位深仍使用文档图像提取服务。ICC 仍按 Alternate 近似，独立 profile/OutputIntent 未实现；普通 Separation/DeviceN 尚未接入此路径。

Indexed 不再额外拒绝合法 DeviceN 基空间，调色板所有分量都先按 0..1 转为 tint，再经现有 transform 求显示近似；混合 None 分量可携带替代颜色数据，不能在求值前删除。Indexed::is_nonpainting 转发基空间判定，ColorSpace::is_nonpainting 纳入 Indexed，因此已共用的 PaintingDevice 同时覆盖路径/文字/图像，不在采集层丢对象。不新增原生色版、叠印或 Type4 求值能力。

Indexed 图像的 PdfImage.data 保存 Decode 后的索引字节，而不是归一化灰度：默认端点为 [0, 2^bits-1]；显式端点按索引单位计算后取整，超出 8 位索引范围裁剪，最终 Indexed::rgb 再裁剪到 hival。与设备颜色共用逐行采样/长度/可失败分配检查，RGBA 转换走调色板，不把索引当作亮度。DeviceRGB 调色板已有回归；Lab/ICC 基空间映射精度、全色彩管理与操作级聚合预算仍待完成。

Indexed::rgb 的调色板字节映射按 PDF 基空间分量范围执行，不采用统一 0..1：Lab 暴露仅 crate 内可见的固定六端点，ICCBased 复用既有 range 查询，其余已支持基空间使用 0..1。分量缓冲改为可失败预留；范围长度检查后，以 f64 中间值插值回 f32，再交给既有基空间转换。ICC 仍仅通过 Alternate 近似，未新增 profile 求值或 OutputIntent 管理；非零 Lab BlackPoint 仍不支持。

None 绘制控制与颜色转换分离：ColorSpace::is_nonpainting 识别 Separation /None 和全 None DeviceN；统一 PaintingDevice 适配层用于 Interpreter::run 与 DisplayList::replay，分别抑制填充/描边、保留组合绘制的可见侧，并调整文字有效绘制模式而保留裁剪位。普通图像判断自身颜色空间，stencil 判断当前填充色；一位 ImageMask XObject 解析后以灰度作为内部样本载体（不是 PDF ColorSpace），Skia 将 Decode 后的样本转换为当前非描边颜色与覆盖 alpha。普通 rgba_buffer 不允许缺少颜色的 stencil 转换，Pattern 着色仍不支持。run_to_display_list 使用未过滤采集路径，保留原始模式、对象及来源，避免视觉不可见内容从编辑/提取结果中消失。低层直接 RGB 查询对 None 仍报不支持；适配层不改变 Device 公共回调签名，也不使 RenderDevice 尚未支持的文字裁剪成为已实现能力。

颜色空间资源现在纳入ResourceKind::ColorSpace，注册使用既有页资源事务、继承读取、同对象绑定复用及类别表复制后修改，CS名称在页作用域内避让。导入沿用对象图Importer，颜色空间根可为名称/数组，不再强制所有资源根均为字典/流；Font/Image/Form原约束仍保留。跨文档必须先导入，再注册目标句柄；直接修改共享颜色对象仍影响所有引用页，不等于单页隔离编辑。解析校验与渲染能力保持分离，操作级聚合预算仍未贯通此路径。

Lab::rgb目前接入零BlackPoint的固定sRGB转换：定义域裁剪后以字典白点计算XYZ，采用Bradford适配到D65，应用sRGB传递函数并按通道裁剪。中间计算用f64固定栈数组，不另建堆工作表；非有限/错误组件与不可适配白点返回ColorError，非零BlackPoint补偿仍明确UnsupportedFeature。此为低层显示默认策略，不是完整ICC或印刷颜色管理。

后续应抽取共享颜色转换策略，并由解释/渲染入口明确传入目标色域、OutputIntent/渲染意图及黑点补偿选择；CalRGB/CalGray尚保留既有转换，不因本次Lab实现视作统一完成。不要把简单通道裁剪宣称为感知色域映射，也不要在未实现时忽略非零BlackPoint。P4-03仍按完整要求继续验收。
## Shading 显示事件检查点（2026-10-07）

Type2/3 Shading 已具备参数、函数和点采样模型，并进入资源注册、内容解释与显示列表回放。`PageObject::Shading` 从无载荷占位改为携带 `ShadingObject`；后者通过 Arc 共享模型，保留矩阵、图形状态及来源。`Device::do_shading` 默认明确返回不支持；Skia 已实现逐像素反变换后调用原函数的绘制路径，轴向非线性/径向像素、保存读回、裁剪/BBox/透明度和预算失败恢复专项已通过，全量回归另见 TODO。Trace 按每次绘制保守计入函数保留容量及资源名，渲染按表面与两份栅格共存检查字节上限；这不是包含颜色空间、原生分配和临时峰值的完整共享预算。Type1/4–7、Pattern 与独立阅读器验证仍待实现。
