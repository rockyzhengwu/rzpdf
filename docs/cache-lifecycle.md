# 文档缓存与修订契约

检查日期：2026-10-04。范围为当前 pdf 核心代码，不代表原生后端或未来缓存实现已验收。

| 状态 | 当前持有方及生命周期 | 编辑规则 |
|---|---|---|
| 原始间接对象 OnceCell | PDFContext；读取源存活期间保留 | 普通解析先查询 Store，不能把原始对象缓存当作最新值；显式原始入口另行命名 |
| 对象流展开缓存 | PDFContext；按源 xref 的对象流归属填充 OnceCell | 校验完成后写入源缓存；展开解码期间的引用解析使用原始源视图，退出后恢复普通 Store 优先视图 |
| 页面尺寸与变换 | PdfPage；每次 display_list 重新计算 | 同一页面对象跨编辑、错误及 unwind 回滚必须重新读取继承属性 |
| 字体、图像及解释状态 | 每次 Interpreter 与资源构造产生 | 不跨解释调用复用；旧 DisplayList 保持其快照，不随文档自动变化 |
| DisplayList | 调用方拥有的绘制结果 | 当前无文档级复用缓存；缓存方需同时记录 DocumentStamp、页面地址与解释选项 |
| 字形名、标准字体名、CCITT 查询表 | 全局静态常量映射 | 不依赖文档修订，无需编辑失效 |

`revision()` 是可见状态失效标记。成功低层写入及事务回滚推进，事务中暂时结果和恢复结果不共享标记。`DocumentStamp` 同时携带身份，避免跨文档同号修订误命中。

`commit_revision()` 是已提交写入标记，成功的最外层 dirty 事务计一次；错误、unwind 和只读不计入提交。不能用它判断事务内缓存是否有效。

当前回归证据：`pdf/tests/page_revision.rs` 验证同一个页面对象跨内容修改/错误回滚、低层尺寸修改/unwind 恢复；已打开文档先解释 Helvetica 以加载源对象，再低层改为 Courier、事务内临时恢复 Helvetica、错误回滚后再次显示 Courier，并严格保存读回。原来的 DisplayList 仍保留 Helvetica 快照。

首次懒加载隔离回归已复现旧问题：Flate 对象流的间接 DecodeParms 从 Predictor=1 改成 99 后，源展开错误地使用修改参数并失败。修复为限深、RAII 恢复的源解析作用域；源缓存解码忽略 DecodeParms 的修改/删除，而退出后的普通解析仍返回修改值/删除错误。错误与 unwind 退出作用域的恢复另有测试。

数组与连续引用补验：Filter 可为间接名字或数组中间接名字，DecodeParms 支持数组内间接字典/null、连续引用及常用参数的间接标量。Flate 源回归覆盖间接 Predictor、参数连续引用、修改/删除后源视图与普通视图不同；普通 ASCIIHex 回归覆盖数组 null 参数及最新 Filter 名称。引用循环受 max_depth 限制，Filter=null 视为无过滤器。

该契约不等于所有解码器兼容性：JBIG2 当前仍返回不支持，其算法验收属于独立功能任务。后续缓存若新增，必须注册其身份、修订、选项和对象生命周期规则，不能默认本次审计覆盖新实现。操作级聚合预算另属 AR-03，修订标记并不限制内存。
