# Browser rendering resource policy

Implementation and scoped Chromium acceptance: 2026-10-25. The pinned Wasm build
and real synchronous/Worker resource gate passed; evidence and limits are in
[the work plan](resource-plan.md). This is not a full browser release,
multi-browser certification or a process-memory sandbox.

## Discover limits before opening

Both synchronous `PdfEngine` and `WorkerPdfEngine` expose `capabilities()` before
any document exists. `doc.capabilities()` reports that document's immutable
effective policy. Open options accept `resourceProfile: "default" | "conservative"`;
arbitrary limits, unsupported profiles and runtime increases are not accepted.

```ts
const engine = await createWorkerEngine();
const build = await engine.capabilities();
const doc = await engine.open(bytes, {resourceProfile: "conservative"});
const effective = await doc.capabilities();
// Use effective.maxRegionDpi, maxRegionSide and maxRasterSide to plan tiles.
// Close doc and dispose engine in the application's normal finally/lifecycle path.
```

| Field | Default | Conservative | Meaning |
|---|---:|---:|---|
| maxDpi / maxFullPageDpi | 288 | 288 | Full-page output, still pixel/byte bounded |
| maxRegionDpi | 1152 | 1152 | Tiled output, not a whole-page canvas promise |
| maxRegionSide | 1024 | 1024 | Each requested tile side |
| maxRasterSide | 32768 | 32768 | Logical page raster side for region requests |
| maxRenderPixels | 4000000 | 2000000 | Raster surface pixel ceiling |
| maxRenderBytes | 16000000 | 8000000 | Raster surface bytes, not MiB |
| maxImagePixels | 4000000 | 2000000 | Decoded image pixels |
| maxDecodedBytes | 16777216 | 8388608 | Decoded bytes / image RGBA ceiling |
| maxOperationBytes | 67108864 | 33554432 | Logical operation accounting |
| maxCachedStreamBytes | 16777216 | 8388608 | Owned encoded source-stream residency |
| maxBufferBytes | 67108864 | 67108864 | Shared tracked input/output/font storage |
| maxWasmMemoryBytes | 268435456 | 268435456 | Browser build ceiling, not free memory |

Capabilities also expose maxHandles, maxPreparedPages, the per-document prepared
page/font estimated-byte cache limits, maxJsonBytes and the image decode policy.
`maxInputBytes: null` means no separate file-size ceiling, **not** unlimited input:
the source copy, handles and shared buffer budget still constrain opening.
Per-document budgets, native decoder/Skia allocations and JS-owned tiles do not
form a single aggregate RSS bound. Opening several documents multiplies some
cache costs. Query/cache-release and application scheduling remain necessary.

## High zoom without a giant canvas

`renderRegion()` accepts 1–1152 DPI at native ABI, SDK and Worker validation;
`render()` stays at 1–288. `rasterSize()` calculates logical geometry up to the
region ceiling without allocating pixels. The reader uses the advertised region
ceiling for `72 * CSS scale * devicePixelRatio`. A tile must still fit the page,
tile-side, output, logical-side and finite-coordinate checks.

High-DPI tiles are rendered directly, not generated by cropping a full-page
bitmap. Tile origins do not enter the PreparedPage key; requested image DPI does.
Existing NoZoom/NoRotate annotation view options and revision identity remain
part of the key. Render-specific snapshots should be replayed at their requested
resolution; the ordinary `prepare_page()` remains full fidelity.

## Target-resolution JPEG: bounded first slice

The enabled policy is `target-if-full-decode-exceeds-limits`. Images already
fitting the full-decode limits keep their original path and pixel output: native
reduced IDCT and full decode followed by raster filtering need not be identical.

For an otherwise oversized, single-stage **sequential SOF0 JPEG**, without masks
or non-null DecodeParms, rendering derives a target from both image-to-page
transform axes and DPI. JPEG IDCT uses 1/8, 1/4 or 1/2 output when sufficient;
otherwise full resolution must still fit. A separate 16000000 source-pixel guard
is retained, actual JPEG/dictionary dimensions must agree, and decoded pixel and
RGBA budgets are checked before allocating output. Rotations/shears and repeated
uses at different scales do not share an undersized image by resource name.

This is decoder-native reduction, not full RGB/RGBA followed by resize. Codec
scratch and encoded/source object copies are separate; no measured peak-memory
or universal 256 MiB success promise is made. The native JPEG C allocations are
not all charged to OperationBudget. Original streams stay in the document for
saving. Full-resolution image extraction and editing do not consume approximate
render snapshots and can still reject the original large image.

Web text-geometry queries and font preflight skip image pixel decoding;
requesting text/font metadata does not force full-resolution image storage.
Copy permission, text coordinates, layer visibility and font-redaction policies
remain unchanged. General content inspection/source editing retains its existing
full-resolution interpretation envelope.

Not enabled for reduction:

- Progressive JPEG: coefficient storage can depend on full source size, even
  with reduced output. Existing bounded full decoding remains in force.
- Unsupported mask combinations, Type3 and tiling-pattern images: keep full interpretation and
  mask/colour processing, or fail at its limits. No alpha/matte is discarded.
- Wrapped/multistage filters or non-null JPEG DecodeParms: unchanged full path.
- JPX: hayro-jpeg2000 0.4.1 exposes `DecodeSettings.target_resolution` and skips
  wavelet levels, but our `scratch_envelope` also accounts for full-source sample
  and code-block metadata. Its safe reduced scratch accounting has not been
  established. `jpxTargetResolution` is explicitly false; merely setting the
  hint would not establish lower peak memory. Simple Flate support is described
  below; remaining codecs retain bounded full decoding.

## Cache observation and release

Decoded ICC profiles share parsed data and compiled transforms within a document
revision. Cache clearing also releases cache-owned ICC references; held display
lists can retain them. `maxIccTransformEstimatedBytes` reports the additional
32 MiB transform-table estimate ceiling per Wasm module, shared across its open
documents and both fixed resource profiles. It is not part of the page/font
cache byte statistics or a measurement of live process memory. A preflight
failure uses reason `icc_transform_bytes`, stage `color_conversion`, and numeric
`limit`/`actual`, so the application can release cached pages and try a lighter
page without recreating the engine. See [transparency](../transparency.md).

`doc.cacheStatistics()` and `doc.clearRenderCaches()` work through both SDKs.
Replies include page/font hits, misses, entries, estimated owned bytes and Skia
font/resource cache usage/limits. On Wasm, clearing also purges unused module-level
Skia caches; it does not affect other engine instances. Native shared consumers
do not acquire that module-wide purge policy.

Clearing releases cache-owned references, not caller-held output arrays,
registered fonts or live snapshots. It does not edit the document/revision. JS
viewport tile caches must be managed separately. Released allocator storage may
be reused even while Wasm linear-memory capacity remains at its high-water mark;
the counters are not browser process-memory measurements.

## Stable resource error metadata

`PdfApiError` keeps `code`, message, operation and page, adding optional
`resource: {reason, stage, limit?, actual?}`. Worker transport preserves it.
Known image/raster preflights use typed `PdfError::ResourceLimitExceeded`, not
message matching. Initial reasons are image_pixels, image_source_pixels,
decoded_bytes, render_pixels, render_bytes, raster_side and retained_bytes;
stages distinguish image_decode and raster_output.

Legacy unclassified failures have `reason: "unclassified", stage: "unknown"` and
omit numeric sizes rather than inventing them. This is not a complete migration
of every parser/filter/native-allocation failure. A Wasm trap still invalidates
the session and is not a retryable resource result.

The ABI retains the existing human-readable error string. Additive exports
`rz_error_details_ptr/len` expose UTF-8 JSON; read both before the next ABI call
that changes state. The SDK copies the metadata before releasing any handles.

Reducing tile size helps raster-output limits, not necessarily image decoding.
Lower DPI can help supported JPEG and simple Flate preview paths. Unsupported image/mask paths may
still require a different source/profile or a clear limit message, not retries.

### Raster extents

Native rendering, WASM preflight and SDK `rasterSize()` cover the continuous
page extent with `ceil(f64(f32(size)) * f64(f32(dpi)) / 72)` pixels per axis.
This includes the final partial pixel of a fractional CropBox/UserUnit extent.
Avoid first rounding `dpi / 72` to f32: at 96 DPI that can turn a 600 pt page
into 801 pixels instead of 800. Region bounds use the same extents; side, pixel
and byte budgets still apply. Raster transforms retain their existing f32
precision. This changes fractional-page allocation dimensions from the older
nearest-integer policy; consumers should query `rasterSize()` rather than
reimplementing that policy.

### Optional target-resolution image decoding

Pass `{imageDecode: "target"}` to `render` or `renderRegion` to proactively
reduce eligible JPEG or simple Flate images even when a full decode fits. The
`budgeted` policy retains full pixels whenever they fit. This trades some image detail for lower decode and
conversion work and smaller retained images; it never raises resource limits.
Both policies keep the bounded full-resolution fallback for unsupported mask
combinations and codecs/processes. Flate RGB/Gray with an eligible 8-bit Gray
SMask uses joint bounded sampling, including Matte. See [the API contract](api.md#image-decode-quality-policy).
Cache statistics expose retained storage estimates, not process peak memory.

## Source stream residency

RZPDF-002 separates parser metadata from raw payload storage; see
[source-backed streams](../source-streams.md) for native API migration and the
fixed seven-image regression fixture. Browser byte input is immutable and range
views share its existing allocation. Resolving image dictionaries or searching
text does not copy all raw image bytes into a second permanent cache.

`cacheStatistics()` adds `sourceInputBytes`, `rawStreamResidentBytes`,
`rawStreamPinnedBytes`, `rawStreamPeakResidentBytes`, `rawStreamTransientBytes`,
`rawStreamPeakTransientBytes`, `rawStreamLimitBytes`, `rawStreamEntries`,
`rawStreamHits`, `rawStreamMisses`, and `rawStreamEvictions`. These report storage
owned by the engine's source-stream subsystem, not decoded images, raster output,
Skia allocations, all operation allocations, or process RSS. Immutable input
views occupy source input storage once and contribute zero owned raw cache bytes.
Temporary generic reads larger than the cache and plaintext AES buffers are
operation-budgeted and counted as transient bytes until their owners are dropped.

`doc.clearSourceStreamCache()` is available through both synchronous SDK and
Worker and returns the same statistics. It releases rereadable owned source
buffers. It leaves edits, active read owners, prepared rendering caches and the
immutable input intact. Use `clearRenderCaches()` separately for derived rendering
storage. Neither API promises to shrink WebAssembly linear memory.

Raw residency failures have reason `raw_stream_residency`, stage `source_read`,
and byte `limit`/`actual`. Unfiltered decoded stream failures use
`decoded_stream_bytes` at `stream_decode`. Reducing DPI does not change the size
of an encoded raw payload; callers should use the reported reason instead of
repeatedly retrying unrelated rendering settings.

## Bounded Flate image previews (RZPDF-003)

`imageDecode: "target"` supports a single Flate filter with 8-bit DeviceRGB or
DeviceGray samples, no masks or device-default color overrides, and Predictor 1
or row-matched TIFF 2 / PNG 10–15. The default `budgeted` policy retains full
pixels when they fit and can use this path when the full image exceeds limits.
An integer area sampler reconstructs rows and generates only target-size samples.
Decode mapping is applied before averaging; the complete zlib checksum and exact
source sample length are checked before publication. The source PDF is unchanged.

Capabilities add `flateTargetResolution`, `progressiveJpegTargetResolution`,
`maxTargetSourcePixels`, `flateComponents`, `flateBitsPerComponent`,
`flatePredictors`, `flateSourceBytesBoundedBy`, `flateSampling` and `flateStorage`
inside `imageDecode`. Source work remains bounded to 16,000,000 pixels, and total
inflated bytes including PNG row tags must fit the active `maxDecodedBytes`.
Output pixels/RGBA and simultaneous row/target allocations have separate guards.
Unsupported combinations retain their normal bounded full-fidelity path.

Render-time errors preserve code/reason/stage/limit/actual and add
`resource.image`: encoding, width, height, targetWidth, targetHeight,
targetDecodeSupported, unsupportedReason and jpegProcess. Mask diagnostics also
include maskKind, maskWidth, maskHeight, maskEncoding, maskBitsPerComponent and
mattePresent; they require dictionary inspection only. `image_source_bytes`
at `image_decode` means lowering output DPI cannot reduce the required source
inflation. `image_operation_bytes` describes simultaneous decoder storage.
Malformed zlib data keeps the `format` category, with image context; progressive
JPEG remains outside target decoding and reports `jpegProcess: "progressive"`.
The actual request target must still fit its budgets even when
`targetDecodeSupported` is true. See [scope and acceptance](../image-preview.md).

The first high-source-pixel Flate slice covers Image XObjects. Inline-image
parsing retains its existing source-pixel limits; this does not authorize larger
inline payloads. The render-only route can also sample eligible inline images
that already pass those parser limits.


## Bounded soft-mask previews (RZPDF-004)

Single-stage 8-bit RGB/Gray Flate images with a single-stage 8-bit Gray Flate
SMask support joint target-size color/alpha sampling. Different dimensions,
Decode reversal and Matte are handled before area reduction. Targets preserve
finer-mask detail; full-source sample buffers are not allocated. Default limits
are unchanged. Both checksums are required before cache publication.

Capabilities specify maskedReductionKinds=["soft"], softMaskEncoding=["flate"],
softMaskBitsPerComponent=[8], softMaskColorSpace=["DeviceGray"], softMaskMatte=true,
softMaskInterpolate=false and maxMaskedSamplingWork=256000000. Unsupported
combinations retain full-fidelity bounded behavior. image_sampling_work is an
independent joint-grid CPU guard. See [scope, diagnostics and
acceptance](../masked-image-preview.md).
