# WebAssembly PDF 实施计划

2026-10-22，依据 [spec](spec.md) 启动。用户已授权本专题的 spec 驱动开发；沿用现有原生版本，不自动开工 v0.15/v1.0，不提交、推送或发布。当前 WA-00～03 已完成，接口/Worker、交互和首批编辑在 Chromium 通过；完整字体服务、显示分块、稳定 SDK 及多浏览器验收仍待完成。

## 执行规则

1. 先关联需求 ID、验收用例及工作项，再实现；必要范围变更先更新 spec。
2. 一阶段的退出条件全部满足后才关闭该阶段。工具链缺失、编译失败、链接成功、浏览器通过必须分开记录。
3. P0 中优先完成一条真实端到端路径。其余字体与复杂渲染用例在各自阶段补齐，不同时重写核心与新增第二后端。
4. 保留原生默认构建和公开契约；原生功能变更按影响补回归，既有测试数量不替代浏览器证据。
5. 证据写入 ignored `output/`，验收文档只登记摘要、生成命令和状态。检查和构建脚本不自动安装；用户要求继续配置后，SDK 可放入 ignored `output/`，不修改系统默认工具链或 shell 配置。

### P0 决策门禁

先验证 Emscripten+Skia+FreeType。`scripts/check_webassembly.py` 仅覆盖环境和可选的 core 编译检查，不代表最终链接或浏览器验收。发现不兼容时，先记录具体依赖/版本/错误，再在 WA-02 调整工具链或最小依赖配置；不能关闭字体、JBIG2、透明度却宣称原有渲染已经成功移植。

P0 必须同时记录基础渲染输入与复杂格式探针的结果。只有 core 编译不足以关闭 P0；因字体、C 库、Skia 链接或浏览器运行受阻时保持待完成。Canvas/纯 Rust 替代方案可形成 ADR，但不自动变成并行必选实现。

### P1 接口冻结

在导出前确定 ABI 错误/句柄/长度及 RGBA 生命周期，TS 页号 0-based、坐标系、白底/alpha 契约一致。Emscripten 导出与 wasm-bindgen 作为不同实现路线；本期只实现前者。首个 JS 包应包含最小使用和完整释放示例。

### P2 字体交付顺序

1. 嵌入/子集字体与 Base14 在 Wasm 中工作；集合索引与原生 FFI 已验证。
2. 显式注册一个字体，扩展为有界多字体选择；保留 PDF 度量。
3. 按需加载 CJK 和其他文字系统字体，统一预检/渲染选择。
4. 覆盖同名不同字节、无 Unicode、自定义编码、Type3、竖排及关闭/取消后的缓存身份。
5. 先测完整资源包，之后再依据测量评估压缩、外置与分片；不得在未知 CID/GID 语义上做 Unicode 分片。

### P4 编辑范围冻结

优先来源驱动的已有代码/可表达 Unicode 文字修改、图片操作、明确的页面操作、全量保存。每个公开入口关联原生支持矩阵。复杂文字新排版、签署及更多增量组合另列任务，不因现有核心 API 存在就默认全部开放到 JS。

## 初始风险和下一步

- 初次盘点缺 emcc/em++ 和预编译 Rust Emscripten target；随后按继续实施指令在 `output/` 准备 SDK，使用已有 nightly 的 rust-src 重编目标标准库。WA-02 使用专用构建驱动，不依赖预编译 target 安装。
- `wasm32-unknown-unknown` 已安装，但旧预检首先失败于 ring 带入的 getrandom 0.2；可重跑诊断，不能据此推断其他原生依赖已经通过。
- 本轮备选路线已实际重跑：getrandom 0.2 默认配置编译失败，mozjpeg-sys 同时报告 C 标准库头文件缺失；见 `output/webassembly/p0-alternative.json` 及其构建日志。未通过该路线，不据此扩大功能声明。
- 现有 Skia 使用默认 FontMgr；Wasm 必须验证无 Fontconfig 的内存 face 创建和字体服务能力，不能直接沿用宿主库探测。
- `catch_unwind`、内存增长、跨 ABI 回调、多个 Rust/C 分配器及 Skia/FreeType 未计入 shared pool 的分配分别验证。
- CJK 字体分发体积、许可和离线可用性是 P2 的正式验收内容，不以开发机 Noto 字体路径代替 Web 资源方案。

下一步：WA-04 冻结稳定 C ABI/TS 契约、结构化错误、句柄/session 与完整生命周期负例；复用 WA-03 已验证的最小入口和像素复制路径。历史版本支持说明保持冻结；新平台状态只写在本专题验收记录中。
