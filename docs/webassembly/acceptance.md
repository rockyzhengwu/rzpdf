## 字体矩阵的必要切片

WA-T06～10 至少覆盖：嵌入/未嵌入/子集、Base14、简繁中文/日文/韩文、符号字体、可靠 Unicode/缺失 Unicode、自定义编码、CID 与 GID 非恒等、TTC 非零索引、同名字体不同字节、选定竖排和 Type3。按照当前核心支持边界选择合成正例，不以一种 TTF 页面替代全部字体类型。

每个输入记录来源/许可、源和字体哈希、期望选择、GID、Unicode、字宽/位置、渲染与失败语义。无法重分发的语料通过本地 JSONL 清单注入，不在本文列文件名，不上传到远端或进入 npm 包。

## 验证命令与结果格式

环境/依赖检查（不编译、不安装）：

```sh
python3 scripts/check_webassembly.py --output output/webassembly/p0-environment.json
```

目标 core 检查（前置工具缺失时明确 blocked，不偷偷换目标）：

```sh
python3 scripts/check_webassembly.py --build-check --output output/webassembly/p0-core-check.json
```

备选路线诊断（不构成主路线通过）：

```sh
python3 scripts/check_webassembly.py --target wasm32-unknown-unknown --build-check --output output/webassembly/p0-alternative.json
```

检查脚本的退出码：0＝请求的预检/编译检查通过；1＝已执行检查失败或超时；2＝缺少前置工具/target、配置或证据写入失败。所有输出均有 `p0_complete: false`；真实链接、页面和浏览器门禁需要后续驱动另行产生证据。`prerequisites_ready` 仅表示预检条件就绪，不证明可交付。

语料/渲染驱动在 WA-03/11 实现；P0 之前不能拿现有原生 `sample_pdf_corpus.py` 的结果充当浏览器结果。源文件读取路径只存在于私有清单及 ignored 报告。

### WA-03 后续兼容修复：R4 与传统内容

增加 Standard V=4/R=4、AESV2 的只读打开：使用文件 ID、对象号和代号派生对象密钥，并分别认证用户/所有者密码。R6 行为保持既有回归；R4 保存明确拒绝，避免误用 R6 写出路径。当前传统密码仅支持 ASCII；浏览器尚无密码输入界面，支持空用户密码文档。

解释器保留 BG/BG2、UCR/UCR2 函数和 q/Q 状态。这些函数用于 RGB 转 CMYK 印刷，在当前 RGB 光栅输出中不执行。MP/DP 验证参数及属性，但不打开标记内容作用域。额外提供显式本地替代字体注册：单个字体程序最多 32 MiB，输入/输出/字体保留池共 64 MiB；PDF 输入仍限制 8 MiB，不自动扫描系统字体。

核心测试 821 项通过、1 项忽略；渲染 64 项、Wasm ABI 3 项、构建检查器 8 项通过。两份私有文档共 286 页原生解析和渲染通过，其中一份需显式完整 CJK 替代字体。逐页浏览器验证结果以本轮实际报告为准，不将原生结果单独当作浏览器通过证据。

完整诊断覆盖 306 页（20 页自有回归、286 页私有文档），无解析或渲染异常。自有回归和第二份私有文档逐通道零差异；第一份的两页各有一个通道相差 1/255，其余零差异。这属于此次原生/Wasm 栅格输出的微小差异，尚未追溯到底层算术操作；私有清单仅对此样本设每页最多 1 个通道、最大差值 1 的显式上限，其他样本继续零差异。该结果证明移植一致性，不能替代独立阅读器的内容正确性对照。
