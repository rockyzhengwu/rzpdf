## API

阶段 A 新增 `document::associated_files`，方法同时适用于 `PdfDocument<R>` 与通过既有 Deref 使用的 owned `Document`：

- `associated_file_owner(page: Option<u32>, budget)`：None 指 Catalog，Some 指当前页索引；返回私有字段的 owner target，包含当前 stamp 与页面身份。
- `associated_files(owner, budget)`：返回不可篡改的 `AssociatedFiles` 快照，按原 AF 数组顺序列出 `AssociatedFileRecord`；无 AF 或 null AF 返回空列表。
- `associated_file_data(snapshot, index, budget)`：只接受同文件／当前 stamp 的快照，显式提取所选 payload，返回保留同池额度的 `BudgetedBytes`。列表不会执行过滤器解码。
- `create_associated_file(definition, data: &[u8], budget)`：创建间接 Filespec 和 EmbeddedFile，返回 ObjectHandle；不绑定 owner 或注册名称树。
- `clone_associated_file(filespec, definition, budget)`：显式创建新的 Filespec 和解码后的新嵌入流，不修改旧图；调用者提供新名称／描述／关系／MIME。保留无关私有键，无法证明安全的已知扩展拒绝。不是编码流逐字节复制。
- `bind_associated_file(owner, filespec, budget) -> PdfResult<bool>`：验证当前 owner 及间接嵌入 Filespec，添加一个关联；已存在相同身份则返回 false，不改 revision／序列化结果。新关联只接受五关系子集，且拒绝 FS／RF／EP／CI／ID／V／DOS／Mac／Unix 扩展；有 Params 时须有 ModDate。该入口检查描述结构，不解码整个 payload 或认证任意私有 schema。
- `unbind_associated_file(owner, filespec, budget) -> PdfResult<bool>`：从一个 owner 移除指定间接身份；不存在返回 false，最后项移除 AF 键，不删除其他关系、对象或载荷。

`AssociatedFileDefinition` 使用 `new(name, mime_type, relationship)` 和可选描述；关系写入子集为 Source、Data、Alternative、Supplement、Unspecified。读取使用原始关系名 String，Schema／FormData／自定义名字不归类成 Unspecified。记录暴露 Filespec 的可选句柄（直接字典无稳定句柄）、Unicode 名称优先的展示名、描述、关系、MIME、嵌入标志和可选 Size／ModDate，字段通过只读 getter 访问。

所有 owner target／快照在任意文档 revision 改变后失效，必须重新获取。ObjectHandle 本身仍为文档内地址，并不携带 revision。绑定／解除采用局部数组 copy-on-write，保留原数组别名与 owner 私有键；不按展示名合并或删除。无操作仍需通过版本／来源／权限校验，不能借幂等调用绕过保护。

## 选定语法与限制

- 写入要求有效 PDF 2.0、unsigned source 和 content-edit permission；低版本明确升级／重开，不偷偷改 header。读取可诊断旧版本原样存在的 AF，不追认其符合性。
- owner 限 Catalog 与实际页面树中的 page；不允许任意字典作 owner。AF 支持直接／间接数组，Filespec 支持直接／间接字典；错误类型、循环、坏引用和重复的间接 Filespec 身份拒绝。
- Filespec 有 EF 时必须为 Type Filespec；无 EF 的外部 Filespec 可只读投影，不做文件系统／网络访问，提取与克隆拒绝。嵌入流须为间接引用和 Type EmbeddedFile。
- 展示名 UF 优先再 F；EF 选择 UF 优先再 F，但所选 EF 键必须有对应 Filespec 名称。AF 首版拒绝 F／UF 指向不同流以及 DOS／Mac／Unix 等多载荷变体，不猜测平台。旧附件和批注 API 不因此收窄。
- 读取嵌入 AF 要求 MIME Subtype；克隆旧普通附件可缺 MIME，由调用者明确提供。MIME 选定子集为一个非空 ASCII type/subtype，各段只接受字母、数字、`!$&^_.+-`，总长不超过 255；无通配符、参数、空白、`#`、`;` 或 `=`。这是生成／编辑 profile，不宣称接受全部合法 MIME token 变体。
- 新建 F 使用可打印 ASCII 名称，否则为 `attachment.bin`；UF 使用 UTF-16BE 文本。新建 EF/F 与 EF/UF 指向同一嵌入流。不推断 MIME，不写文件或执行其内容。
- 新建流省略可选 Params；读取 Params 投影 Size 和 ModDate，不推断日期。克隆若原 Params 存在，要求 ModDate 文本存在，并验证可选 Size 与解码载荷长度相等；不编造文件系统日期或更改来源字段。
- 名称不允许空／NUL／控制字符；写入名称与描述的 UTF-8 长度及生成的 UTF-16BE 编码长度（含 BOM）、读取单个编码文本字段各最多 64 KiB，与 max_token_bytes 相交。读取文本遵守已有 PDF 文本解码规则，不新增 Unicode 容错。
- 单个 owner 最多 1024 项，与 max_objects 相交；单次 reference 追踪最多 min(32, max_depth)；新建／克隆解码 payload 最多 min(64 MiB, max_raw_stream_bytes, max_decoded_bytes)。提取沿用已有流解码器的 max_decoded_bytes 及共享预算，创建的 64 MiB 上限不是提取器的解码前硬上限。

克隆在旧流解码后检查创建上限，解码阶段仍按现有 max_decoded_bytes 和共享预算约束，不能把 64 MiB 称作克隆的解码前硬上限。创建前检查输入载荷；生成对象发布前另以预算化克隆校验全部 token、直接嵌套深度及字典／数组大小，不只校验调用者的名称与 MIME。

## 预算与原子性

返回列表持有同池 MemoryLease，直到列表释放；返回 payload 持有 BudgetedBytes。预算对象克隆和源解析、列表 capacity、输出文本、payload 及事务使用同池。新建字典和克隆补丁另预留 64 KiB 加输入文本长度的 16 倍作为保守 scratch，不称为实际逐分配计量。原始输入、store 常驻增长、旧解析缓存和原生分配仍不构成全 RSS 上限。

写入在事务中发布，失败不留下 Filespec／流半成品。失败后旧快照可能失效，应重新取 target／snapshot；同池有效重试必须通过。列表不是对未知私有键和全部 owner 的语义认证。新建对象尚未绑定时可保留在对象表，解除／名称移除不等于物理删除。

示例和独立配方使用新目录与 create-new 文件，不覆盖已有文件；不承诺整个多文件输出目录原子性，后期 I/O 失败可能留下已生成文件。文档事务和正式 writer／宿主文件 API 的原有失败契约保持，不能将目录辅助程序冒称成另一个原子 writer。
