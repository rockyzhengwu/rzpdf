# v0.12 文件结构与兼容能力盘点

盘点日期：2026-10-18。实现基线为 `a5c7f9e`，即已提交的 v0.11；本轮只盘点和更新文档，不实现新格式或放宽写入保护。结论是：读取基础已存在，主要新增开发量集中在输出布局、文件级诊断和有限恢复，而非重写 PDF 解析器。

本轮建议分为 A 文件结构写出、B 保留与恢复、C 综合验证。候选边界见[实施计划](v0.12.md)，当前与目标能力对照见[支持矩阵](v0.12-support.md)。候选范围不表示已经实现或验收。

## 源码现状

| 能力 | 现有入口及证据 | 缺口与影响 |
|---|---|---|
| 全量保存 | `pdf/src/writer.rs` 的序列化循环、`write_xref_table`、`write_trailer_limited`；`document/save_options.rs` | 输出传统 xref 表，没有输出布局选项；不能选择新建 xref stream 或 ObjStm |
| 流压缩 | `SaveOptions.compression`、`prepare_document_output_object` | Preserve / FlateUnencoded 处理普通流编码，不会把多个间接对象打包成对象流 |
| xref 读取 | `parser/parser.rs` 的 `parse_xref_with_offset`、`load_xref_chain`、`parse_xref_stream` | 已读传统表、xref stream、混合引用及 Prev；有模式检查和限额，不是缺少整个读取器。新输出仍须验证 W/Index、各类记录、自引用条目和多轮互读 |
| 记录模型 | `document/cross_ref_table.rs` 的 ObjectInfo / ObjectState | Compressed 的 offset 保存容器号，gennum 保存成员索引；`object_id()` 已把逻辑 generation 正确归零，但字段仍承载不同含义，新增 writer 不宜继续传播这种隐式约定 |
| 对象流读取 | `objects/object_streams.rs`、`pdf_context.rs` 的压缩对象解析 | 已有 N/First、成员边界、顺序、类型和预算检查；没有对象筛选、分组、成员编码或新容器写出器 |
| 全量对象枚举 | `pdf_context.rs` 的 `serializable_object_ids`、`materialize_all_objects*`；writer 逐对象写出 | 不是只保存可达页面树，也不是自动 GC。旧结构流可能仍作为普通间接流写出；新布局必须制定容器处置规则，不能把保留旧容器误称为重建新对象流 |
| 增量保存 | `document/owned.rs`、`writer/incremental.rs`；`v05_incremental` | 严格不可变来源、源前缀、Prev、自由链、generation、失败重试已实现；追加仍写传统表。原压缩成员更新为独立对象，旧结构容器禁止直接改删 |
| R6 | `security/transform.rs`、`writer/protection.rs`、`writer/incremental/security.rs`；v05/v011 安全测试 | 解密对象流一次、XRef 免加密等既有基础可复用；新建 ObjStm 后的压缩／加密顺序和新 xref stream 输出尚未闭环，不能直接沿用逐成员加密循环 |
| 签名 | `signatures/`、私有 SignedRevisionPlan；v011 集成及独立门禁 | 已有历史验签、限定签署和受控修改。不能将新通用布局选项直接套到已签来源或已准备的 CMS 占位字节；本轮建议保持这些入口原布局 |
| 兼容语法 | `parser/syntax.rs` 的 `read_pdf_stream_inner`、`consume_stream_start` 等；`ParseOptions.mode` | 默认 Compatible，包含局部容错，如 Length 不匹配后寻找 endstream；没有统一文件级容错事件报告。内容流 diagnostics 已存在，但不是文件结构恢复报告 |
| xref 恢复 | `find_start_xref` 从末尾至多 1 MiB 查找 startxref，然后解析指定位置 | 未见独立的全文件对象索引重建入口；坏偏移、缺失 xref 不是自动恢复能力。Compatible 不能等同于 repair |
| 元数据与附件 | `document/metadata.rs`、`attachments.rs`、`trees.rs` | 已有 Info、原始 XMP packet 和 EmbeddedFiles；XMP 不负责 XML 语义验证。通用 AF/AFRelationship 语义与未知扩展的读／保留／编辑尚无统一覆盖矩阵，不能把附件 API 当成全部关联文件支持 |
| 性能与限额 | OperationBudget；`examples/v05_save_benchmark.rs` | 已有 1/10/100 MiB、单 metadata 更新基准；不足以说明大量小对象、稀疏编号、对象流分组、新布局或恢复扫描的性能。tracked bytes 不代表 RSS |

全量保存和增量保存都已有版本、权限、源签名、预算和失败保护。新开发应复用这些保护，而不是创建一个能绕过它们的“优化保存”入口。

## 优先处理的架构问题

### 写出布局与对象语义分离

当前全量 writer 将对象遍历、准备、保护转换、偏移计算和传统表输出放在同一路径。继续按格式复制整段循环，会使新旧格式的保护、版本和预算检查分叉。

建议增加内部布局计划与两个小型编码组件，候选位置为 `writer/layout.rs`、`writer/xref.rs`、`writer/object_stream.rs`。布局计划负责对象分类、临时容器号、输出顺序和预留，不改文档 overlay、对象句柄或 revision。全量与增量复用 xref 编码；增量仍保留独立的源前缀、Prev 和保护身份校验。

对象语义 ID 和来源对象图保持稳定；XRef/ObjStm 的临时输出对象号由计划单独分配，不能调用会提交文档修改的公共新增对象入口。异常、预算不足和 writer 失败后，源文档和准备令牌仍应遵守既有契约。

### xref 记录显式区分三种含义

建议内部使用 Free(next, generation)、Uncompressed(offset, generation)、Compressed(container, index) 三种记录。现有公共 ObjectInfo 的迁移需在 V12-01 明确兼容方案；不能同时维护两份互不校验的真实记录，也不能把 compressed index 当成 generation 写出。

稀疏 Index 输出应按实际记录工作，但不自动取消现有 Size／对象号限制。超大偏移用编码单元测试验证，不要求构造十几 GB 的实际测试文件。

### 保护顺序与布局计划共同约束

对象流成员先按允许的语法编码，再组合、压缩、对容器应用保护；不能对成员和容器重复加密。XRef、Encrypt、metadata 公开例外以及 Crypt/Identity 沿用既有语义并分别验证。签名字典和占位对象保守留在独立对象中，受控签名入口不接收新布局选项。

旧 XRef 的偏移不能作为新有效索引使用；旧 ObjStm 不能同时被当成新成员的有效容器和无关原样流。存在 Extends 或未知活跃容器关系时，必须保留已证明的语义或拒绝该重布局，不静默删对象，也不宣称重布局能够安全擦除历史数据。

### 兼容诊断与索引重建分开

保留 Strict／Compatible 的现有默认和调用契约；增加有界文件结构报告，记录偏移、对象身份、修正类别和影响。新的显式恢复入口另记不可变来源状态，不能通过修改 mode、Root 或 overlay 伪装成严格来源。

本轮建议最小恢复只处理可明确重建的未加密、非压缩对象来源，并返回只读视图。不能确定 stream 边界、Root 或版本归属时拒绝。恢复写回、加密／签名恢复和任意多 revision 重建不作为首版恢复范围；这一取舍属于开工前待确认的候选边界。

## 标准与外部对照

文件结构按 ISO 32000 第 7.5 节、保护按第 7.6 节及适用版本检查；[PDF 2.0 第 7 章更正](https://pdf-issues.pdfa.org/32000-2-2020/clause07.html)用于核对对象流限制和引用规则，不代替完整标准。

[qpdf 的对象流／xref stream 实现说明](https://qpdf.readthedocs.io/en/11.9/object-streams.html)提供独立互操作对照，包含成员 generation、容器索引、混合输入和不可加密的 xref stream 等说明。它的默认分组数量或未生成 hybrid 的选择不是本库必须照搬的标准要求。独立测试应验证实际输出，而不是仅以 qpdf 能修复后打开作为通过。
