# v0.11 安全与互操作矩阵

2026-10-17 冻结实施边界，V11-00～13 已完成下列限定范围本地验收；包含层级字段、可见外观和受控签后修改，不表示全部标准可选操作均已实现。最终证据见[验收记录](v0.11-acceptance.md)。所有外部样本由脚本使用公开合成数据生成，不使用生产密码、证书或私钥，不访问证书网络服务。

## 加密保存

| 输入或操作 | 冻结边界 |
|---|---|
| Standard V=5/R=6、PDF 2.0 | 认证后允许未签名、严格不可变字节输入增量保存 |
| Standard V=5/R=6、PDF 1.7 | 保留既有 ADBE BaseVersion 1.7、ExtensionLevel 至少 8 检查；不在追加过程中静默补声明或升级版本 |
| Encrypt | 允许直接字典或原间接字典；必须与已认证身份/参数一致，间接对象不允许 Upsert/Delete；明文 trailer 的 Encrypt 不作为普通数据加密 |
| ID | 禁止调用者改变源 ID；追加保留第一项，生成新的第二项；无操作/回滚后无净变化时返回原始字节，不更新 ID |
| 字符串、普通流、附件 | 只在变更对象的输出边界加密一次；源 ObjStm 中被更新的成员输出为普通间接对象，其余源容器字节不改写 |
| Crypt/Identity、metadata | 复用现有处理；Identity 明确表示公开载荷，EncryptMetadata=false 的 metadata 保持明文；不承诺这两类例外的保密性 |
| 认证与权限 | user/owner 均可保存获准的修改；既有 modify、fill_forms、assemble、annotate 权限不放宽；签名来源检查不改变 |
| 多轮保存 | 至少三轮保存—严格重开—追加，保留每轮源前缀；不隐式 rebase。AES IV 和 revision ID 随机化，非空追加不承诺字节级确定性 |
| 更换密码/算法、移除保护 | 增量接口拒绝；走已有显式全量保护工作流及 owner 检查 |
| R2/R3/R4/R5、非 Standard、公钥加密 | 本版暂不新增兼容解密或弱算法输出。V11-02 的决策为保持明确拒绝；R4/AESV2 已加入独立拒绝样本。遗留读取另立独立安全矩阵，不作为 R6 的兜底路径 |
| 加密签名、已签名加密来源 | 继续拒绝，不由本版阶段 A 开放 |

遗留读取决策的理由是本版优先闭合已认证 R6 的保存契约及独立签名链，不同时引入基于对象号派生密钥等另一套历史变换路径。该决定只关闭 V11-02 的取舍任务，不声称遗留格式已经实现或不符合标准。

## 签名阶段的冻结目标

保持外部 detached DER CMS、单个 CMS SignerInfo、SHA-256、issuer/serial 证书标识、受限 signed attributes、证书集合及 CMS 长度。私钥不进入核心。沿用 `ring 0.17.14` 作为密码学验证后端及现有 `cms 0.2.3`/`der 0.7.10`，不自行实现密码学原语；不在阶段 A 添加依赖。

| 算法 | V11-04～06 已验收的实现边界 |
|---|---|
| RSA PKCS#1 v1.5 / SHA-256 | 沿用 2048～8192 位及既有完成校验约束，增加公开的历史验签结果；保持既有输入版本边界 |
| RSA-PSS / SHA-256 | 范围限定 PDF 2.0；PSS SHA-256、MGF1 SHA-256、salt length 32、DER 省略默认 trailer field 1；受限 PSS SPKI、其他摘要/salt 组合明确拒绝 |
| ECDSA P-256 / SHA-256 | 新增范围限定 PDF 2.0；命名曲线 P-256、DER 签名、算法参数必须符合相应 profile；其他曲线、显式曲线参数和固定宽度签名不默认接受 |

PSS/ECDSA 的 OID、ASN.1 默认参数、适用 PDF 扩展声明及证书 key 类型必须在 V11-06 的输入/输出门禁逐项核实；不允许只把 OID 加入白名单就判定支持。参数规则对照 [RFC 4055](https://www.rfc-editor.org/rfc/rfc4055) 和 [RFC 5758](https://www.rfc-editor.org/rfc/rfc5758)，PDF 版本/扩展按适用规范单独登记。上表是本库选择的目标子集，不是对完整标准算法集合的声明。

公开验证必须分别报告覆盖/结构、密码学和后续修改状态；信任、有效期、撤销、时间戳一律不由无网络核心背书。多签目标至少三签链；每签回溯其覆盖 revision，未知/损坏/混合历史先拒绝相关写入。

## 修改约束阶段的冻结目标

- 从默认拒绝逐项开放受控编辑；原有 `require_unsigned_source` 不全局移除，低层任意对象更新及签名来源全量重写继续拒绝。
- DocMDP 读取区分声明权限级别；P=1 不开放本版写入。P=2/3 仅对后续分类器证明符合约束的填表、签名及支持的批注操作开放，模板实例化等未实现操作仍拒绝。
- FieldMDP 按完整字段身份处理 All/Include/Exclude 与后代；在历史和当前关系图中检查，不能用改名、删除字段、共享 AP/字体或低层改 Perms 绕过。
- 任何允许修改都要检查实际对象/可达关系差异，再在提交前、序列化后和重开后复核；“旧签密码学有效”与“后续修改获准”分别给结果。owner 身份不覆盖签名约束。
- v0.9/v0.10 的结构/图层、命名空间及无法维护关系的拒绝规则保持；不因字段修改允许而放开页面迁移、正文/共享资源修改。

阶段 C 按以上规则实现为独立的不可变受控计划，而非通用编辑特权。支持既有 Tx/checkbox 填值及外观、既有空签名字段签署和新增 Square；其他规范允许但本版未实现的操作仍拒绝。`signature_constraints` 读取声明，`signature_modifications` 比较每轮实际对象变化并区分 Allowed/Forbidden/Unsupported，完成接口再次重开核验。公开接口和具体限制见[受控工作流](../signed-workflows.md)。

DocMDP 要求绑定唯一第一认证签名，P 为整数 1/2/3，省略时默认 2，V 为名称 `/1.2`。FieldMDP All/Include/Exclude 绑定签署时字段对象身份，并展开组后代；未知方法/版本、非法集合和冲突 Lock 不放行。Widget 的 Locked 标志不禁止填值，ReadOnly 按字段 Ff 判断；LockedContents 和未知位明确拒绝。规则依据 [ISO 32000-1 第 12 章](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf)及 [PDF 2.0 交互功能更正](https://pdf-issues.pdfa.org/32000-2-2020/clause12.html)。

## 样本和证据登记

独立入口为 `docs/check-v011-encrypted-incremental.py <new-directory>`，其生成命令、输入/输出 hash、生产者、认证角色、版本和轮次登记在输出 `manifest.json`。脚本与纯合成输入由本项目生成并随仓库许可；外部工具按各自许可证运行，不复制其实现或分发生成的私密资料。

| 生产者/样本 | 用途 |
|---|---|
| pikepdf 合成原始页/metadata/私有字符串 | 纯自建文档图，不依赖引擎生产自己的正例 |
| qpdf R6 classic、ObjStm、clear metadata、1.7 extension 8 | 两种输入布局、metadata 例外和有效版本；明确检查 Info 原为压缩对象后被独立更新 |
| MuPDF R6 / PDF 2.0、直接 Encrypt | 独立加密实现、不同 Encrypt 表达形式；认证/追加与 qpdf 交叉读取 |
| MuPDF R6 / PDF 1.7 缺扩展声明 | 保留版本拒绝负例，不静默升级或修改生产者输入 |
| qpdf R4/AESV2 | 遗留读取未纳入时的明确拒绝，无输出 |
| rzpdf PDF / OpenSSL CMS，三算法 | 新准备签名完成校验、公开读取和独立 pyHanko 密码学对照；不是证书信任或签后授权结论 |
| pyHanko，三算法、层级字段、三签链 | 独立签名生产者，每个历史版本分别验证；新增工作流另覆盖既有层级空字段签署与受控填值 |
| 真实签名字典被追加替换/释放 | 保留旧版密码学报告并明确 current=false、Replaced/Removed；不能从最新对象图抹去历史 |
| CMS/参数/版本负例 | 摘要、签名比特、证书标识、PSS 盐/MGF、EC 参数、弱 RSA、DER、非零填充及 PDF 版本明确区分失败/格式错误/不支持 |
| 旧 v0.5 独立 qpdf ObjStm 样本 | 单签及独立追加的纯 xref-stream/ObjStm 来源用新验签入口复验；输入 SHA-256 另记，不借用旧二进制结果 |

当前工具实测 qpdf 11.2.0、pikepdf 9.11.0；MuPDF 版本由每次独立门禁的 `mutool-version.log` 登记。历史签名入口为 `docs/check-v011-signatures.py`，复用已有 OpenSSL/pyHanko 0.37.0 环境，42 个密码学/历史案例和来源 hash 登记于输出 manifest；该门禁关闭 diff-policy，不验证修改授权。旧 v0.5 验证结果不能自动覆盖新增算法。

## 多签追加的限定边界

V11-07 的入口只接受严格不可变、未加密 PDF 2.0，无历史 MDP/Lock/SV/AA/XFA/线性化等声明，现有签名全部有效且最新签覆盖完整来源。仅支持间接 AcroForm 和扁平已签/文本/复选框 Widget；不写入既有空签名字段。私有审批计划绑定源 hash/stamp，限定两处旧对象的关系更新及三个新对象；一般编辑和保存接口保持拒绝。历史或当前声明被移除不构成解锁条件。

`docs/check-v011-multisign.py` 与历史读取门禁不同：开启独立 pyHanko diff-policy，逐 revision 核对旧 CMS、ByteRange、覆盖范围及精确对象变更。21 个案例包括两种布局/两类首签生产者的四签链，以及 DocMDP P=1/2/3、FieldMDP All/Include/Exclude、共享 AcroForm/Widget、错误页面归属拒绝。该旧入口仍不接收 MDP 输入，不因新工作流而扩大边界。

## 层级字段与受控修改门禁

`docs/check-v011-workflows.py` 独立生成 27 个案例，覆盖 classic/ObjStm、层级/多 Widget Unicode 外观、签名—填值—checkbox—再签链，P=1/2/3 和缺省 P，All/Include/Exclude 及组后代。页面 CropBox、共享字体、结构、图层、字段改名、移除 Perms 等未授权尾部必须拒绝；重签为有效 CMS 的非法参数仍不得获准。源输入和目标已存在均不可被破坏。

显式 P 的填值/签名开启 pyHanko 0.37 diff-policy。该工具未实现 P=3 批注策略，且要求显式 P；这两类分别使用独立精确对象投影/声明检查，加 pyHanko 或 OpenSSL 的 CMS 验证，不冒称工具提供了不存在的授权结论。MuPDF 当前构建无 OpenSSL 签名后端，仅参与渲染，不计作密码学验证器。

Unicode 和新增 Square 使用独立页面级绘图参考：两引擎、两页共八组精确像素对照，另比较独立生产者 Courier 签名文字的跨引擎范围并目视复核。参考 PDF 的全量重写仅供渲染，不拿来声称签名有效。运行环境、最终计数与指纹见验收记录。

不安装 Poppler、不运行 fuzz。阶段最终结果与源码指纹见 [v0.11 验收记录](v0.11-acceptance.md)，整体任务见 [实施计划](v0.11.md)。
