## Incremental saves

Use `Document::from_bytes_with_mode(bytes, ParseMode::Strict)` and explicit
`save_incremental_to_bytes`, `save_incremental_with_budget`,
`save_incremental_to_writer`, or `save_incremental_to_file`. Existing default
save methods remain full rewrites. Options: `IncrementalSaveOptions`.

| Input / operation | Current boundary |
|---|---|
| Immutable owned bytes, strict parse | Supported |
| File, arbitrary reader, legacy generic document, compatible mode, new document | Incremental request rejected; use full save or reopen owned bytes |
| Traditional xref, xref streams/object streams, hybrid | Tested; output appends traditional sparse xref |
| Existing incremental revisions | Three successive reopen/edit/save revisions checked independently |
| New / replaced / deleted ordinary objects | Supported, including nonzero generations |
| Modified compressed object | Appended as a standalone ordinary object |
| Deleted compressed object | Supported; old qpdf 11.2 warning, libqpdf 12.2 check passes without recovery |
| Directly editing XRef / ObjStm containers | Rejected; edit the contained logical objects instead |
| Live reference to a deleted object | Rejected, including live orphan objects; old xref trailer roots are historical |
| Object-number reuse | Not performed; allocation respects original Size |
| No changes / rolled-back edits | Exact original bytes returned |
| Trailer-only Info removal | Explicit null prevents inheritance from older revisions |
| Encrypted, signature-bearing, linearized source | Rejected, even if protected source objects were overwritten in the overlay |
| Header / Catalog version downgrade | Rejected |
| In-place source append / implicit rebase | Not provided; reopen output to append a further revision |

Source bytes and their length/xref/trailer baseline are immutable. Saving does
not clear edits or advance document revision/commit counters. On serialization
failure no external output is touched. A failing caller-owned Write can contain
partial bytes. File output reuses the full writer's atomic replacement helper.

Operation budgets charge snapshots, validation tables, encoded objects and final
output, including the original prefix. Persistent source bytes and source caches
are not included in temporary-operation accounting; this is not a process-RSS cap.

Incremental saving is **not redaction or secure deletion**. Removed text, metadata
and attachment payloads may remain recoverable in the original bytes.

The parser recognizes the compact xref-stream sentinel `(0, 0, 0)` as reserved
object zero with semantic generation 65535. Other invalid zero generations and
free-list cycles/missing/live targets remain rejected. This is a specific
interoperability rule, not general damaged-file recovery.

## Password protection

| Input / operation | Verified boundary |
|---|---|
| Standard V=5 / R=6, Length=256 | AESV3/Identity; direct crypt-filter dictionaries, DocOpen |
| R=2..5 / RC4 / public-key / indirect CF / EFOpen | Explicitly rejected |
| Input declaration | PDF 2.0 or PDF 1.7 Adobe extension level >=8 |
| New encrypted output | Full rewrite, declares PDF 2.0 |
| User / owner authentication | Distinct roles; wrong password never publishes partial plaintext |
| UTF-8 password | SASLprep; <=1024 input bytes, <=127 normalized bytes, no truncation |
| Empty password | Empty user supported; new owner must be nonempty |
| Ordinary strings / streams / object streams | Object-boundary transform once; compressed objects inherit outer decryption |
| Explicit Crypt / Identity / EFF | Unique first Crypt stage; xref/Encrypt/clear metadata exceptions |
| Default authenticated full save | Preserve protection independently of mutable Encrypt entries |
| Remove / replace existing protection | Explicit SaveSecurity and owner authentication required |
| Permissions | Advisory report, modify gate plus high-level annotate/assemble/fill policies; see guide |
| Encrypted incremental / encrypted signatures | Rejected |

## External approval signing

| Input / operation | Verified boundary |
|---|---|
| New document or strict immutable owned bytes | One invisible signature; >=1 page |
| Traditional xref / pure xref stream and object streams | Supported signing inputs |
| Hybrid references anywhere in source history | Signing rejected; explicitly full-rewrite and reopen first; A incremental support unchanged |
| File / arbitrary reader / compatible mode | Reopen strict owned bytes first |
| Owned source older than PDF 1.4 | Upgrade by full rewrite and reopen first |
| Existing flat text/checkbox forms | Up to 256 fields retained; duplicate signature name rejected |
| XFA / nested/scripted fields / NeedAppearances / existing signatures | Rejected |
| Prepare | Immutable final byte owner, exact ByteRange, SHA-256, identity/revision token |
| External backend contract | Detached CMS over the concatenated signed ranges, not raw RSA over PDF digest |
| Completion algorithms | Single SHA-256 signer, RSA PKCS#1 v1.5 2048..8192 bits, embedded issuer/serial certificate |
| RSA-PSS / ECDSA / SKI identifier / multiple signers | Rejected |
| Completion checks | CMS structure, messageDigest and RSA integrity, reservation, fresh token, single use |
| Certificate trust / expiry / revocation / timestamps / LTV / DocMDP | Not verified or claimed |
| Source signature report | Exact Contents binding and covered revision; always verification=NotPerformed |
| Signed-source low-level edit / full rewrite / repeat signing | Rejected even if attempting to remove signature objects first |
