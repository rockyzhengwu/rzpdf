# v0.7 工程验收

日期：2026-10-15。v0.7 的 A/B/C 冻结范围已完成本地工程验收，允许进入 v0.8 范围盘点。支持边界以 [字体矩阵](v0.7-font-matrix.md) 为准，不代表任意 PDF、字体或书写系统均受支持。

## 固定源码与环境

最终候选为 `8a901e0`，生产代码及样本提交为 `da67f1e`；两者的 Rust/Cargo/样本完全相同，`8a901e0` 只修正独立检查器对历史严格解析结果的假设。完整工作区门禁开始至结束没有修改 Rust/Cargo/样本，独立报告记录候选与干净工作区，之后仅更新文档。

环境：macOS 13.7.8 x86_64，Rust/Cargo 1.96.0；qpdf 11.2.0，MuPDF 命令行 1.27.0，PyMuPDF 1.26.7，pikepdf 9.11.0，FontTools 4.39.4。未验证其它平台或最低 Rust 版本。没有新增 Rust 依赖、修改包版本、推送、标签或发布；fuzz 继续暂缓，不使用 Poppler。

## 实现范围

- A：保留已验收的受限 Type3 图形字形、d0/d1、资源作用域、Unicode 提取、文字元数据/图形分离和来源隔离；在最终候选上重跑模型及 12 页执行门禁。
- B：CMap 的 code→CID、code→Unicode 表保留原始字节长度；反向编码不猜测另一码长。新增通用字体检查快照、竖排 W2 原点字段和实际轮廓原点辅助方法，修正竖排 em/轮廓几何。Type1、name-keyed CFF、OpenType/CFF、简单及 CID TrueType 的固定读绘组合有独立验证。
- C：新增 `GlyphRun`/`PositionedGlyph` 及 `overlay_page_glyph_run[_with_budget]`；显式 PDF 码和文字原点、可选 GID/Unicode 断言，复用已有字体而不改写映射。输入/原生 GID 范围预检、权限/签名保护、共享页及 Form 资源隔离、回滚、限额重试、全量/增量保存均有回归。

公共契约、示例、预算排除项和迁移说明见 [字形运行指南](../glyph-runs.md)。

## 兼容变化与保留限制

`Font::Type3`、Type3 元数据消费者要求沿用 A 阶段契约。B/C 增加 `ExtractedCharacter::vertical_origin`，下游结构体字面量构造需要增加该字段；竖排 em/outline 辅助几何现在正确应用 W2，`position` 本身仍是文字原点。按码长匹配 ToUnicode 和 `Cmap::cid_for_char` 可能让以往错误地取到数值别名的输入返回缺映射；旧无长度 `cid(u32)` 对有歧义的结果返回 0。

CID-keyed CFF charset 映射、CFF/Type1 子集、任意 Type3、变量/彩色字体、完整 shaping、系统字体回退及自动重排均不在本版正向范围。裸 GID 输入不自动变成 PDF 字符码。特别的多码长数值碰撞及同 CID 不同 Unicode 存在独立阅读器差异，不能用内部单元正确性扩张跨阅读器正向矩阵。

`UnitaryMethod.pdf`（本机 hash `8c3362bb393931232785a3733db9204213b0747aa9a26e18410c9fa898aa9d0f`）严格模式仍拒绝不合规 object 0 代次；兼容模式 296 个码仅 62 个有 Unicode，234 个缺映射未解决，日志 `tmp/pdfs/v07-unitary-limit.log` / `tmp/pdfs/v07-unitary-mapping-limit.log`。它仍是排除案例，不计作验收成功。预算仅覆盖指南列明的分配，不是进程 RSS/CPU 硬限；本版验收不自动关闭长期 P0～P5 父任务。
