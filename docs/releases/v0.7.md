# v0.7 字体与文字解释实施计划

日期：2026-10-15。状态：实现中，尚未验收。承接已验收 v0.6 源码 `0f647af` 和收口提交 `969f152`。目标是补齐 PDF 字体解释、字符映射和显式字形运行写入，不包含语言 shaping、字体自动选择、OCR 或段落重排。

## 开工盘点和阶段边界

标准依据为 ISO 32000-2:2020 第 9 章，结合 [PDF Association 第 9 章勘误](https://pdf-issues.pdfa.org/32000-2-2020/clause09.html)，并区分 PDF 1.7 及更早输入。实现按以下三阶段推进，三个阶段均为本版必选，不将单个字体模型交付当作整版完成。

| 阶段 | 现有实现 | 本版交付与退出条件 |
|---|---|---|
| A Type3 | `Font::try_new` 及预算构造均明确拒绝；已有内容解析、Form 执行、资源作用域和绘制设备 | 字体模型、字形程序、FontMatrix/宽度、d0/d1、资源及递归保护；提取与绘制分开处理，同一字符不重复绘制，保存导入与独立几何/像素验证 |
| B 字符映射与嵌入字体 | Simple/Type0、Encoding/Differences、ToUnicode/CMap、静态 TrueType/Type1/CFF 的部分 FreeType 路径及子集器已存在 | 冻结 code→CID→GID 与 code→Unicode 两条独立矩阵；多标量/代理对、竖排原点、缺失映射、真实字体读绘与错误负例；不从零重写已有能力 |
| C 字形运行与读写 | builder 支持已编码字符串，TrueType 嵌入及来源编辑已存在 | 显式字符码/GID/Unicode/位置契约、水平及冻结的竖排组合、输入预检、事务、保存重开和独立位置验证；不将任意 GID 当作 PDF 字符码 |

Type3 首个实现切片是独立的有界检查模型，供后续解释器接入。它不自动开放页面 Type3 绘制；在绘制门禁通过前保留现有 UnsupportedFeature。d0/d1 度量和 Widths 分别暴露，不能把字形流中的度量当作 PDF 字体宽度表的替代。

## 实施约束和最终验收

不把 Type3 的绘制程序扁平化成普通字体文件；字体数据、字符编码、绘制执行和 Unicode 映射分开。资源循环与字形递归必须在执行前或执行额度内确定失败。字形内部事件的来源不得冒充页面根操作；未支持的嵌套编辑拒绝，不污染其他调用。

本版不要求变量/彩色字体、完整 OpenType shaping、所有字体子集器或所有 PDF 通用兼容。实际支持的着色、裁剪、递归、嵌套和字体格式组合由阶段矩阵定义；允许先交付有明确限制的切片，但不得无验证地标为正式支持。

验收必须在同一最终源码上完成相关单元/集成、完整工作区回归、独立映射/位置/轮廓检查及固定样本视觉复核。测试中的超时、崩溃、预算不足、未知映射、缺字体和资源循环不算通过；临时分配 reservation 不能宣传成进程 RSS 或 CPU 硬上限。推送、标签及发布不随实现自动执行。
