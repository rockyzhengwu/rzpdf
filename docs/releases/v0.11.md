# v0.11 加密保存与签名链路

状态：2026-10-17，V11-00～13、阶段 A/B/C 及横向验收均已完成限定范围本地验收。最终完整工作区 85 组、1,501 项，联合 156 项，四组独立门禁 27/21/42/30 案例，八组精确像素及十个页面渲染结果目视复核通过；609 项源码/配置/测试资产的前后指纹和列表一致。[安全边界](v0.11-security-matrix.md)、[支持矩阵](v0.11-support.md)和[验收记录](v0.11-acceptance.md)分别登记范围、能力及实际证据。基线为实现 `c26f243` 和规划 `b9f5f17`；未改包版本、提交、发布或推送。可盘点 v0.12，不自动开工。

本版解决三个核心问题：在保持保护的情况下追加保存、明确验证每个签名覆盖的历史版本、只允许符合约束的签后修改。不是证书信任服务，不承诺 PAdES/PDF/A 合规，也不把加密、签名和增量保存任意组合开放。

## 架构调整

1. **历史版本视图**：从不可变源解析 revision 边界、xref/Prev 和可解析的历史对象图。签名覆盖范围不能只用当前 overlay 或最新对象解析，也不能把原始前缀仍存在等同于修改获准。
2. **验签与信任分层**：分别报告 ByteRange/覆盖版本、CMS 摘要及签名密码学结果、后续变化和约束结果。证书链信任、过期、撤销和时间戳不伪装成核心验签结论；不隐式访问网络。
3. **受控修改计划**：以对象变化和可达关系分类实际变更。准备计划绑定源身份、revision、授权策略和预算；采用不修改 overlay 的不可变计划，由专用完成接口返回复验后的字节，而不是打开可重入的通用修改特权。低层任意更新及全量重写继续保守拒绝已签来源。
4. **保存与保护策略分离**：增量 serializer 接受已验证的保护/变更计划，不接受通用 `ignore_signature` 开关。读取旧对象的解密状态与新写对象的加密状态分开，防止明文泄漏和重复加密。
5. **拆分签名模块**：在不改变现有 API 契约的前提下逐步分离历史模型、CMS 验证、签名准备/完成、修改策略和外观集成。复用既有 writer、事务、AcroForm、AP 和共享预算，不另建旁路对象库。

未知变更、未知 transform、混合/损坏历史或无法建立完整关系的输入，默认拒绝相关写入。权限取加密权限、文档/字段签名约束及操作范围的共同限制；owner 认证不应自动绕过签名修改约束。

## 实施顺序与退出条件

三个阶段及横向验收均为必选，不用一次小范围成功关闭整个版本。按 V11-00 的边界和样本冻结实施 A；B 的历史读取/验签可先独立交付，但 C 未通过前不开放一般签后写入。冻结的算法和修改策略目标不表示相应实现已经存在，须各自通过 B/C 门禁。

## 验收矩阵

每个实现条目必须同时登记公开入口、支持版本/算法、样本、正负例、错误类别及实际执行证据。新增测试数量不是标准覆盖率。

- **加密保存**：user/owner/错密码；空 user 密码；直接字符串/普通流/metadata/附件；旧 ObjStm 中对象被更新与未更新的组合；至少三轮 Prev；新密文可由独立工具解开，原始字节前缀完全不变，未选明文例外不泄漏新增明文。Encrypt/ID 被低层篡改及不支持 crypt filter 必须拒绝。
- **历史签名与算法**：至少两类独立生产者的审批签名；空字段/层级字段和已签字段；不同覆盖 revision；篡改原始正文、xref、ByteRange、CMS 摘要/签名、证书标识和算法参数。结果须区分 unsupported、malformed、cryptographic failure、not verified；不把 untrusted 等同于签名比特错误。
- **多签与修改约束**：至少三签链；追加旧字段填值、可见 AP 和后续签名的允许/禁止组合；认证约束与字段锁交叉；共享资源改变、隐藏层正文改变、结构节点/页面迁移及删除锁定字段的绕过负例。每个旧签分别验证，不能只检查最后一签。
- **事务与资源**：准备后编辑、rollback、外层 panic、重复完成、CMS 超占位、预算恰好不足、随机源/外部签名器失败、writer 短写及目标文件已存在。检查文档身份/revision、提交计数、源 hash、旧签范围和重试能力；区分调用者 writer 可能部分输出与原子文件接口。
- **独立与视觉**：复用已安装 qpdf/pikepdf、OpenSSL/pyHanko 和 MuPDF/Pillow，先确认版本和可用性；工具缺失记未验收，不自行安装或算通过。AP 变化对照既有表单渲染；无绘制变化则不以截图代替签名或授权校验。不安装 Poppler，不运行 fuzz。

测试按任务运行专项，在阶段集成和最终冻结时跑完整工作区，不为每个小改动重复全量。V10 的 1,453 项是基线证据，不覆盖尚未实现的 v0.11。

## 不包含与保护边界

加密签名组合、公钥加密、新建弱算法加密、PAdES/LTV、在线信任链/撤销/TSA 服务、HSM/私钥存储、原地覆盖已签原文件、自动删除历史敏感数据及任意签后编辑均不随本版默认开放。线性化与新的 xref/ObjStm 输出布局沿用 v0.12/后续专题边界。R2/R3/R5 等遗留读取的最终决定必须落在 V11-00，不能默认承诺全覆盖或开工后悄悄删除任务。

标准依据沿用 PDF 标准路线的第 7 章（文件结构/加密）与第 12 章（签名/变换）及适用版本的差异；PDF 2.0 更正核对 [Syntax errata](https://pdf-issues.pdfa.org/32000-2-2020/clause07.html) 和 [Interactive features errata](https://pdf-issues.pdfa.org/32000-2-2020/clause12.html)。扩展算法的具体规范、OID 和依赖版本须在 V11-00 单独登记，不将勘误索引视作完整标准替代品。
