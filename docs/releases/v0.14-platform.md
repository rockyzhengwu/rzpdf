# v0.14 平台与迁移说明

新增 API 是按本版限定范围验收的增量式接口；不改 ParseOptions、Limits、SaveOptions 或 IncrementalSaveOptions 的既有字段，不改默认 writer 布局。保留 `pdf`／`render`／`font-data` 三个 crate，没有新增依赖。方法定义在 `PdfDocument<R>`，owned `Document` 沿用 Deref；`RecoveredDocument` 不获得写能力。

新建使用 `Document::new_with_version(PdfVersion::V2_0)`。旧文档应显式按 PDF 2.0 保存、重开后再调用 AF 写接口；读取旧文件的原始 AF 不等于升级或追认符合性。ObjectHandle 仍是地址；owner target 和列表包含 stamp，任何修改之后都需重新获取。

已有附件／批注的载荷选择没有统一成一个新默认：名称树 API 仍按 F，批注 API 仍优先 UF。这些入口现在复用一个不做外部 I/O 的选择辅助函数；新 AF 的额外 Type／MIME／关系／歧义规则不会无声收紧旧接口。普通旧附件要复用到 AF，应显式克隆并提供名称／关系／MIME，而不是原地补写共享 Filespec。

只有本地 macOS 13.7.8（22H730）x86_64 实际执行并通过本版门禁；Linux、Windows、macOS arm64 未验证。工具版本、固定规模耗时和 RSS 从最终运行记录引用，不把编译／启动等待算成算法正文，也不更改系统签名、安全服务或动态库配置来缩短启动。

事务、权限和错误契约沿用既有模型：失败不能留下半注册对象；rollback 可能使旧 stamp 失效；同一 OperationBudget 释放后可重试。budgeted payload 与列表在存活期间保留额度；scratch reservation、持久 store／缓存和全进程 RSS 的不同口径见[边界](v0.14-boundaries.md)和[性能记录](v0.14-performance.md)。
