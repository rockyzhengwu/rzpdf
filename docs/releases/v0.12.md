# v0.12 文件结构输出与兼容收口计划

状态：2026-10-19，V12-00～13、M1～M4 和阶段 A／B／C 已完成冻结范围本地验收。最终同一源码完整工作区 91 组、1591 项，联合复验 18 组、217 项、九组必选独立门禁和 437 页目视复核通过，640 项输入及十个二进制前后一致。范围见[冻结边界](v0.12-boundaries.md)，证据见[验收记录](v0.12-acceptance.md)。仅 macOS x86_64 已验证，其他平台明确未验证。本版已收口，未提交、推送、改包版本或发布，不自动进入 v1.0。

目标是补齐文件结构的选定输出组合，明确未知对象保留及恢复来源，再对各版已声明能力做可追溯审查。分三个必选阶段，不以阶段 A 输出一个压缩文件就关闭整版。

## 冻结实施范围

### A 文件结构输出

- 默认仍为传统 xref、独立间接对象；旧 API 不隐式启用对象流或升级版本。
- 新增全量 xref stream 输出，以及全量 xref stream + ObjStm 输出。对象流和交叉引用流要求适用的 PDF 1.5+，更低版本须显式升级；不改变现有不降有效版本的契约。
- 全量新布局同时纳入未加密和现有 R6 保护。保留 R6 沿用 PDF 2.0 或合格的 PDF 1.7 扩展声明；新设置 R6 沿用 PDF 2.0 要求。显式移除和重新设置保护均按既有身份／权限规则，不新增旧加密算法。
- 增量新增 xref stream 追加，限定现有严格不可变、未签来源；覆盖未加密与 authenticated R6。旧 compressed 成员修改仍输出独立对象；本版候选不在增量尾部新建 ObjStm。
- 普通输入读取涵盖传统表、xref stream、hybrid 及 Prev；来源转换能力和新输出格式分别验收。hybrid 输出、线性化输出不纳入。
- v0.11 签名／受控更新保持既有布局和保护边界。新选项不传播到已准备字节，不允许重排 CMS 占位或重写已签来源。

### B 对象保留与恢复

- 以读／保留／编辑三列审查未知键、普通未知对象、trailer、源结构容器、Info/XMP、EmbeddedFiles、AF、结构和 OCG。普通原样保存与页面导入／删除的关系维护分别证明。
- 给现有 Compatible 容错增加有界文件结构诊断；保持与内容流 diagnostics 分离。不把 Strict 读取成功宣称为整份 PDF 标准符合性验证。
- 候选新增显式、只读的有限 xref 恢复：针对错误 startxref 或缺失／损坏 xref，但仍保有明确 trailer Root 的简单未加密、单 revision、非对象流来源。不得从文本中的 obj／endobj 子串猜对象，不能确定 stream 边界、存在冲突对象或 Root 歧义即拒绝。
- 恢复首个 profile 限完整输入不超过 64 MiB、候选对象不超过 `min(max_objects, 100000)`；扫描步骤、报告及 parser／operation 限额见[冻结边界](v0.12-boundaries.md)。这些是保守策略上限，实际预算／性能由后续任务验证，不是已测得的性能保证。
- 索引重建来源只读；不开放恢复写回、增量、签署或受控编辑。保留现有 Compatible 正常全量保存契约，但不能将新恢复来源混入该路径。恢复加密、签名、ObjStm、混合／多 revision、无 trailer 的猜测恢复暂缓。

只读恢复和增量不新建 ObjStm 已纳入 V12-00 冻结范围；不是声称其他组合无法按标准实现。

### C 标准覆盖和工程验收

- 对 v0.1～v0.11 的正式支持范围建立“标准条目／版本／读写渲染编辑／入口／样本／正负例／证据”矩阵；实验功能和未实现项不自动转正。
- 增加真实工具生产的可再生样本、对象投影和像素对照，记录来源、许可、版本及 hash。不能只让本库写、本库读。
- 补齐大量小对象、分组边界、稀疏编号、多轮追加、不同编码和恢复扫描的预算与性能基线；不设尚未测量的压缩率或提速承诺。
- 分别登记 macOS／Linux／Windows 的实际结果。工具或平台不可用记未验证，不自动安装、创建远端 CI 或算作通过；本地验收与跨平台宣称分开。

## 架构调整

1. **内部布局计划**：在既有权限／版本／来源校验之后建立对象分类、临时容器号和输出顺序；复用现有序列化、压缩、保护和预算，不复制全量 writer。
2. **类型化 xref 记录**：明确 Free、Uncompressed、Compressed 的字段含义；共享表／流编码，统一溢出、自引用、自由链及 generation 检查。
3. **对象流打包器**：只处理合格对象，按对象数和未压缩字节双上限分组；stream、非零 generation、Encrypt、长度依赖及签名占位等保持独立。参考适用标准核对其他禁入类型。
4. **保护边界**：成员编码—容器压缩—容器加密；xref stream 保持可读取，不重复加密成员。源结构容器与业务未知对象使用不同处置规则。
5. **来源诊断状态**：文件结构报告与内容诊断分离；恢复状态不可通过 mutable trailer 或 mode 修改消除，读取成功不产生写入授权。

`writer/layout.rs`、`writer/xref.rs` 和 `writer/object_stream.rs` 已用于 M1。兼容方案采用独立 `SaveLayout` 枚举及四个保存入口，不增加 SaveOptions 必填字段；现有 public ObjectInfo 不改签名。完整 API 和默认行为见[冻结边界](v0.12-boundaries.md)。

## 里程碑顺序

1. **M1 未加密文件结构输出**：V12-00～03。先输出不打包的 xref stream，读回与独立检查稳定后再加入 ObjStm。
2. **M2 保护与增量闭环**：V12-04～05，补齐 R6 全量及 unsigned 增量；不能让 R6 到最后才发现对象流被重复加密。
3. **M3 保留与恢复**：V12-06～08，诊断和只读来源能力先于对象索引重建。
4. **M4 工程收口**：V12-09～13，矩阵可随开发累积，最终冻结后执行全量门禁。

V12-00～03 关闭 M1，V12-04～05 关闭 M2／阶段 A，V12-06～08 关闭 M3／阶段 B，V12-09～13 关闭 M4／阶段 C。整版最终门禁已独立执行，不借用子阶段计数替代；详细边界和原始结果见验收记录。

## 独立与回归门禁

| 领域 | 必须验证 |
|---|---|
| 输出组合 | 未加密全量三种布局；R6 的新流布局；unsigned 未加密／R6 的传统及流式增量；禁止组合明确拒绝，无静默回退 |
| 独立结构 | qpdf 检查和 xref 检视、pikepdf 成员／字典／流投影、MuPDF 读取；记录警告，工具发生结构重建时不能算严格写出通过 |
| 历史与保护 | 至少三轮 Prev，修改／删除旧压缩成员；旧源前缀、Encrypt／ID 和认证权限；v0.11 四组安全门禁复验，新布局不得绕过签名来源保护 |
| 保留与绘制 | 普通未知对象及私有字典、附件/XMP/AF、Unicode 字体、表单／导航、结构和 OCG 的选定样本；同引擎重布局前后像素保持，独立阅读器复核不出现丢页／空白／错字 |
| 恢复 | 每种成功恢复都有 Strict 拒绝和只读来源断言；歧义、扫描耗尽、错误 Root、流内伪对象及不支持的保护／历史拒绝，报告不假装原文件有效 |
| 失败 | 输出上限、共享预算、对象号溢出、压缩／随机源／writer 错误、目标已存在、rollback/panic；源对象／提交计数／原文件不部分提交，符合原接口的重试契约 |

专项随任务运行；完整工作区只在阶段集成和最终冻结时运行，不在纯文档盘点时重复长回归。不运行 fuzz，不安装 Poppler；现有工具不足应登记，不自动补装。
