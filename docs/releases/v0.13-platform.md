# v0.13 Platform and migration notes

The execution host is macOS 13.7.8 (22H730), x86_64, rustc/cargo 1.99.1.
The frozen profile passed 1609 whole-workspace tests, 273 joint rechecks and all
eleven required independent gates plus the supplementary indirect-config audit.
Linux, Windows and macOS arm64 have not been executed. Final test outcomes are
recorded separately in the [acceptance record](v0.13-acceptance.md); an available
native dependency or a successful compile is not a cross-platform test result.

The API is additive in `document::optional_content_edit`. `PdfDocument<R>` owns
the implementation and `Document` uses its existing Deref facade. Existing
ParseOptions, Limits, SaveOptions and IncrementalSaveOptions literals remain
valid; default save layouts and old selection APIs do not change.

Each writing method takes a caller-owned shared OperationBudget. There is a
conservative 2 MiB scratch minimum and a selected authoring profile, rather than
an implicit promise that every file accepted by the reader is editable. See
[layer authoring](../layer-authoring.md) for the complete call sequence and
[limits](v0.13-boundaries.md) before choosing a pool size.

ObjectHandle remains a document-scoped address, not a revision token.
LayerConfigurationTarget and page ContentProgram require an exact document
stamp. Reacquire them after edits and entered transactions that rolled back.
No new ordinary editing API becomes available on RecoveredDocument or bypasses
signature-source and R6 permission checks.

Default configurations are generated with ON / View semantics; permissive legacy
reading is not tightened. To initially hide groups, put them in OFF instead of
setting the default BaseState to OFF. Alternative configurations can use OFF or
Unchanged. No layer migration, deletion, flattening, action execution or secure
erasure is added.

The library retains existing host-file atomic replacement and caller-writer
partial-I/O contracts. The example generator uses new paths; a later example
failure may leave earlier successful files in its output directory. No package
version, tag, release, remote CI, dependency or system security setting changes
are part of this implementation.

Some local test processes show long launch-to-harness delays even when their
reported test body is only milliseconds. A read-only process sample did not
resolve symbols reliably, so no specific system-service cause is asserted.
System security settings were not changed and tests were not ignored to avoid
that delay; build/launch time and test-body time are reported separately.
