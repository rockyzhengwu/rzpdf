# v0.3 font and external-file support matrix

Status: frozen positive matrix; final workspace regression is recorded in the
separate acceptance report. This is a deliberately narrow support claim, not
an assertion that arbitrary fonts or PDF files work.

## External documents

These are unmodified public documents, not rzpdf-generated fixtures. Download
by the Wikimedia Commons file page and verify SHA-256 before running tests;
the files are not redistributed in this repository. License descriptions
belong to the respective file pages.

| File | Origin / license | Producer / pages | SHA-256 | Initial strict result |
|---|---|---|---|---|
| [17 years of Cantonese Wikipedia](https://commons.wikimedia.org/wiki/File:17_years_of_Cantonese_Wikipedia.pdf) | Deryck Chan, CC BY-SA 4.0 | Google, 11 pages; embedded CJK fonts | `c021c80a85cbe19bccd19aa538e93f9490873aea6600676e8fbf6b2d41ced143` | Strict mode rejects malformed object 0 free offset; compatible mode reads all 11 pages with complete Unicode mappings and zero page diagnostics; saved copy reopens strictly |
| [Scanner-test](https://commons.wikimedia.org/wiki/File:Scanner-test.pdf) | LA2, CC0 1.0 | LibreOffice 4.4, 1 page; embedded TrueType | `7e74fb2a07678dfea62ab7d773a2cd3c78e6fd5fe81b379d9ccde7303e3187db` | Strict parse, 7,114/7,114 Unicode mappings, zero diagnostics after MCID-only marked-content support; strict round-trip passed |

The distinct producers are established from PDF metadata and the Commons
file pages. Both originals and saved copies passed `qpdf --check` locally,
which does not imply full PDF semantics. The Chinese file includes Identity-H
CJK font resources. On the frozen copies, rzpdf's per-character Unicode,
charcode and floating-point position tuples are identical before/after save;
all 11 pages have complete Unicode mappings and zero interpretation
diagnostics. The scanner page has 7,114/7,114 mappings and zero diagnostics.
MuPDF plain text and structured text (including positions) were identical
before/after save for both documents. MuPDF 72-dpi page PNGs were byte-identical
for all 12 selected pages. Each page was also rendered by rzpdf/Skia and
visually compared; there is no observed missing glyph or layout shift, though
minor anti-aliasing differences remain. The original Chinese file's strict
parse rejection is an explicit compatibility limit, not a silent repair.

The separately examined pdfTeX-produced CC0 `UnitaryMethod.pdf` was not
selected: 234 of 296 characters lack Unicode mappings in rzpdf, even though
MuPDF extracts text. This is recorded as an explicit compatibility gap, not
counted as a passing document. A one-page Microsoft Print To PDF CC0 sample
was likewise not selected because it consists of images and has no text-font
coverage. These substitutions preserve the two-producer minimum rather than
loosening the positive matrix.

## Existing implementation inventory

| Layer | Included capability | Remaining limit |
|---|---|---|
| `font-data` | 14 PFB/AFM families and 65 licensed CMaps, generated into `OUT_DIR` from read-only inputs | No arbitrary external CMap discovery |
| Simple fonts | Encoding, AFM widths, embedded program and declared alias lookup; source provenance exposed | Alias rendering is a substitute, not exact font reproduction |
| Type0/CID | Identity-H/V, ToUnicode, CID/GID and W/W2 parsing, with the selected static-font H/V matrix checked | No general complex shaping or arbitrary vertical-font guarantee |
| Static TrueType writing | Whole and subset embedding; selected embedded glyph closures, GIDs, metrics and checksums independently checked | Not a generic font-subsetting compatibility claim |
| Editing | Transactional subset/edit paths, budget rejection and shared-resource isolation in the selected cases | No automatic reflow or general nested-content coverage |
| Skia renderer | GID drawing and vertical offset support; selected pages visually checked | Image resampling remains nearest-neighbor, with visible differences on some downscaled graphics; unsupported PDF graphics features remain |

Existing synthetic vertical tests and historical local-font runs are useful
regressions but do not themselves expand this matrix. There is no automatic
system-font discovery or arbitrary-font fallback in scope. MCID-only marked
content is ignored for visual/plain-text interpretation, while semantic
properties such as `ActualText` remain outside this selected behavior.
