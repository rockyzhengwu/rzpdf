# v0.14 关联文件实施计划

2026-10-19，基线为 v0.13 检查点 `6be4cc3`。状态：范围盘点完成，V14-00～09 均未实施或验收。目标是补齐 PDF 2.0 的文档级与页面级关联文件 AF 闭环，不重写解析器、writer 或渲染器。源码依据和候选取舍见[盘点](v0.14-inventory.md)。本计划不启动 v1.0，不承诺 PDF/A、PDF/UA 或全部 AF owner 支持。

## 本版范围

| 能力 | 必选交付 | 明确不包含 |
|---|---|---|
| 读取 | Catalog／page 的 AF 列表、Filespec 身份、名称／描述、关系、MIME 和选定参数；显式有界提取 payload | 全文件附件发现、外部路径读取、URL 下载或附件执行 |
| 创建 | 从字节创建带 AFRelationship、Unicode 名称和显式 MIME 的间接 Filespec／EmbeddedFile | 从扩展名推断关系；自动判断业务文件内容 |
| 复用旧附件 | 显式克隆选定已有 Filespec 为新的 AF Filespec；必要时克隆流字典补 MIME，保留 payload；旧名称／批注／其他 owner 不变 | 原位改写共享关系或共享载荷；缺字段时静默补猜测值 |
| 关联编辑 | 绑定／解除 Catalog 或一个页面与 Filespec 的关系；同一文件可关联多个 owner | 物理删除、垃圾回收、安全擦除、解除其他 owner 的链接 |
| 页面操作 | 选定 page AF 的同文档复制、跨文档导入／选页提取、重排及删除的保留与保护验证 | 将源 Catalog AF／EmbeddedFiles 自动合并；新增 StructElem、XObject、批注或 DPart AF 编辑 |
| 保存保护 | 三种全量布局、两种 unsigned 增量、既有选定 R6 身份／权限组合 | 签名后任意修改、恢复写回、新加密 handler |

无 AF 的旧 API 和默认保存行为不变。新生成仅面向有效版本 PDF 2.0；低版本显式升级后重开或拒绝，不静默修改版本，也不以旧版本保留行为冒充支持 AF 生成。旧附件与原始保存接口的兼容范围不收窄。

## 数据与 API 设计方向

建议新增 `document/associated_files.rs`，共享的 Filespec／EF 辅助解析放在 document 内部，而不是再增加 crate。外部类型只表达文档 owner、页面 owner、关联记录、文件定义和关系值，不能开放“任意 ObjectHandle 都是 AF owner”的通用写入入口。

首版写入关系限定 Source、Data、Alternative、Supplement、Unspecified；其余关系名只读保留并报告，不做有损归类。具体枚举与编码规则由 V14-00 核对完整规范后冻结，不能把当前子集说成完整标准列表。

入口按以下职责分开，Rust 名称和签名待 V14-00 固定：

1. 读取一个明确 owner 的 AF 快照；返回 stamp、原顺序和独立 Filespec 身份，不解码全部附件。
2. 通过读取记录／句柄显式提取一个嵌入文件，接受共享 OperationBudget；没有 EF 的外部 Filespec 不能被当成本地路径打开。
3. 从字节创建，或从旧附件显式克隆 AF Filespec；调用方给出关系、名称和合法 MIME。新建文件不隐式注册 EmbeddedFiles 名称。
4. 将当前文档内已验证的 Filespec 绑定到选定 Catalog／page；重复同一身份不重复追加，同名不同对象不合并。
5. 从一个 owner 解除指定 Filespec；不存在时无操作成功，最后一项移除 AF 键，不影响名称树、批注、其他 owner 或存储对象。

新 API 的幂等操作要求 commit revision 和已序列化状态不变；ObjectHandle 仍为地址，不能当作 revision token。索引选择、列表快照或预检计划需 stamp，页面采用身份而非可过期页号绑定；失败回滚后重新取快照。

## 架构约束

- 复用 PDFContext 版本／权限／来源保护、文档身份、预算事务和现有 writer。RecoveredDocument 不增加写能力，签后受控修改白名单不增加 AF 操作。
- 新增共享 Filespec／EF 校验只覆盖实际共同规则，不借机大改全部附件或批注模块。F／UF、EF 对应关系和默认载荷选择必须冻结，差异有测试；旧 API 不能无说明改变提取结果。
- 对 owner AF 数组做 copy-on-write；旧数组别名与其他 owner 不变。保留 owner 和 Filespec 的无关私有键；无法证明相关扩展不冲突时拒绝编辑，不能整份快照重建而丢键。
- 不提供共享 Filespec 的原位关系／payload setter。不同关系通过新 Filespec 表达；已验证的不可变 payload 可共享。克隆缺 MIME 的旧流时只改新字典，不污染旧引用。
- 页面迁移复用现有批次 ID map；同一导入批次保持 Filespec／stream 共享，不跨文档复用裸对象号。未知 owner 回指、结构容器和未选中页面引用仍拒绝。
- 新列表／计划／载荷／克隆／事务临时分配使用同一 OperationBudget，数字上限与现有 Limits 相交；未跟踪的缓存、store 增长和原生分配单列，不把 tracked peak 当 RSS。
- 不给现有 ParseOptions、Limits、SaveOptions 或 IncrementalSaveOptions 添加必填字段，不改变默认输出布局。不缓存跨 revision 的 AF 解析结果；单次操作可复用一次有界解析结果，避免复制 v0.13 的逐成员重读模式。

## 验收矩阵

| 类别 | 正例 | 负例与不变量 |
|---|---|---|
| owner／身份 | Catalog、两页、一个文件多 owner、同名文件、重复绑定 | 外国句柄、过期快照、已删除页面、错误对象类型；不按文件名判断身份 |
| Filespec／EF | F／UF、直接／间接输入、共享流、Unicode 名称、描述、合法 MIME | 不匹配 EF 键、歧义载荷、缺关系／MIME、非法 MIME；未知关系不自动改写 |
| 输入安全 | 空文件、零字节、含 NUL／高位字节的纯合成载荷、受支持编码 | 超大／压缩展开超限、循环引用、嵌套限额、外部路径／URL；不打开、不联网、不执行 |
| 编辑隔离 | 关联数组旧别名、private 键、多页共享、一页解除 | 不改变其他 owner、原 Filespec 或 payload，不误删名称／批注；失败无部分提交 |
| 页面关系 | 页面级 AF 复制／导入／提取／删除 | Catalog AF 不偷偷并入；未选页面／未知回指与结构容器继续拒绝 |
| 保存 | 三全量 × Preserve／Flate，两个增量布局；选定 R6 | payload hash／字典语义／共享关系保持；低版本、错密码、权限、签名／恢复拒绝；无失败输出 |
| 外观 | 原始页面和所有成功修改后页面的 MuPDF 对照；选定 Skia 对照与文本核对 | AF 是非绘制修改，要求外观和正文不变；不能用附件提取通过替代像素检查 |
| 预算 | 记录数、owner 数、payload 大小三类规模；同池重试 | 边界刚好满足／差一、累计多文件、整数溢出、drop／unwind 释放；不宣称全 RSS 受控 |

记录数建议测 1／100／1000，payload 建议测 0 B／1 KiB／1 MiB，加一组多文件累计载荷；最终数值上限在 V14-00 根据实际实现与 Limits 冻结，不把建议规模当成硬上限或性能 SLA。

## 独立验证与回归

独立样本优先采用 pikepdf 和 MuPDF PDFDocument 接口的原始合成配方。V14-00 必须先探测本机工具是否能创建所需 AF 图；当前尚未验证 MuPDF 的该配方。不能用“pikepdf 创建后由 MuPDF 重写”冒充第二种原始 AF 生产者；若工具能力不足，报告并明确调整配方后才能关闭 00。不安装新工具来隐式改变环境。

新增 `v014_associated_files` 集成测试、示例和 `check-v014-associated-files.py` 门禁为计划产物，当前不存在。qpdf／pikepdf 检查结构、MIME、引用与解码字节；MuPDF 独立提取／渲染能力先探测，不假定它能列出仅 page AF、未注册名称树的文件。必要时结构投影检查 AF、显式 stream 提取检查 hash，分别声明工具实际验证内容。

旧功能联合复验至少包括附件单元、metadata、v09_annotations、v09_page_relationships、v010_structure_transfer、v012_preservation、v012_recovery、v012_incremental_stream、v012_layout_security、v013_optional_content_edit 和相关权限／签名测试。最终独立必选门禁为新增 AF、v0.12 对象流（内含 xref）、布局安全、增量、保留、恢复，v0.13 图层和旧图层，以及 v0.11 的工作流、多签、CMS／历史、加密增量，共十二组；嵌套命令不重复计数。任何豁免须先修改范围并说明，不能把未运行写成通过。

先定向、阶段联合，再冻结源码／配方和实际驱动执行整版；收取真实退出码，源码变化按影响复验。编译、启动等待、测试正文分别记录，长测不靠 ignore 收口。每版使用新产物目录，记录原始来源、许可、工具版本、hash、预算和实际视觉页数。平台只按实际运行登记，不沿用 macOS 推出其他平台通过。
