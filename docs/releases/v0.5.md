# v0.5 高级保存与安全：实施计划

日期：2026-10-14。状态：计划与开工前盘点；没有任何 v0.5 功能通过验收。

v0.4 已于 2026-10-14 收口：用户确认完整回归全部通过，证据来源见 [v0.4 验收记录](v0.4-acceptance.md)。可以开始本版实现；基线为包含 v0.4 收口记录的提交。本文的阶段编号是交付边界，不自动修改 Cargo 版本或创建发布标签。

## 1. 产品目标和分期

让调用者能保存有限修改、用密码保护文档，以及把最终 PDF 交给外部签名方签署。不是实现通用密码恢复、完整证书信任服务或所有历史安全处理器。

| 阶段 | 必选交付 | 退出门禁 |
|---|---|---|
| V05-A 增量保存 | 未加密、未签名文件的追加式保存，原字节保留，多次编辑链 | 字节前缀、xref/Prev、删除、事务、外部重开、输出失败测试 |
| V05-B 密码保护 | Standard handler 的 AES-256 / R=6 读取和全量写出；密码和权限报告 | 外部生成/外部读取双向验证、错误密码、字符串/流边界、预算 |
| V05-C 签名接口 | 未加密文件的单个不可见批准签名；外部 CMS 签名准备/完成两阶段接口 | ByteRange 精确覆盖、外部签署与验证、篡改/过期准备结果拒绝 |

每阶段可以作为独立候选里程碑交付；只有三阶段必选门禁都通过，才称整个 v0.5 完成。若后两阶段延期，应明确缩小并重新确认版本范围，不能只完成 A 就勾选全部。

本期明确不做：RC4 新建加密、R=2–5 历史密码处理、Public-key encryption、密码破解、加密文件增量保存、加密与签名组合、多签追加、已有签名文件编辑、DocMDP/FieldMDP 修改授权分析、可见签名外观、时间戳/LTV/撤销在线查询、PAdES/PDF/A/PDF/UA 符合性、原地追加写源文件、真正脱敏和安全擦除。fuzz 延续暂缓决定。

## 2. 已有能力与差距

| 位置 | 当前证据 | 本版工作 |
|---|---|---|
| `pdf/src/writer.rs` | 全量序列化；非空 Encrypt 保存明确拒绝 | 拆出共享对象编码器，新增追加式 writer，保持原入口默认全量 |
| `document/save_options.rs` | 明确是 full-rewrite options | 用独立模式/入口表达增量；不改变旧调用默认语义 |
| `document/store.rs` | Upsert/Deleted 及对象号分配 | 导出稳定变更快照；分清源缓存、编辑覆盖层和保存基线 |
| `document/state.rs` | 事务、revision、commit_revision | revision 是失效令牌，不是可直接序列化的变更日志 |
| `parser/parser.rs` | Prev、XRefStm、严格 startxref 和链异常测试 | 盘点各种输入链；保存所需末次偏移与源完整性信息 |
| `parser/security.rs` | CryptFilter 校验；SecurityHandler::try_new 返回 UnsupportedFeature | 实现完整认证、密钥管理、对象级解密及写出策略 |
| `parser/crypto.rs` | RC4/AES 部分低层函数和向量测试 | 审计用途与填充/IV 契约；不能把已有 ZeroPadding helper 直接用于通用 PDF 对象加密 |
| `filter/crypt.rs` | 只有 Identity 可用 | 接入文档安全上下文，避免重复解密 |
| `document/acroform.rs` | v0.4 扁平文本/复选框 | 签名字段用独立 API，不顺带承诺一般字段树编辑 |

上述盘点是源码事实，不是 v0.5 支持声明。

- [ ] 明确不可变源的生命周期：保留原字节或稳定只读源；外部源变化须检测/拒绝，不能盲目拼接。
- [ ] 保留最后有效 startxref、源长度、原 trailer、原对象号/代次等元信息；与对象缓存分离。
- [ ] 保存期间冻结文档变更快照；任何失败不清空变更表、不推进基线。
- [ ] 本版保存不隐式 rebase：输出后再次编辑继续相对原源生成结果；要连续追加版本，重开上次输出。两个路径分别测试。
- [ ] 设计独立 security context：认证状态、敏感密钥、过滤器、权限、密码字节处理；不污染内容编辑 API。
- [ ] 设计 PreparedSignature：最终待签字节、排除区间、摘要算法、文档失效令牌；准备后不可再改变字节。
- [ ] 审查密码学/CMS 依赖：许可、平台、维护状态、构建体积和敏感内存；优先成熟依赖，不自行实现 AES/SHA/CMS 原语。

安全不变量：密钥/密码不进入 Debug、日志、错误或 fixture；使用操作系统支持的密码学随机源；认证失败不暴露部分解密对象；能控制的敏感缓冲区采用清理策略，并公开无法保证所有内存副本清零的限制。

## 4. V05-A：增量保存

### 实施顺序

- [ ] V05-01：定义增量入口、选项与 preflight。新建无源文档、不可信恢复源、加密/已签名输入、线性化输入先明确拒绝；不静默退回全量保存。
- [ ] V05-02：实现稳定排序的 Upsert/Deleted 快照，覆盖 trailer-only 修改、未变更和新对象后删除。
- [ ] V05-03：追加对象、传统 xref 子段、trailer、startxref/EOF；保留原前缀，正确处理 Root/Info/ID/Size/Prev，排除过期 XRefStm 等字段。
- [ ] V05-04：删除条目与代次/空闲链规则；先不重用删除对象号。新增对象不得与源对象或已有代次冲突；拒绝仍被存活对象引用的删除。
- [ ] V05-05：输入矩阵逐项开放：传统 xref、xref stream/对象流、多次增量、混合引用。修改压缩对象时追加独立对象，旧对象流不改写。跨形式链需独立工具验证，不凭解析能力推定可保存。
- [ ] V05-06：输出字节限额、偏移溢出、无变更返回原字节、文件安全输出。优先返回完整新字节/写到独立目标；禁止直接改写源文件。

### 必选验收

- 原前缀逐字节相等，不只是页面看起来相同；增量尾部不重写所有未修改对象。
- 全量与增量保存后的页面文本、资源、书签、链接、附件和基础表单语义一致。
- 保存/重开/编辑重复至少三次；每级 Prev 指向正确 xref，最终最新定义优先。
- 覆盖替换、新增、删除、trailer-only、无修改、事务失败、共享资源隔离；未知对象保持。
- 源含对象流的单对象修改可重开，未修改对象仍从原链访问。
- 错误源、循环/越界链、非法代次、offset/Size 溢出、预算不足均有明确错误。
- 注入输出写入失败：源不变；文档可重试；原目标不被失败结果覆盖。外部 Write 的部分写入不能冒称自动回滚。
- 本库 strict 重开及 qpdf 结构检查通过；独立阅读器读取修改值，MuPDF 对固定视觉样本渲染对比。
- 不承诺增量保存清除历史内容；API 文档显著说明旧文本/附件可能仍在原字节中。

## 5. V05-B：限定加解密

### 实施顺序

- [ ] V05-07：冻结 V/R/Length/CF/StmF/StrF/EFF/EncryptMetadata/ID 输入矩阵、R=6 密码规范化和长度边界。非 ASCII 密码只在规范与独立样本均验证后开放，不静默截断/变换。
- [ ] V05-08：认证：用户/所有者密码、空用户密码、错误密码、权限字段一致性；区分 PasswordRequired、InvalidPassword、UnsupportedSecurity 和 malformed input。
- [ ] V05-09：按解析层级解密字符串和流；正确处理对象流内字符串、显式 Crypt/Identity、xref stream 和 Encrypt 字典等例外，避免双重解密。
- [ ] V05-10：全量加密写出，安全随机密钥/盐/IV，正确流 Length、元数据策略和文件 ID；R=6 所需 PDF 版本/扩展声明不得只改 header。
- [ ] V05-11：显式 Preserve/Remove/Set 保存安全策略；默认保留原保护，绝不因普通 save 静默输出明文。已认证并授权的调用者可显式移除/换密码；改变安全配置只走全量保存。
- [ ] V05-12：权限报告与高层编辑策略。普通用户按策略限制写操作，所有者认证可管理安全设置；低层对象 API 的边界必须公开。权限标志不是防复制或 DRM 保证。

### 必选验收

- qpdf 生成的 R=6 fixture 能读；本库写出的文件能由 qpdf 认证、解密，并由独立阅读器显示。
- 用户/所有者/空密码/错误密码分别验证；非 ASCII、边界长度及非法编码有确定结果，不在日志打印密码或 key。
- 覆盖 literal/hex 字符串、普通流、压缩流、对象流、附件、元数据和 Identity；逐项验证内容没有重复加密/解密。
- `/Perms` 等认证一致性失败、未知 handler/revision、损坏密文/填充/字典均拒绝；“能解出部分文本”不算成功。
- 默认保存仍有保护；显式解密输出无 Encrypt 且内容一致；换密码后旧密码失败、新密码成功。
- 对同一明文的两次独立加密输出不同且都能解密；随机源失败时拒绝写出。测试可注入固定随机源，生产 API 不开放弱随机默认值。
- 用已知标准向量与独立实现验证，而非仅本库加密后本库解密。字符串与流的短块/整块/空输入均覆盖。
- 预算、输出故障、认证失败不推进事务或保存基线；secret Debug 脱敏测试通过。

范围依据：[qpdf 加密说明](https://github.com/qpdf/qpdf/blob/main/manual/encryption.rst)区分安全处理器修订及历史兼容性；[qpdf CLI 文档](https://qpdf.readthedocs.io/en/11.7/cli.html)说明加密输出的版本门槛。实施时记录实际工具版本，不直接复制新版本参数到当前机器。

## 6. V05-C：外部签名接口

### 实施顺序

- [ ] V05-13：只读签名字段识别与结构报告：ByteRange、Contents、覆盖到的 revision；此处不返回未经验证的“签名有效”。检测已有签名/认证权限后拒绝本期编辑/再签。
- [ ] V05-14：未加密、未签名输入创建单个不可见批准签名字段；不破坏 v0.4 已有字段；XFA/复杂不支持结构在写出前拒绝。
- [ ] V05-15：prepare：生成最终追加版本，固定 ByteRange 与 Contents 预留空间；返回不可变准备结果和签名用数据。首期冻结 SHA-256 与 detached CMS / adbe.pkcs7.detached。
- [ ] V05-16：明确外部接口签的是原始待签区间、PDF 摘要还是 CMS signed attributes，避免把 PDF 摘要直接当 RSA 签名写进 Contents。CMS 与私钥操作由成熟外部后端承担。
- [ ] V05-17：complete：校验准备结果未失效、CMS 与待签摘要匹配、长度足够；只填预留区域，保持已计算摘要的字节不变。拒绝陈旧令牌、错误签名内容、空间不足和重复完成。
- [ ] V05-18：签后编辑保护：本期默认拒绝修改/重写已签文件；不以“原字节还在”推断签名允许编辑。

### 必选验收

- ByteRange 两段准确覆盖最终 PDF，唯一排除 Contents 区域；无负数、重叠、越界、整数溢出或尾部漏签。
- 用仅用于测试的证书和外部 CMS 后端完成签署；pyHanko 独立验证摘要、CMS 签名和覆盖范围。
- 明确区分结构合法、密码学完整性、证书信任、签后修改四个结果。自签测试证书必须显式配置本地测试信任，不能当作公网可信。
- 修改被签覆盖字节必然验证失败；追加后续字节被报告为有签后变更，不误报“整个当前文件完全覆盖”。
- CMS 不是 raw signature；错误摘要/无效 CMS/截断/超预留长度必须拒绝，完成失败后源和准备结果可追踪。
- 准备后编辑文档、错配另一文档结果、重复完成、预算不足和输出失败都有负例。
- 签名前后页面外观、基础表单和交互关系不变；qpdf 检查不能代替签名验证。

签名后的增量更新并不天然合法；独立验证还涉及修改分析和信任上下文，参见 [pyHanko 验证说明](https://pyhanko.readthedocs.io/en/latest/cli-guide/validation.html)。本期不自行承诺完整信任链/撤销或 DocMDP 判定。

## 9. 排期与优先级

执行顺序：V05-00 → A → B → C → 最终收口。C 技术上依赖 A 而不依赖 B；本期不强行组合加密与签名。优先解决源快照与追加正确性，再扩密码学与签名表面。

按一名熟悉代码的开发者估算：设计/基线 2–4 个工作日，A 1–2 周，B 2–4 周，C 2–3 周，综合收口约 1 周；总计约 6–11 周，仅作风险预算，不是交付承诺。R=6 密码规范化、混合引用链、CMS 接口和独立验证是主要不确定项。每阶段验收后按实际差距重新估时。
