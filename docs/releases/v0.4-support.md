# v0.4 limited interaction support matrix

Status: bounded scope accepted locally on 2026-10-14; full regression completion confirmed by the user. Not tagged or released. This matrix describes the v0.4 API, not universal PDF interaction support. See [scope and gates](v0.4.md) and [acceptance evidence](v0.4-acceptance.md).

| Area | Read | Write/edit | Explicit limits |
|---|---|---|---|
| Bookmarks | Flat leaf outline list with in-file `/Fit` page destinations | Append, rename, unlink | No nested outlines, actions, or arbitrary view modes |
| Named destinations | Flat `/Names/Dests`; `/Fit` and `/FitH` page-index projection | Set/unlink `/Fit` target | No nested name tree, legacy catalog `/Dests`, or view-coordinate API |
| Links | Page `/Fit`, named target, printable ASCII URI | Add page/named links; add `http`/`https`/`mailto` URI links | Other actions, scripts, and link editing/removal unsupported |
| Annotations | Square rectangle and RGB color | Add Square with self-contained normal appearance | Other subtypes and Square editing/removal unsupported |
| Attachments | Flat document `/EmbeddedFiles`; decode payload | Add, extract, unlink; Unicode name via `/UF` | No nested name tree, file-attachment annotation, execution, or secure erase |
| AcroForm | Flat merged Widget text fields and Yes/Off checkboxes | Add/fill and regenerate normal appearance | Text appearance is printable ASCII only; no XFA, hierarchy, radio/push, signature, scripts, or calculations |

AcroForm reading preserves ReadOnly/Required/NoExport flags; filling ReadOnly is rejected. Existing rollover/down appearances are retained when normal appearance is regenerated. Field name and value strings are decoded as PDF text strings, not raw UTF-8.

Cross-feature relationships remain conservative: copy/import reject pages with nonempty annotations; page deletion rejects document navigation or nonempty annotations. Reordering retains page object identities. Unknown PDF structures may be readable at the low-level object layer but are not supported by these high-level APIs.

Input and stream limits come from `ParseOptions::limits`; failed high-level writes use edit transactions. Removal unlinks an object and is not a secure erasure promise. No PDF/A, PDF/UA, accessibility, or signature conformance is implied.
