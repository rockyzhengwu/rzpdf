# v0.3 engineering acceptance

Date: 2026-10-13. Scope: the frozen cases in
[v0.3 support matrix](v0.3-support.md), not general PDF or font compatibility.
This report distinguishes engineering acceptance from a commit, push, version
tag or crate publication.

## Candidate and local environment

The candidate is the v0.3 source and fixture revision containing this report.
The README rewrite immediately preceding it was committed separately as
`3949f33`. Local platform:
Darwin 22.6.0 x86_64; Rust/Cargo 1.96.0; qpdf 11.2.0; MuPDF `mutool`
1.27.0; FontTools 4.39.4 on Python 3.11. No remote CI was available.

## Verified cases

- The font matrix generator `pdf/examples/v03_font_matrix.rs` produces three
  pages: NotoSansSC static TrueType Identity-H, the same font Identity-V, and
  Courier/WinAnsi. MuPDF reports the expected Unicode strings. `mutool show`
  confirms Identity-H/V, ToUnicode, CIDToGIDMap, W and W2 objects. MuPDF and
  rzpdf/Skia renders were visually inspected for glyphs, direction, clipping
  and spacing. The embedded H/V font programs extract byte-identically to
  the pinned fixture. `python3.11 docs/check-v03-font-matrix.py
  output/pdf/v03-font-matrix.pdf` uses PyMuPDF and FontTools to check 14
  horizontal and four vertical ToUnicode/CID/GID/W entries, all four W2
  metric triples, and Courier/WinAnsi text with 600-unit AFM advances
  independently.
- `pdf/tests/v03_font_edit.rs` covers a new Chinese glyph, unchanged shared
  page, failed-transaction rollback, an insufficient operation budget, and
  a renamed OFL Latin font whose `é` is composite. The generated three-page
  subset sample is strictly reopenable and has the expected extracted text.
  `python3.11 docs/check-v03-font-subset.py
  output/pdf/v03-subset-composite.pdf` independently verifies the four
  extracted font programs, table/global SFNT checksums, original glyph IDs,
  glyf outlines, horizontal metrics and composite closure.
- The two selected public external documents have different producers; the
  11-page Chinese document has embedded CJK fonts. `v03_probe` confirms
  complete Unicode mapping, zero page diagnostics and exact rzpdf
  Unicode/charcode/position tuples before and after save on all 12 pages.
  MuPDF plain and structured text is identical between each original and
  saved copy, including structured-text positions; 72-dpi MuPDF page PNGs
  compare byte-identically. All 12 pages were visually compared with Skia
  output. Original/saved files and generated font samples pass `qpdf --check`.
  Skia's nearest-neighbor image sampling can make downscaled graphics look
  rougher than MuPDF; that is a published visual limit, not a text/glyph
  mismatch. A trial of linear sampling was reverted after it broke four
  existing exact-pixel image tests; the final candidate retains nearest
  sampling.
- The original Chinese document's malformed object-0 free offset is rejected
  by rzpdf strict parsing, although qpdf accepts the file; compatible parse
  succeeds and the saved file reopens strictly. The unrelated pdfTeX sample
  described in the support matrix is excluded because rzpdf lacks 234/296
  Unicode mappings. These are recorded limits, not passing cases.
- `font-data` generates derived CMap/module files in Cargo `OUT_DIR`; its
  source inputs remain read-only. `cargo package -p font_data --list
  --allow-dirty --locked --offline` lists all 65 CMaps, 14 PFB/AFM pairs,
  provenance and license notices, without generated `src` artifacts.
  `cargo package -p font_data --allow-dirty --locked --offline` packaged
  108 files and verified the package build successfully (exit 0).
  The historical `python3 docs/check-cmap-data.py` provenance/dependency,
  codespace, writing-mode and effective-CID regression also passed.
- Historical v0.1/v0.2 smoke examples were regenerated on this candidate:
  `create_document`, `edit_content`, `edit_text_operators_v02`, and
  `edit_form_v02`. Their four independent `docs/check-*-example.sh` / text
  operator checks all exited 0 under `set -e`, covering qpdf structure,
  text/position, image/path edits and shared Form calls. This is a focused
  v0.1/v0.2 smoke rerun, not a claim that the nested v0.2 gate script was
  rerun in full.

## Regression and final state

The final `cargo test --workspace --locked --offline --quiet` exited **0**:
one `font_data` unit test, 719 PDF core unit tests, all PDF integration groups
including four new v0.3 tests, 38 renderer unit tests, and doc-test groups
passed with no failures. The initially started workspace run used a compiled
copy of the new budget test from before its snapshot-refresh correction and
exited 101 at that test; it is not counted as acceptance. The corrected
targeted test and the subsequent complete workspace rerun both passed.

`cargo fmt --all --check` currently fails on extensive pre-existing workspace
formatting differences; it has not been silently represented as a passing
gate or mass-formatted as part of v0.3. `git diff --check` passed. No remote
CI, version tag or crate publication is claimed.

No fuzz testing was implemented or run for v0.3, as requested. The narrower
support and known graphics/text limits remain in the matrix and README.
