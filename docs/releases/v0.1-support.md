# v0.1 已验收支持矩阵与限制

更新日期：2026-10-13。本矩阵冻结 v0.1 的交付边界，不表示已发布或任意文件均可处理。验收状态见 [版本清单](v0.1.md)，证据见 [验证记录](v0.1-validation.md)。

| 能力 | 本版范围 | 重要限制 / 验证入口 |
|---|---|---|
| 文档状态 | 无输入源创建、文件/字节打开、严格/兼容解析、完整重写保存 | 默认新建1.7；选择2.0不等于符合性认证；推荐验收使用显式 Strict |

| 页面操作 | 增删、复制、完整重排、旋转/裁剪；跨文档导入、合并、按顺序选页拆分 | 索引从0开始；重排须完整排列，批量选页须唯一；资源按复制后修改隔离；v01_workflow / page_transfer_edit |

## 错误与资源限制契约

- 使用 `ParseOptions { mode, limits }` 控制输入策略；需要读取诊断时使用报告接口，不以空输出推断成功。
- 已有对象/深度、token、原始/解码流、缓存、图片/渲染像素、操作数、字符、路径及诊断限额；算术溢出和分配失败在已接入路径返回错误。
- `max_operation_bytes` 只约束显式接入同一 `OperationBudget` 的分配，不是全进程RSS/CPU保证。文档常驻数据、首次源缓存、部分传统接口的克隆/提取结果共存、跨文档导入整体峰值以及FreeType/Skia/解码器原生分配未全部统一计费。
- 本版不能宣传“所有畸形输入都无panic”或“全引擎硬内存上限”。确定性异常输入回归不是形式证明；与正式支持场景直接相关的已知崩溃、静默损坏、跨页污染或失败部分提交仍是发布阻塞项。
- 不支持功能返回 UnsupportedFeature 或相关明确错误；兼容模式的内容诊断由调用者决定是否拒绝。无法处理时不自动转换成空白页或假Unicode成功。
- `save_to_file` 的文件替换测试覆盖原文件字节、权限、临时文件清理及write/sync/rename错误/unwind；不承诺断电恢复、网络文件系统语义或未验证的平台原子性。

## 输入路径审计边界

本轮检查 `PageBuilder::validate`、标准编码/PNG/JPEG资源入口、导入前置检查、文件/Writer保存和FreeType创建错误传播，并关联现有确定性回归。未新增生产代码变更；资源名称由内部ASCII数字缓冲产生的UTF-8转换与测试中的故障注入panic不等同于外部输入触发panic。这个定向审计不替代所有解析器/字体/颜色模块的P0-08全面审计。

## 平台与非目标

当前实际验证为 macOS x86_64 / Rust 1.96.0。用户确认远端没有CI；仓库中的Ubuntu stable Rust工作流只是配置，不能算作已验证平台，也不作为本次本地验收的前置条件。Windows尚未验收，不能借用Unix文件替换结果宣称支持。

复杂内容/嵌套编辑、自动字体子集和竖排保持实验状态。完整批注/表单、增量保存、加解密、签名、真正脱敏、PDF/A/UA符合性和OCR不属于本版；fuzz继续暂缓，不实现、不运行。
