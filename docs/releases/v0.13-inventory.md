# v0.13 源码盘点与实施边界

2026-10-19，代码基线 `57f338f`。结论：v0.13 适合完成选定图层的高层创建、配置编辑与内容绑定，不需要重写解析器、渲染器或 writer。配置身份、Properties 注册、调用隔离和同池预算是主要新增工作。当前为静态源码盘点，未执行新增测试，未实现功能；[计划](v0.13.md)中的任务仍未验收。

## 已有测试能够证明什么

`ContentBuilder::try_build_with_limits` 已做 Strict 操作符解析、参数类型／范围、q／Q、BT／ET、路径当前点及待结束 clipping 检查，应复用而非重写。但该循环不追踪 BMC／BDC／EMC 的栈，也不解析实际页面资源和旧 Contents 的入口状态；因此还需要图层段专属验证。底层 `append_page_contents` 则只检查载荷长度后追加，不调用该 builder 校验。

[v010_optional_content.rs](../../pdf/tests/v010_optional_content.rs) 有 27 项测试定义，覆盖默认／替代配置、四策略、VE 优先级、循环／未知扩展、View／Print usage、foreign／stale 快照、隐藏内容状态、ActualText、Form／image／批注、版本、预算与缓存选择。它们证明的是读取／求值／解释路径，不是本版写入能力。

[check-v010-optional-content.py](../check-v010-optional-content.py) 已有 pikepdf 合成输入、qpdf 结构检查、三种配置的 Skia 输出与 MuPDF 期望几何对照，允许单通道 1 级量化差异但不允许几何位移。其配置通过既有入口选择；原样保存不等于修改 D。新门禁必须额外检查本库生成和编辑后的对象及字典，而不是只重跑旧脚本。

## 建议冻结的具体取舍

1. OCG 支持创建和重命名，不做删除／合并。删除需要扫描全部内容、OCMD、配置及未知关系，不能仅移除 OCGs 条目。
2. 默认配置采用明确的 Default 目标；已有替代配置用“文档 stamp＋Configs 索引”定位。索引只在该 stamp 下有效；不把同名配置合并，也不强制改写为间接对象。
3. 组句柄每次校验文件身份、对象存在、OCG 类型和注册成员资格。内容及配置快照额外验证 revision；已经退出并回滚的事务按旧规则使快照失效。
4. 首版配置写入字段为 Name、BaseState、ON／OFF。Intent／Usage／AS／Order／RBGroups／Locked 不提供编辑器；已有依赖规则无法证明不受影响时拒绝状态变更，重命名可按独立字段证明处理。简单新配置显式写出状态，不借用读取容错作为规范生成规则。
5. OCMD 只创建，不提供任意现有表达式重写。VE 与 P 的优先级沿用现有语义；未匹配 Intent 的 OCMD／VE 继续按既有子集拒绝。
6. 页面段绑定只追加经过完整检查的独立新段；要求入口与出口状态可证明，不自动修补旧内容。外层 q／Q 不能保存当前路径，也不能代替 BT／ET、BDC／EMC 和资源验证。
7. Form／image 仅绑定顶层明确寻址的一个 Do，现有嵌套绑定不纳入。已有外层 OC 与 XObject 自身 OC 不得覆盖：首版拒绝已存在自身 OC 的目标，不隐式合并表达式。支持的共享调用通过局部资源和独立对象隔离，不改全局对象。
8. 有结构所有权的 Form、未知关键字典语义、Type3／soft-mask 特殊调用不纳入隔离绑定；保留原拒绝。不得复制 StructParent／StructParents 就声称结构关系完整。
9. 新段不分配新 MCID，也不自动建立 ParentTree；允许不涉及所有权变更的选定标记嵌套，ActualText 跨图层原子替换仍保留拒绝。

这些是本轮建议的收口边界，正式签名和精确支持语法仍由 V13-00 固定。范围放宽须同时增加实现、预算和独立证据，不能以“底层可构造”替代验收。

## 新增模块与 API 草案

建议新增 `document/optional_content_edit.rs`，包含 OCG 输入、配置 patch、成员策略／表达式输入，以及内部带 stamp 的预检计划。方法按“创建组、重命名组、创建／修改配置、创建成员字典、追加图层内容段、绑定单次 XObject 调用”分开；具体 Rust 名称和返回类型待冻结，不承诺现在能编译。

公共输入尽量使用构造器或 non_exhaustive 类型，不给既有 Options 增加必填字段。表达式使用受限的组叶子和 And／Or／Not，而非接受任意 PdfObject；绑定接受受来源校验的内容程序与操作位置，而非屏幕命中序号。内部统一处理 Properties 注册、局部字典补丁、版本与保护检查，复用现有内容提交器，不复制 writer。

## 验收矩阵

| 任务 | 正例 | 必选负例及不变量 |
|---|---|---|
| 01 组 | Unicode、同名不同对象、新建／已有 OCProperties、私有键 | 外国／已删除／未注册／错误类型；无半注册组 |
| 02 配置 | 默认＋两个替代、同名、ON／OFF／Unchanged、直接／间接字典 | 过期索引、冲突／重复成员、未知相关规则；其他配置与引用不变 |
| 03 成员 | 四策略、嵌套 VE、重开求值 | 非法元数、外国成员、循环／深度／节点超限；不短路漏校验 |
| 04 新段 | 文本／路径／图像、Properties 命名冲突、继承资源、两种选择 | 旧段未闭合、非法操作符／资源、跨边界 ActualText；旧内容字节不改 |
| 05 调用 | 两页共享对象、同页两次调用、Form 矩阵／BBox、image mask 保留 | 自身 OC、嵌套目标、结构所有权、未知语义；只改选中调用 |
| 06 保存 | 三全量／两增量；Preserve／Flate；选定 R6 user／owner | 错密码／权限、低版本、签名／恢复；前缀、ID／Encrypt、失败输出不退化 |
| 07 预算 | 1／100／1000 组和表达式／段规模基线 | 恰好不足、算术溢出、drop 释放、同池失败重试；tracked 与 RSS 分开 |

组合按可适用性展开，不能把每列全做机械笛卡尔积；V13-00 给每个必选场景唯一 ID 和断言。既有图层选择、标记文本、结构迁移、共享资源编辑和 v0.11／v0.12 保存安全门禁构成联合复验集合，之后同一冻结源码完成完整工作区。

## 开工前剩余决策

- 确定公开 API 的构造方式、预算入口、配置目标类型，以及 owned Document 的转发。
- 确定新段允许的操作符和内容状态验证器，现有底层 builder 不能直接当成可信输入。
- 固定新 API 组／配置／表达式／工作量上限，与 Limits 相交；不能只写“有界”而不落实数值和边界测试。
- 确认两类外部生产者的实际能力，冻结合成配方与来源。pikepdf 和 qpdf 共用后端；MuPDF 重写只能证明重写输入，不冒充独立的原始图层生成器。
- 区分 PDF 1.7 与 2.0 的生成约束和现有兼容读取；依据[第 8 章勘误](https://pdf-issues.pdfa.org/32000-2-2020/clause08.html)核对绑定与配置，不能直接把读取器所有容错写成默认输出。

风险最高的是 04／05 的内容状态和共享隔离，其次是 02 的配置更新保留；01／03 可以先交付定向闭环。不开启迁移／删除／扁平化，也不重做字体或文档元数据。完成 V13-00 后即可按 A、B、C 分阶段实施，当前不运行完整回归或提交／推送。
