# v0.6 内容流与图像基础实施计划

计划日期：2026-10-14；验收日期：2026-10-15。状态：最终源码 `0f647af` 的 A/B/C 限定范围已完成本地工程验收，完整回归 61 组、1,165 项通过，0 失败/忽略，独立像素/结构及逐页视觉复核通过。范围见 [输入矩阵](v0.6-matrix.md)，实测及任务追踪见 [验收记录](v0.6-acceptance.md)。承接 [PDF 标准基础能力路线](../pdf-standard-roadmap.md)，不改变 v0.5 已验收边界；未推送、打标签或发布。

## 目标和阶段

让标准图像对象和内联图像能够被可靠解释、提取、保存和限定编辑；补齐 JPX/JBIG2 进程内解码入口。上层可据此接入 OCR，但本版不做识别、表格推断或自动排版。

| 阶段 | 必选范围 | 退出条件 |
|---|---|---|
| V06-A | 内联图像、既有过滤器/图像参数、来源与读写编辑 | 不误判 EI，前后操作保留，独立像素/位置检查、失败回滚 |
| V06-B | JPX 进程内解码和页面闭环 | 冻结容器/颜色/位深/透明度矩阵，独立像素/渲染、解码预算 |
| V06-C | JBIG2 进程内解码和 Globals 关系 | 页/全局数据组合、独立图像/渲染、保存重开与限额负例 |

本期不要求 JPX/JBIG2 编码器，不承诺所有图像/颜色/透明度组合。颜色管理、完整透明组和复杂字体分别在后续版推进。后端关闭或组合未支持时必须给出明确错误，不能输出空白图像视为成功。

不做 OCR、无标记表格/段落识别、自动排版，以及已确认暂缓的 3D、多媒体、脚本/XFA 执行、专业印刷、线性化、在线信任服务和全格式字体子集器。这里的图像编辑不等于安全擦除；增量输出仍可能保留原字节。

## 每阶段具体交付

### A 内联图像

1. 解析 BI 字典、ID 数据到 EI 结束的完整内容项，保留原始字节、字典/数据范围和流来源；支持的缩写、过滤器链和跨 Contents 边界规则逐项冻结。
2. 首批矩阵复用无过滤器、ASCIIHex/ASCII85、Flate/Predictor、RunLength、LZW、DCT/CCITT 中实际可用的既有路径；DeviceGray/RGB、Indexed 和 1 位 stencil 按既有能力补验。不把所有过滤器与颜色空间的任意组合都列为自动支持。
3. 页和已支持非 Group Form 内联图像进入解释/渲染/提取事件，并保留矩阵、裁剪、原操作位置及文档/页/修订身份。不能伪造一个 XObject 名称代表内联来源。
4. 提供内联图像的原始数据和解码结果访问、显式构建/写入、按来源替换和删除；未修改内容尽量原样保留，替换不得改变邻接文字/路径或其他调用。

此阶段先把已有普通图像能力接通到内联对象，不等待 JPX/JBIG2 后端才开始。BI/ID/EI 作为一个完整内容项的计数及兼容适配方案由 V06-02 明确，不能破坏旧文字/路径来源索引。

### B JPXDecode

1. 选定并接入进程内后端；至少冻结一组可独立验证的无损灰度/RGB 基础样本及有损样本。JP2/原始 codestream、其他组件/位深/Alpha 组合是否开放由矩阵决定，不能用少量样本泛化。
2. 解码结果不仅是 Vec 字节：需要明确尺寸、组件、采样精度、颜色和 Alpha 信息，并按适用规范处理 PDF 字典与图像头信息的关系。旧过滤器 API 的兼容适配也要说明。
3. 接通读取、绘制、提取、保留编码后保存重开；替换可使用已有 RGB/RGBA/JPEG 写出路径，不开发 JPEG 2000 编码器。

### C JBIG2Decode

1. 选定并接入进程内后端，覆盖无 Globals 和带共享 Globals 的单色基础样本；其他段/组织方式先列明支持或拒绝。
2. Globals 解析、解码、页数据和保留结果共用操作预算，结合现有解码深度/循环检查；不得重复发布原生裸指针或让输出依赖已经释放的源。
3. 接通单色图片的读取、绘制、提取、原编码保存及跨文档复制/导入的 Globals 引用迁移；替换用已有合法图像编码，不开发 JBIG2 编码器。

以上保留开工能力契约；最终 API 见 [图像指南](../image-codecs.md)。每个阶段都包含单元/集成、预算、错误与独立工具检查，不能只完成过滤器函数便收口。

## 首先解决的架构问题

先设计“保留原始编码及来源的图像内容项”，再接解码器。当前普通 Operator/SourceOperation 和命名 XObject 来源不足以直接容纳内联二进制数据；图像模型、解析位置、绘制事件和编辑认证必须一起衔接。

解码侧先明确输出元信息及字节所有权。复用原始/解码流状态，声明后端输入、临时空间和保留输出的预算/生命周期；不能把图片先无界解码，再事后检查尺寸。新接口保持现有修改权限、签后编辑保护及源快照失效契约。

## 必选验收场景

- 字节中含 EI、ID、空白和注释样式的图像数据不截断；图像前后文字/路径操作索引、数值和字节边界准确。
- 内联与 Image XObject 在同等参数下得到相同像素及绘制几何；资源查找覆盖页和声明支持的非 Group Form 作用域。
- 旋转、缩放、裁剪、解码参数、蒙版和透明度组合按冻结矩阵逐项验证，未知组合明确拒绝。
- 原样保存保留未修改编码；显式替换/删除不改变邻接内容和未选调用；保存重开后能独立读取、解码和渲染。
- Globals、资源和对象引用在复制/导入后属于目标文档；删除或释放源文档不破坏结果。
- R6 加密内容流中的内联图像只随外层内容流解密一次；新构建/编辑入口不得绕过权限或签后编辑保护。本版不因此开放加密增量保存或已签来源编辑。
- 错误/截断输入、预算不足、输出失败和编辑失败不留下部分更新；释放后重试可成功。
- 至少两类独立生产者的来源合法样本，配套合成边界案例；不得只用本库输出作互操作依据。
- 独立解码器/MuPDF 的像素与位置、qpdf/pikepdf 的结构、本库读回和逐页视觉复核形成证据。先登记无损逐像素、有损容差及来源，不能用截图掩盖组件或 Alpha 错误。
- 如后端缺少可验证的工作量/内存约束，限定暴露接口和输入范围并完成审查，不默认作为任意不可信文件的安全解码服务。
