# v0.3 字体与兼容性：实施派单与收口边界

制定日期：2026-10-13。状态：**冻结子范围已完成本地工程验收**，证据见[支持矩阵](v0.3-support.md)与[验收记录](v0.3-acceptance.md)。v0.1/v0.2 的已验收范围不因本文扩大；未选中的子集、竖排与兼容性代码仍按候选/实验能力处理。每项勾选依据本版同一源码候选的证据，不将 `TODO.md` 的历史专项结果直接算作本版通过。

## 一句话目标

在**固定、可复现的字体和文件矩阵**内，让 PDF 的字符码、Unicode、字形、位置及画面结果可解释、可对照；超出矩阵时明确报告替代、缺字或不支持，而不是静默给出貌似成功的结果。不承诺任意 PDF 或任意字体兼容。

## 冻结的必选范围

| 范围 | 本版必须证明 | 不随本版扩张 |
|---|---|---|
| 内置西文字体 | 已验收 Helvetica/WinAnsi 保持；增加至少一个不同 Core 14 家族及明确编码/字宽样本，检查提取、位置和渲染。未嵌入字体的替代结果必须可诊断。 | 操作系统字体发现、按名称自动下载字体、任意缺失字体的精确还原。 |
| 静态 TrueType/CID | 用来源和许可明确的静态字体，固定横排 Identity-H 与竖排 Identity-V 各一组；核对 ToUnicode、CID/GID、W/W2、方向、字形位置及保存重开。 | 可变字体实例化、CFF/Type3 全覆盖、复杂 shaping/bidi、自动回退或段落排版。 |
| 字体子集编辑 | 固定静态 glyf TrueType 的已有字符及新增字符各一组；至少一次共享页或重复 Form 调用的隔离/回滚。独立抽取嵌入字体核对字形闭包、映射、度量和校验和。 | 任意字体自动子集、跨所有嵌套深度、重排版；不因旧实验入口存在而扩大 v0.2 正式编辑范围。 |
| 外部文件兼容 | 除既有受控 fixture 外，登记**至少两份可合法保存和复验的真实公开文档**，覆盖不同生产者，且至少一份含中文/嵌入字体；逐页记录解析、提取、渲染和保存重开结果。 | 私人业务 PDF、无许可样本、用自编测试页冒充真实文档；样本通过不推断普遍兼容。 |
| 故障语义 | 所选矩阵内不允许静默换字、漏字形、错误 Unicode、跨页污染或失败后局部修改；所选矩阵外明确诊断或拒绝，并公布已知差异。 | 把不支持格式转换为空白页、把替代渲染称为精确渲染。 |

正式支持的**具体字体文件哈希、字符/编码样本、外部 PDF 名单、页数和预期结果**须在 V03-01 盘点时写入同目录的支持矩阵草案后冻结。上表的最低类别和数量不能缩水；若合法样本或能力无法满足，保持该项未完成，不能仅修改表述宣布收口。当前历史 Arial 等本机字体样本可用于开发，但来源/再分发许可未核清前不作为必须可复验的正式样本。

## 派单与完成定义

- [x] **V03-01 盘点与样本冻结（先行）**：按字体格式、PDF 编码、ToUnicode、字形映射、横/竖排、提取和 Skia 绘制列出现有代码与测试；逐项标候选/实验/未支持。登记上述静态字体和真实文档的来源、许可、哈希、预期页/文字/画面；冻结具体支持矩阵与可接受差异。关联 P3-05、P4-02、P4-07。
- [x] **V03-02 字体来源与替代语义**：审查内置字体命中、未嵌入字体回退、缺失程序和字形名绘制路径；使精确字体、显式替代和无法绘制在 API/诊断中可区分，所选样本不静默跳过字形。保留 `font-data` 独立 crate；本期不引入系统字体自动发现。关联 P4-02、P4-07。
- [x] **V03-03 静态 TrueType 横/竖排**：在冻结字体上核对 Identity-H/V、W/W2、ToUnicode、CID/GID、绘制方向与坐标；修复矩阵内差异，并对缺字/不支持表给出确定性失败。只把通过独立检查的子范围转为正式支持。关联 P4-02。
- [x] **V03-04 子集与编辑闭环**：固定字体的新增字符、复合字形、映射更新、共享隔离、预算拒绝与事务回滚；保存重开后独立抽取字体验证源 GID/轮廓/度量/表校验和及 Unicode 文本，视觉核对。P3-05 原父任务只有其全部原始条件满足才勾选；本版只关闭冻结子范围。
- [x] **V03-05 外部文件差异清单**：逐份运行严格/兼容解析、文字/位置提取、图片或字体诊断、全页渲染与保存重开；和独立工具结果对比。每个差异标为本版修复、明确不支持或已知视觉差异；矩阵内静默错误必须修复，不能作为普通已知限制放行。关联 P4-06、P4-07 的限定子范围。
- [x] **V03-06 数据构建可复现性**：将 `font-data` 生成源码写回 `src` 的构建方式迁至构建输出或等效的只读输入流程；验证干净检出、离线构建、原始数据哈希/许可声明、打包清单及既有 CMap 行为不变。静态数据体积优化可测量后做，不以具体二进制大小作为退出条件。
- [x] **V03-07 候选门禁与支持发布**：在同一干净候选提交上运行锁定依赖完整回归、v0.1/v0.2 回归、字体/样本专项、qpdf/MuPDF 等独立结构和文本检查及全部选定页面的视觉对照；归档工具版本、命令、产物、人工复核和失败记录。更新支持矩阵、README 限制、CHANGELOG 与验收报告后才能声明 v0.3 工程完成。

执行顺序：V03-01 → V03-02/03/04/06（按实际缺口小步完成）→ V03-05 → V03-07。V03-05 可在开发中持续跑，但最终差异清单以冻结候选为准。每张单必须有对应测试或独立证据、明确拒绝路径与回归影响；已有测试足够时不为数量重复造测试。

## 明确不做与升级规则

本版不做完整 Type3/CFF/可变字体、所有编码和竖排字体、Pattern/Shading/Lab/ICC、完整透明组和软蒙版、JPX/JBIG2 新解码后端、通用损坏文件恢复、OCR、PDF/A/UA、自动排版、真正脱敏、加密/签名或 fuzz。P4-01 内联图片及 P4-03～05 的完整任务不作为本版退出条件；若冻结样本恰好依赖其中某项，要么补一个严格限定且独立验收的子范围，要么更换合法样本并记录原因，不默默扩大整个版本。

无远端 CI 时只声明实际本地平台和工具结果。工程验收、提交/推送、版本标签、crate 发布是不同动作；后两者需另行确认。未选中的旧实验 API 继续存在，不因此取得正式兼容承诺。
