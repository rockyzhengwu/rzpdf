# v0.14 源码盘点与范围选择

2026-10-19，基线为已收口的 v0.13 提交 `6be4cc3`。本轮仅完成静态盘点和实施计划，没有实现或验收新能力。建议 v0.14 聚焦 PDF 2.0 文档级和页面级关联文件 AF；详细任务与验收见[版本计划](v0.14.md)。

## 候选方向

| 方向 | 基线实际能力 | 取舍 |
|---|---|---|
| 关联文件 AF | EmbeddedFiles 附件、FileAttachment、AF 原样保留；没有 AF 语义读写入口 | 本版：Catalog／page 的读取、创建、绑定、解除和选定页面操作闭环 |
| 图层页面迁移 | v0.13 已有创建／配置／局部绑定；迁移仍有保护性拒绝 | 后续独立版本；需处理默认／替代配置合并、OCMD 图和引用映射，不能直接移除 guard |
| CFF／Type1 文字裁剪轮廓 | 已有部分字体读取和绘制，裁剪路径仍限定 TrueType | 后续字体专题；不把绘制支持当成轮廓提取支持 |
| XMP 语义编辑 | 原始 packet 和选定 Info 编辑；无 XML schema 同步 | 暂不引入 XML 重写器；保留现有原始替换契约 |
| 大规模图层性能 | v0.13 基线揭示逐成员重新读取模型的重复成本 | 优化候选，不作为 AF 的隐含依赖；若单独优化，必须补来源与额度回归 |
| 更广颜色、恢复或安全组合 | 已有各版限定矩阵和明确拒绝 | 不在本版混入印刷、恢复写回、旧加密或加密签名专题 |

AF 描述 PDF 对象与文件之间的显式关系，属于核心文件格式能力。读取 CSV／XML 附件的业务含义、推断表格、运行附件程序属于应用层。

## 最重要的边界

关系由 Filespec 上的 AFRelationship 表达，而不是由文件名或 MIME 推断。同一 Filespec 被多个 owner 使用时，其关系值也被共享；修改某一绑定不得顺带改变其他 owner。首版采用创建新 Filespec／显式关联和解除，不提供原位修改共享 Filespec 的关系或载荷。

读取只列举调用者明确选择的 Catalog／page AF，不递归寻找全文件所有“附件”。列表不自动解码 payload；提取另走受预算限制的接口。未知关系名可在只读投影中保留，不能映射成 Unspecified 后写回。

仅有 EmbeddedFiles 名称不代表存在 AF；仅有 AF 也不要求补入名称树。移除一个名称、一个 FileAttachment 批注或一个 AF 链接，都不自动删除其他关系、Filespec、payload 或增量历史。

## 开工前必须解决

V14-00 必须冻结公开签名、关系枚举、直接／间接输入处理、F／UF／EF 规则、MIME 语法、数值限额、授权和独立样本。当前计划不是已发布 API，也不是这一步已完成。

标准核对入口为 ISO 32000-2:2020 7.11 与 14.13，结合 [第 7 章勘误](https://pdf-issues.pdfa.org/32000-2-2020/clause07.html)和[第 14 章勘误](https://pdf-issues.pdfa.org/32000-2-2020/clause14.html)。勘误明确 AF 所指 Filespec 需要 AFRelationship，关联文件的嵌入流需要 MIME Subtype。完整规范和适用表项仍须在 V14-00 登记；勘误网页不是完整规范替代品。

首版选择 PDF 2.0 生成，不处理 PDF/A-3 等旧版本扩展配置。旧文件中原样保留的数据不因本版被自动升级或追认符合性。特别是内容段 AF／MCAF 与 v0.13 的 OC 绑定并非同一种语法，本版不复用 OC 标签冒充 AF。
