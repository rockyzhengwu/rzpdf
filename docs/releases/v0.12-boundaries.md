# v0.12 冻结边界与接口决策

冻结日期：2026-10-18，接口补充及收口：2026-10-19，实现基线 `a5c7f9e`。V12-00～13 已按本页接口与边界完成限定本地验收；证据见[验收记录](v0.12-acceptance.md)，任务对应见[计划](v0.12.md)。不因整版收口扩大本页支持 profile 或未验证平台的宣称。

## 输出组合

| 工作流 | 本版目标 | 当前子阶段 |
|---|---|---|
| 默认全量 | 传统 xref、独立对象，保持原接口行为 | 保持现有实现 |
| 未加密全量 | 新 xref stream、不打包对象 | V12-01／02 |
| 全量对象流 | xref stream + ObjStm；未加密和 R6 分别验证 | 未加密 V12-03；R6 V12-04 |
| R6 无对象流的新布局 | 按现有版本、认证、权限和保护保留／更改规则 | V12-04，显式组合入口，默认保留保护 |
| unsigned 增量 | 传统及 xref stream，未加密与 authenticated R6，保留原前缀 | V12-05，独立 IncrementalSaveLayout，默认仍为 Classic |
| 签名／受控更新 | 沿用 v0.11 私有计划和原布局 | 不接收通用新布局选项 |

新建 ObjStm 仅纳入全量，增量继续把修改成员作为独立对象追加。hybrid／线性化输出、新签名布局、旧加密 handler、公钥加密和任意签后重写不纳入。不因能读取某种输入就自动开放其任意输出组合。

## 公共 API 与兼容

不增加 `SaveOptions` 或 `IncrementalSaveOptions` 的必填字段，保留已有穷尽 struct literal。`save_options::SaveLayout` 标记 non_exhaustive，提供 Classic（默认）、XrefStream 和 XrefStreamWithObjectStreams；新增变体不改变 XrefStream 独立对象输出的含义。

`PdfDocument`（包括 owned Document 的既有转发）新增：

- `save_to_bytes_with_layout(options, layout)`。
- `save_with_layout_and_budget(options, layout, budget)`，返回保留额度的 BudgetedBytes。
- `save_to_writer_with_layout(writer, options, layout)`。
- `save_to_file_with_layout(path, options, layout)`。

V12-04 新增显式组合入口 `save_to_bytes_with_layout_and_security(options, layout, policy)`、`save_with_layout_and_security_and_budget(options, layout, policy, budget)`，以及对应 `save_to_writer_with_layout_and_security`／`save_to_file_with_layout_and_security`。原布局入口等同 policy Preserve，旧安全入口仍选 Classic；不新增 options 必填字段，不传播到签名或增量接口。

新入口复用原有来源、权限、版本、序列化和原子文件策略；不让调用者传“已验证”布尔值。普通 Vec 返回后不保留 operation reservation；writer 完成序列化后再输出，I/O 仍可能留下调用者缓冲区的部分内容。文件接口沿用原有原子替换，不等同于示例程序的 create-new 策略。

现有 public ObjectInfo／解析接口不改签名。新增 writer 内部类型化记录是从源与 overlay 生成的一次性输出计划，不是第二份可修改对象库；Compressed 的成员索引不会作为 generation。跨 reader 的公共模型迁移不作为使用新布局的前置条件。

## V12-02 编码与资源边界

- 仅未加密、未签来源；无签名草稿按既有源标记检查。要求有效 PDF 1.5+；更低版本只接受明确的版本升级，不静默改 header。新布局拒绝保留 Linearized 声明，不依赖排序使旧声明失活；本阶段不迁移提示表或校正线性化偏移。
- 新 xref stream 的自身对象号高于来源 Size 保留范围、源 xref 记录及当前对象号，不进入 overlay，不改变 stamp／commit_revision。已有悬空引用不得意外指向这个新结构对象。
- 初版使用未压缩的 `/W [1 8 4]`、`/Index [0 Size]`，处理孔洞／删除的自由链、普通对象 generation 和自身 type 1 记录。完整范围输出受 Size 上限约束，不宣称已实现稀疏 Index 压缩优化；未来增量另行编码稀疏区间。
- 64 位偏移采用栈上编码单元测试，不生成巨大实际文件。generation 不超过 65535；内部 type 2 使用独立容器号与 32 位索引。V12-02 不打包，V12-03 通过单独变体生成 ObjStm。
- Size 与条目数不得超过现有 `max_objects`，载荷 `13 * Size` 同时受 `max_raw_stream_bytes`、`max_decoded_bytes` 限制；算术溢出在分配前失败。对象、输出缓冲、记录数组和 trailer 构造共用调用者 OperationBudget；不承诺原生／遗留全部分配或 RSS 上限。
- `StreamCompression::FlateUnencoded` 只作用于原有对象准备路径，不隐式改变新 xref stream 的编码。新 trailer 清除 Prev／XRefStm 和旧结构／过滤／外部流字段，重新建立 Type、Size、W、Index、Length；业务未知键按原规则保留。
- 旧结构容器仍沿用当前全量保存语义；V12-02 不宣称执行了对象流重打包、Extends 迁移或历史数据清除。重布局容器关系的完整处理属于 V12-03／06。

## 对象流与恢复限额

ObjStm 首个 profile 采用每组最多 100 对象、未压缩成员／索引合计最多 1 MiB，并与 parser／operation 限额相交；单个不适合打包的对象保持独立，禁止对象不入组。这是本库的分组策略，不是标准统一上限。实际编码、解码互操作及性能由 V12-03／10 验证。

### V12-03 对象流处置

`XrefStreamWithObjectStreams` 仅开放未加密、未签、有效 PDF 1.5+ 全量输出。计数前计算序列化长度，不先构造超大候选缓冲；分组同时包含索引字节、分隔符和成员正文。Preserve 生成原始 ObjStm，FlateUnencoded 试压缩后仅在体积减小且符合原始流限额时使用；有界试压缩及重分配重叠计入共享 operation 预算，失败不吞掉真实 ResourceLimit。

stream、非零 generation、Catalog／Root、Encrypt、间接 Length 链、引用对象，以及直接或嵌套的签名／占位／结构声明字典不入组。新容器保留业务对象 ID／值，使用临时 ID 和 type 2 索引，不进入 overlay；最终再次检查全部保留对象／trailer 引用，防止后分配容器绑定原有悬空引用。全量重开修改的压缩成员可以重新打包；既有传统增量仍将修改成员独立追加，不新建 ObjStm。

只替换字段语义已知且没有普通对象／保留 trailer 引用的旧 XRef／ObjStm；旧号记 free，不按可达性回收业务对象。ObjStm 的 Extends、任一旧容器未知字段或活跃外部容器引用均明确拒绝；不宣称迁移语义集合。Classic 和不打包的 XrefStream 仍沿用原处置，不将这一保守拒绝新增到旧模式。V12-06 的保留关系清单见下方；性能记录仍归 V12-10，不能以互操作结果替代。

恢复首个 profile 限完整输入最多 64 MiB、候选对象最多 `min(max_objects, 100000)`。扫描／探测步骤累计上限为 `16 * input_bytes + 1024`（检查溢出），单次报告最多 1024 事件／1 MiB tracked 字节池，并与既有 token／深度／payload／operation 限额相交，V12-07／08 已实现精确边界与失败重试测试；歧义或超额明确拒绝，不只解析输入前缀就声称成功。这些是保守产品上限，不能由固定规模实测推导任意输入的性能保证。

## V12-04 全量 R6 新布局

沿用现有 Standard V=5／R=6 handler，不增加旧算法。未签来源先完成原始／历史签名检查和认证；user／owner 可按原权限保留，移除／替换既有保护须 owner。保留 R6 需要 PDF 2.0 或 PDF 1.7 ADBE level 8；新增／重新设置 R6 按既有契约生成 PDF 2.0，显式指定低版本或降级仍拒绝。R2～R5、公钥、加密签名不开放。

成员以明文序列化和分组，可选 Flate 后，ObjStm payload 按默认流 crypt filter 处理一次；不对成员逐个加密。含安全字典／占位标记的对象保持独立并走原 handler 检查，不能因打包绕过拒绝。默认字符串和流 crypt filter 不同，含字符串对象保持独立。XRef 和 active Encrypt 不加密；Catalog／Encrypt／stream 不入 ObjStm。metadata=false 与 Crypt／Identity 保留原例外，未加密不代表未压缩。

新流布局复用已有间接 Encrypt 的 ID 和 generation，并从已认证 handler 写出真实字典，不采信可变 overlay 的降保护请求。原 Encrypt 是直接字典或来源无保护时，临时 Encrypt 与 XRef／ObjStm 一样在 Size／源记录高水位外分配，并检查悬空引用别名。新 trailer 只允许计划生成的 Encrypt 引用通过，不放宽任意业务引用。Classic 保留旧分配行为。Remove 可能将旧间接 Encrypt 作为普通对象保留；不承诺历史／私有数据擦除。

分组除 100 成员／1 MiB 和原限额外，对默认 AES 流预留 IV／padding 的原始流空间；压缩及密文缓冲均计入同一 OperationBudget，真实 ResourceLimit／RNG／host I/O 错误明确返回，可重试。文件使用原子替换，示例驱动使用 create-new；凭证仅从主机环境读取，不放在 argv 或日志，样本只用公开合成凭证。

## V12-05 增量布局接口

owned `Document` 新增 non_exhaustive `IncrementalSaveLayout`（Classic 默认／XrefStream）及 `save_incremental_to_bytes_with_layout(options, layout)`、`save_incremental_with_layout_and_budget(options, layout, budget)`、`save_incremental_to_writer_with_layout(writer, options, layout)`、`save_incremental_to_file_with_layout(path, options, layout)`。不向 IncrementalSaveOptions 增加字段，不把全量 ObjStm 变体用于增量，也不让签名／受控私有入口接收新布局。

来源仍须严格解析的不可变 owned bytes，未签、非线性化；新建、file／reader 和 Compatible 输入拒绝。真实流式追加要求有效 PDF 1.5+，不静默升级；无操作／回滚精确返回原字节，无新结构 ID 或随机数请求，低版本无操作亦如此。未加密沿用旧 ID 契约；R6 保留 Encrypt（包括直接字典）、首 ID 和权限，更新第二 ID。仅 XRef 内与已认证 handler 完全相等的直接 Encrypt 字典免于 Perms 签名误判，其余标记和原始／历史签名检查不放宽。

新尾部使用未加密、未压缩 W [1 8 4]，Index 仅覆盖改变对象、已知 free、0 与自身记录的连续区间；未改条目从 Prev 继承。Prev 指最后物理 section，不能误指 hybrid 的同 revision 补充流；不保留旧 XRefStm。修改的压缩成员独立追加、逻辑 generation 0，删除增加 generation 至 65535 饱和；不新建 ObjStm，不复用来源保留号。新结构 ID 位于 Size、源 xref 和当前号之外并拒绝悬空引用别名；只存在于输出，不改变 overlay、句柄、stamp、提交计数或分配器。

Size 仍受 max_objects 限制，稀疏载荷只按所写条目数乘 13，同时受 raw／decoded 限额；Index、记录、字典和输出接入 operation 预算。64 位偏移复用共享类型化编码；溢出、错误 generation、源结构容器编辑、活对象引用已删除对象均拒绝。恰好限额、低一字节、失败释放和充足额度重试有专项测试。writer／file 沿用序列化先行与原子替换契约；原前缀保留不等于脱敏或安全擦除。

## V12-06 保留与页面关系

完整的按操作边界见[对象与关系保留矩阵](../object-preservation.md)。普通私有字段／对象、共享循环、trailer 根、Info、原始 XMP、EmbeddedFiles 和 AF／AFRelationship 的表示保留分别覆盖全量三布局、两种增量，以及未加密／R6；这不新增通用 AF／私有 schema／XML 编辑器，不宣称 PDF/A 或 PDF/UA 合规。

内部 `document/preservation.rs` 共用 trailer 业务根判定，替代 writer 私有副本。页面删除后验检查包含 Catalog、Info 和私有 trailer 根；任何仍活跃的未知引用指向被删页均拒绝并回滚，不由 Retarget 猜测私有字段含义。普通历史索引容器不是业务根；若业务图显式到达 XRef／ObjStm，删除亦拒绝，因为不能证明原始载荷的关系仍可维护。

跨文档页／资源导入的通用 ID map 不重写结构容器载荷，故显式拒绝 XRef／ObjStm（含间接 Type），不把原始 member ID／文件偏移作为普通数据盲拷贝。普通页可达扩展、AF 和 page Metadata 继续沿一份映射保留循环／共享；非选择页引用拒绝。Catalog 的 Info／XMP／附件／私有根不随页自动合并。未带结构的同文档复制可共享普通间接数据，不承诺私有所有权推断。

旧 XRef 未知字段的保守 repack 拒绝保持，不因为该字段也出现在 trailer 就视为已理解。低层对象构建接口、结构／OCG／表单导航和安全边界不扩大。删除扫描仍使用既有节点／深度限额，导入沿用累积 token／payload 限额；不宣称全部页面图分配已接入单一 operation 预算或 RSS 上限。失败回滚保持序列化状态、提交计数和分配器；旧 stamp 可失效，调用者需重新取快照。

## 恢复来源

V12-07 新增 `parser::diagnostic::{StructureDiagnostic, StructureReason, ReadProvenance}` 与 `PdfDocument::structure_diagnostics()`／`read_provenance()`（owned Document 沿用转发）。来源取自不可变 parser／construction 状态，不采信 trailer 或 overlay。文件报告与页面内容 diagnostics 分离，懒读取发现的事件随后可取新快照；记录偏移、已知对象 ID 和固定原因，不保存输入控制的消息。1024 个事件／1 MiB tracked 字节池与 max_operation_bytes 相交，重复事件去重，容量和增长重叠计费，超额返回 ResourceLimit，不静默截断。ParseOptions／Limits 不增加字段。

V12-08 新增独立 `document::recovery::RecoveredDocument`、`RecoveryLimits` 与 `from_bytes`／`from_bytes_with_options`／`from_bytes_with_budget`。恢复类型不 Deref 为 Document，不暴露 ctx／PdfPage／内部文档或转换；只有分离的 geometry／DisplayList、Info／raw metadata、诊断与来源读取。没有任何编辑、全量／增量保存、签署或受控更新入口，编译失败 doctest 验证能力边界。恢复始终使用 Strict 对象语法，不能由调用方 mode 放宽。

扫描按词法顺序解析完整间接对象，只接受可验证的直接 Length；字符串／stream 内容中的伪对象和 trailer 不作为索引候选。允许 startxref 错误、完全缺失传统表或仍限于数字／n／f token 的损坏表；保留一个明确 trailer、有效 Size、间接 Catalog Root 和单一最终 startxref／EOF。末尾最多 64 字节、非首部 header／提前 EOF 标记、重复对象或键、未知间隙、间接 Type、签名／安全标记及外部流拒绝。64 MiB／100000／16*n+1024 均可降低而不可提高；输入容量、保守索引增长及 budget-aware 对象解析计入共享预算，失败释放并可在同池重试。下游解释仍沿用原限额，不把扫描步骤称为渲染工作预算或 RSS 保证。使用与限制见[指南](../file-recovery.md)。

首个索引重建入口显式启用，只处理仍有明确 trailer Root 的简单未加密、单 revision、非 ObjStm 来源；不能可靠跳过 stream、分辨对象或选择 Root 时拒绝。加密、签名、hybrid、多 revision、压缩对象和无 trailer 猜测恢复不开放。

重建来源只读，不能经由 mode、trailer、overlay 或重新包装解锁保存／增量／签署／受控修改。现有 Compatible 的局部容错与全量保存不被偷偷改成该新恢复模式；两者报告和能力分别标记。只读恢复与自动修复写回明确分开，后者不在本版。

## 样本与验收登记

跨版本的标准／入口／正负断言／边界／独立工具映射见[覆盖索引](../pdf-standard-coverage.md)。固定规模、分组／稀疏编号／三轮追加／恢复扫描和 tracked/RSS 分列见[性能基线](v0.12-performance.md)，默认兼容与真实平台状态见[迁移与平台记录](v0.12-platform.md)。这些索引不把旧版历史外部门禁冒称本轮重跑，也不把测试总数转换为标准覆盖率。

V12-02 用 pikepdf 生成含共享循环私有对象、两页绘图、Info／XMP 和附件的输入，分别经 qpdf 对象流、MuPDF 重写、新 xref stream 和显式 hybrid 构造得到五种输入。每种输入做 Preserve／Flate 两种输出，共十个结构／对象投影案例；MuPDF 对两页比较，共二十组像素对照。外部工具来源和构造输入来源分别记录，不将 pikepdf 与其 qpdf 后端冒称两个独立实现。

本版另覆盖 Unicode／多 Widget 签名工作流、结构／OCG 原样保留、保护身份及多轮历史的选定样本；来源、生成命令、许可、版本、hash 和预期登记在配方、manifest 与覆盖索引中，不宣称所有组合均支持。最终完整工作区、四组 v0.11 安全门禁和新增独立／预算／视觉门禁已执行，结果见验收记录；阶段专项未冒充整版全量。

标准参考：[ISO 32000 第 7 章更正](https://pdf-issues.pdfa.org/32000-2-2020/clause07.html)及[qpdf 独立实现说明](https://qpdf.readthedocs.io/en/11.9/object-streams.html)。具体布局策略为本库选择；不自动发布、提交或推送，不运行 fuzz，不安装 Poppler。
