### Candidate failures and corrections

Source-signature preflight exposed an existing ObjectInfo::object_id conversion
that treated a compressed object's stream index as its generation. Three A
object-stream cases failed before the correction. Compressed IDs now use
generation zero, with a direct assertion and full A recheck scheduled.
Signature dictionary value parsing originally used an exact-end-boundary reader
and rejected legitimate following keys; it now uses the budgeted single-object
reader. The budgeted page accessor uses its existing into_parts API rather than
accessing a private field. A new permission test initially used a below-minimum
widget rectangle and got a geometry error before permission checking; its
fixture now uses valid geometry without weakening the permission assertion.
All corrections are in `25fe579`; final Rust results must be recorded below.

### Failures found and handled

First tests exposed existing multi-subsection parsing that failed to advance to
the next subsection, and a strict object-zero rule that incorrectly prohibited
nonempty free chains. Both were fixed with dedicated positive/negative tests.
A synthetic fixture initially lacked the required binary header comment; the
fixture was corrected without weakening header validation.

qpdf-generated compact xref streams use reserved object zero `(0,0,0)`. The
parser normalizes only that sentinel; malformed generations remain rejected.
Historical xref-stream Info references are no longer treated as live roots when
checking deletion; raw structural-stream edits are explicitly rejected.

qpdf CLI 11.2 still exits 3 when checking deletion of a compressed object. Its
[v11.2 implementation](https://github.com/qpdf/qpdf/blob/v11.2.0/libqpdf/QPDF.cc)
looks up removed object-stream members with a map insertion. The
[current implementation](https://github.com/qpdf/qpdf/blob/main/libqpdf/QPDF_objects.cc)
uses a non-inserting find. Isolated libqpdf 12.2 checks the same output with
recovery disabled, zero warnings, and resolves the deleted object to null.
The gate records only the exact known legacy diagnostic; arbitrary warnings or
failures remain errors. This is not recorded as a successful qpdf 11.2 check.

Latest pikepdf 10.17 source build against the system's old qpdf headers failed.
The binary-only pikepdf 9.11 wheel provided libqpdf 12.2 locally under tmp/pdfs;
system Homebrew packages and security settings were not changed. Local example
executables received ad-hoc signing during verification; no source/credentials
or distribution signature was involved.
