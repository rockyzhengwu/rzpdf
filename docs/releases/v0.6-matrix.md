## 标准与复用路径

依据 ISO 32000-2:2020 的内容流（7.8）、过滤器（7.4，特别是 7.4.7 JBIG2 和 7.4.9 JPX）、图像（8.9，特别是 8.9.7 内联图像）、Form（8.10）和安全处理器（7.6）。内联缩写优先级、ID 数据分隔和 SMaskInData 关系遵循 [PDF Association 第 8 章勘误](https://pdf-issues.pdfa.org/32000-2-2020/clause08.html)。

| 单元 | v0.5 基线 | v0.6 路径 |
|---|---|---|
| 普通 Image XObject 与位打包、Indexed、Decode、stencil、部分 SMask | 已有 | `PdfImage` 共用，补图像组合测试 |
| 内联对象及来源 | BI 显式拒绝 | `InlineImage` 保存字典、编码载荷和数据范围；`Operator::inline_image` |
| Page 和已支持非 Group Form 绘制/提取 | XObject 已有 | 共用 `ImageObject` 与 Device，BI 操作来源，不伪造资源名 |
| 页/嵌套图像选择编辑 | 命名 Do 已有 | 接入内联删除、变换和替换；沿用快照及调用隔离 |
| JPX 与 JBIG2 | 解码入口占位 | 进程内后端、头预检、共用过滤器调度及预算 |
| 原编码保存及引用迁移 | 流与 GraphCopier 已有 | 不用解码像素覆盖原流；Globals 经普通引用图迁移 |
| R6 与签后保护 | v0.5 已验收 | 内联数据只随外层流解密；编辑入口保持既有保护 |

## 内联图像

BI/ID/EI 是一个完整内容项，操作索引与前后文字/路径一致。保留原始缩写字典；转入图像解释时规范化已定义缩写，短键优先。未知字典条目按规范忽略，但原样来源保留。

| 数据边界 | 默认输入范围 | 明确拒绝 |
|---|---|---|
| 无过滤器 | DeviceGray/RGB/CMYK、Indexed 及 1 位 stencil；精确行长度，既有 1/2/4/8/16 位样本路径 | 未过滤资源别名颜色空间，无法从原始字典计算组件数 |
| ASCIIHex/ASCII85 | 外层过滤器的编码结束符；可封装既有过滤器链 | 缺结束符、缺 EI |
| Flate | zlib stream end；DecodeParms/Predictor 复用既有路径 | 截断或超过输出限额 |
| RunLength | EOD 128，跳过完整 literal/repeat 块 | 截断块 |
| LZW | 9–12 位码与 EOD 257；EarlyChange 0/1 | 非法代码和未结束流 |
| JPEG DCT | JPEG 段长度、熵编码转义及 EOI | 无合法编码终止 |
| CCITT | ASCIIHex 包装的 Group 4；适配旧过滤器的展开样本，覆盖非整字节行宽、BlackIs1、Decode 和 stencil | 直接作为内联外层编码时不搜索 EI 猜测边界；ASCII85 包装未单独验收 |
| JPX、JBIG2 内联过滤器 | 仅 Image XObject 可用 | 即使 ASCII 包装，内联也按标准限制拒绝 |

内联内容项不得跨独立 Contents 流。标准允许的更广泛流拼接仍可保留在文档对象中，但这个解析/编辑接口显式拒绝；不将拼接分隔字节当作原图像数据。资源别名颜色空间在有明确编码边界的图像中按 Page/Form 作用域解析。内联 Device 颜色的 DefaultGray/RGB/CMYK 覆盖暂不开放，存在非 null 覆盖时明确拒绝，留待颜色管理版；不静默忽略覆盖。

## JPX

默认后端 [hayro-jpeg2000 0.4.1](https://github.com/LaurenzV/hayro)，仅 `std` feature，无 `image`/SIMD，无系统 subprocess。接受 JP2 或原始 J2K，单 tile、零原点、无符号 8 位、等采样 Gray/RGB；无损与有损均需独立样本。质量层最多 64，分解最多 8 级，tile parts 最多 64。

拒绝 palette/组件映射、Alpha/cdef、ICC、CMYK、编码样本非 8 位、分采样、ROI、组件编码覆盖、packed packet headers、多 codestream、多 tile 及未知 marker。SMaskInData 只接受 0；独立 SMask 保持既有受限路径。输出元信息包含尺寸、组件、位深和颜色空间，缺省 PDF ColorSpace 可从头推导；字典尺寸与颜色须匹配，BitsPerComponent 与 Decode 按 JPX 规范忽略，实际采样精度取图像头。无需 JPEG 2000 编码器，原编码保留，替换可走普通 RGB/RGBA/JPEG。

## JBIG2

默认后端 [hayro-jbig2 0.3.1](https://github.com/LaurenzV/hayro)，仅 `std` feature；传递依赖 hayro-ccitt 0.4.0，无生产 subprocess。接受嵌入式、已知段长度、单个非 striped 页，Generic/GenericRefinement、PatternDictionary/Halftone 和结束段；Globals 可携带有实际图像意义的共享 pattern 或 intermediate region，不用空 Globals 替代门禁。

拒绝符号字典和 text region：后端没有分配限额接口，其符号尺寸在压缩数据内部，无法通过现有头预检约束。这意味着常见 symbol-coded 扫描件尚不属于本版输入范围；原对象仍可保留/复制，但渲染会明确报未支持。完整文件组织、unknown-length/striped 页、扩展引用表、profile/custom table/extension 等也拒绝。最多 1024 段、256 patterns、每维 65535，实际像素、累计区域和 grid 工作量继续受 Limits 限制。

黑白输出是 PDF 的按行 MSB 打包样本（0 黑、1 白），不是后端内部“1 表示黑”的位图。Globals 按同一池解析与解码，持有到页解码结束；递归引用使用既有解码深度检查。复制/导入保留原页流及 Globals 引用并迁移到目标文档。

正向独立样本覆盖 GenericRegion 的 MMR/算术编码及共享 PatternDictionary/Halftone。GenericRefinement 和 Globals intermediate region 虽有实现入口，尚无本版固定正向互操作样本，因此保留为未验收，不将后端接受的所有段组合泛化为正式支持。

## 读写与编辑边界

| 对象 | 读取 / 解码 / 绘制 | 保存 / 导入 | 创建 / 修改 |
|---|---|---|---|
| 内联图像 | 按上述边界和颜色矩阵解释，保留来源 | 未修改字节保留，资源按已有图复制 | 显式构建；页级原内联替换、删除、变换；已支持非 Group Form 的选定调用删除/变换/转 XObject 替换 |
| JPX Image XObject | 已列出的 Gray/RGB 基线 | 保留原编码及字典，不重编码 | 不提供 JPX 编码器；使用已有 RGB/RGBA/JPEG 替换 |
| JBIG2 Image XObject | 已列出的 Generic/Pattern-Halftone 基线 | 保留编码和共享 Globals，跨文档迁移引用 | 不提供 JBIG2 编码器；使用已有 RGB/RGBA/JPEG 替换 |

默认构建必须包含两个进程内后端，不提供运行时可选后端或系统工具回退。表中的保存/导入不代表对范围外编码作像素验证。

## 后端审查与预算契约

三个新增 crate 为 MIT OR Apache-2.0，兼容项目 AGPL-3.0-only；Rust 最低版本 1.92，本机 1.96。精确版本锁定在 Cargo.lock。比较原生 OpenJPEG/jbig2dec 后选择纯 Rust，避免新增原生构建和裸指针生命周期；MuPDF/OpenJPEG/jbig2enc 只用作独立验收工具。

后端源码审查覆盖元信息解析、component/region 位图分配、halftone grid、共享段以及 decoder sink 的所有权。本版采用前置输入/像素/结构限额和保守 scratch reservation；输出及 Globals 实际保留容量由 OperationBudget 持有。内部临时 Vec 未接入项目 allocator，保守额度不是实测峰值或 RSS 硬上限，也不是 CPU 超时。两后端都不能直接作为任意不可信输入的安全解码服务；服务层仍需进程隔离和资源/时间限制。未支持组合不得静默降级为空白。维护状态和精确版本 OSV 检查在最终验收登记，不承诺没有未知漏洞。

## 公共入口

`InlineImage::{new,dictionary,encoded_data,dictionary_range,data_range,to_content_bytes}`、`Operator::inline_image`、`ContentBuilder::draw_inline_image`；页级提取/替换/删除/变换与嵌套图像操作沿用文档快照认证。解码使用过滤器模块的进程内入口及预算入口，JPX 另提供 `inspect` 和带元信息的 `decode_with_budget`。图片编码器、OCR 和布局推断不在此版本。
