# v0.7 字体输入与验证矩阵

日期：2026-10-15。源码 `47e2383` 的 Type3 A 阶段通过专项、独立验证及完整工作区 1,188 项回归，证据见 [阶段验收](v0.7.md#type3-执行阶段验收)；B/C 仍未完成。本矩阵区分已有代码、当期已验证组合与待补工作，不以解析入口存在推断所有字体均可绘制。

## A 阶段 Type3

| 单元 | 当前支持范围 | 明确限制或验证入口 |
|---|---|---|
| 字体模型 | 单字节码、Encoding/Differences、Widths、FontBBox/Matrix、间接字段和 CharProcs | 缺失字段、非法类型/数值、过期或跨文档快照拒绝；`v07_type3_model` |
| 度量与位置 | Widths 取字形空间宽度；FontMatrix 改变形状，推进只取水平分量；Tf/Tz/Ts/Tc/Tw/TJ | CharProc 与 Widths 不一致拒绝；非标准矩阵及正负变换独立对照 |
| 绘制 | Tr=0、alpha=1、Normal 混合；d0 图形，d1 继承颜色且仅允许 stencil 图像 | 非默认 Tr、透明度、字形内文本、ExtGState、sh 和透明组拒绝 |
| 资源 | 字体显式独立作用域，省略时回退到页面；Form 沿用已有契约 | 显式空字典不回退；嵌套字体/页面同名资源隔离回归 |
| 提取与编辑 | 字符码、Unicode、字符位置、操作来源、TJ 项/字节范围；已有原代码/整次绘制编辑 | 不新增 Type3 Unicode 编码、保留 advance 的宽度聚合或字形内部编辑 |
| 保存与导入 | 原编码保留；共享 CharProcs/资源按现有引用图复制 | 源文档释放后读取/绘制、共享页删除隔离、R6 及权限测试 |
| 预算与失败 | Type3 字体及 CharProc 解码/解析共池；字形与 Form 共用逻辑操作/路径/流解码工作额度 | 既有图像解码沿用图像限额；原有状态/资源克隆及原生分配仍有计账排除项，不是全页统一预算或 RSS/CPU 硬限 |

独立正向矩阵为 12 页：常规、页面旋转 90/180/270、水平缩放/上移、非标准 FontMatrix、负字号、负水平缩放、裁剪、图像、stencil、非 Group Form。生成器和检查入口为 `docs/check-v07-type3-render.py`；Tr=3/7 保留为显式拒绝案例，不计作像素成功。原始模型/执行结果不等于所有 Type3 图形组合正式支持。

## B 阶段已有能力与待补验证

以下为源码盘点，除 Type3 本期结果外，不声明已完成 v0.7 验收。既有 v0.3 范围仍以其 [固定字体与公开文件矩阵](v0.3-support.md)为准。

| 单元 | 已有实现/证据 | 本期下一步 |
|---|---|---|
| Simple 字体编码 | `simple_font.rs`、`encoding.rs`：预定义编码、Differences、字形名、缺映射报告；已有 Core14 固定样本 | 独立对照 code→glyph 与 code→Unicode，不用 Unicode 猜测覆盖 PDF 编码 |
| Type0/CID | `type0.rs`、`cid_font.rs`：CMap、CIDToGIDMap、W/W2；已有 Identity-H/V 固定静态 TrueType | 扩充非 Identity、多字节与非同值 CID/GID，核对竖排原点和显式缺失映射 |
| ToUnicode/CMap | 已有 1～4 字节、codespace、继承、代理对及多标量单元；Type3 新增多标量正例 | 冻结单元与独立生产者的逐格对应；不能只用少数案例泛化 |
| Type1/PFB | Descriptor 可解码 FontFile；Core14 PFB 通过既有 FreeType/Skia 绘制 | 与独立提取/轮廓交叉验证；`Type1Program::try_new` 仍未实现，不能据此说 PFB 完全不能绘制 |
| CFF/OpenType | Descriptor 可解码 FontFile3，CIDFontType0 与 FreeType/Skia 有入口 | 必须新增正向 CFF/封装及 code/CID/GID/轮廓样本；不能把空 OpenTypeProgram 类型当作已验收解析器 |
| TrueType/子集 | 已有 glyf、静态 H/V、复合字形和两个公开文件；TT cmap 实际解码选 0/4/12 | 复验并记录其他 cmap/字体格式限制，不要求所有子集器或 shaping |

已知公开 `UnitaryMethod.pdf` 的 v0.3 Unicode 缺口仍需单独定位，不能改标为通过；中文公开文件的原字节严格解析限制也不随新功能自动消失。缺字体、缺映射和替代字体继续显式区分。

## C 阶段待实现契约

字形运行写入需验证目标页字体、PDF 字符码、CID/GID 映射及 Unicode 对应，接受显式位置，不把 shaping 输出的 GID 直接当成 PDF 字符码。位置单位、字号/矩阵、水平/竖排输入和不可表达映射的错误必须先冻结；失败不留下部分内容，沿用事务、权限和共享资源隔离。当前只有已有编码字符串/builder 能力，尚无本期字形运行 API。
