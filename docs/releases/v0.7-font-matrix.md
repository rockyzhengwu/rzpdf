# v0.7 字体输入与验证矩阵

日期：2026-10-15。最终候选 `8a901e0` 的 A/B/C 冻结矩阵已通过本地验收：完整工作区 1,208 项、独立字体/公开文件/子集/Type3 及视觉复核通过，证据见 [验收记录](v0.7-acceptance.md)。不以解析入口存在推断所有字体均可绘制。

## A 阶段 Type3

| 单元 | 当前支持范围 | 明确限制或验证入口 |
|---|---|---|
| 字体模型 | 单字节码、Encoding/Differences、Widths、FontBBox/Matrix、间接字段和 CharProcs | 缺失字段、非法类型/数值、过期或跨文档快照拒绝；`v07_type3_model` |
| 度量与位置 | Widths 取字形空间宽度；FontMatrix 改变形状，推进只取水平分量；Tf/Tz/Ts/Tc/Tw/TJ | CharProc 与 Widths 不一致拒绝；非标准矩阵及正负变换独立对照 |
| 绘制 | Tr=0、alpha=1、Normal 混合；d0 图形，d1 继承颜色且仅允许 stencil 图像 | 非默认 Tr、透明度、字形内文本、ExtGState、sh 和透明组拒绝 |
| 资源 | 字体显式独立作用域，省略时回退到页面；Form 沿用已有契约 | 显式空字典不回退；嵌套字体/页面同名资源隔离回归 |
| 提取与编辑 | 字符码、Unicode、字符位置、操作来源、TJ 项/字节范围；已有原代码/整次绘制编辑 | 不新增 Type3 Unicode 编码、保留 advance 的宽度聚合或字形内部编辑 |
| 保存与导入 | 原编码保留；共享 CharProcs/资源按现有引用图复制 | 源文档释放后读取/绘制、共享页删除隔离、R6 及权限测试 |
| 预算与失败 | Type3 字体及 CharProc 解码/解析共池；字形与 Form 共用逻辑操作/路径/流解码工作额度 | 既有图像解码沿用图像限额；原有状态/资源克隆及原生分配仍有计账排除项，不是全页统一预算或 RSS/CPU 硬限 |

独立正向矩阵为 12 页：常规、页面旋转 90/180/270、水平缩放/上移、非标准 FontMatrix、负字号、负水平缩放、裁剪、图像、stencil、非 Group Form。生成器和检查入口为 `docs/check-v07-type3-render.py`；Tr=3/7 保留为显式拒绝案例，不计作像素成功。原始模型/执行结果不等于所有 Type3 图形组合正式支持。

## B 阶段字符映射与字体兼容

冻结输入是 [v0.7 自有样本](../../pdf/tests/fixtures/v07/README.md) 的八页与既有 [v0.3 固定字体/公开文件](v0.3-support.md)。`v07_font_mapping` 有 8 项专项；CMap 继承、codespace、UTF-16 与缺失映射继续复用现有字体单元。最终版本结果以验收记录为准。

| 单元 | 本版实现与验证组合 | 支持边界 |
|---|---|---|
| Simple 字体编码 | WinAnsi/Core14、Differences 反转 A/B 的实际 GID；ToUnicode 可独立取另一 Unicode 序列 | 不用 Unicode 替换 PDF 绘制编码；无 ToUnicode 时仍为现有 AGL 标量回退，不新增完整字形名序列算法或嵌入 Type1 内建编码提取 |
| Type0/CID | Identity-H/V 静态字体；非 Identity code→CID 7/19→GID 1/2；四种字节长度及不同 CID 共享 GID | CIDFontType2 的显式 CIDToGIDMap/Identity；CID-keyed CFF charset→GID 不支持，不计作正向绘制 |
| ToUnicode/CMap | 映射键保留源字节数；无 codespace 时也不把 `<41>` 与 `<0041>` 混为一项；多标量、代理对、bfrange、继承/局部覆盖及缺失映射回归 | `Cmap::cid_for_char` 是带长度查找；旧 `cid(u32)` 在长度歧义时返回 .notdef 0；已有 65 个有许可预定义 CMap，不发现系统任意 CMap |
| 竖排度量 | W/W2 与 code→CID 独立，保留 advance、文字原点及 W2 向量；新增 `glyph_origin_display`，修正竖排 em/轮廓辅助几何 | 原 `position` 仍是文字原点；新公开 `vertical_origin` 字段对结构体字面量构造有迁移影响；不推断竖排 GSUB |
| Type1 | 原 PFB 分段连接后嵌入 FontFile；FreeType/Skia 实际读绘，MuPDF 对照 GID/像素 | 未新增纯 Rust Type1 程序解析器或 Type1 子集器；无编码/无 ToUnicode 的 pdfTeX 输入仍有缺口 |
| CFF/OpenType | 项目自有 name-keyed CFF Type1C 和 OpenType/CFF 封装；FontTools 独立轮廓/宽度与 Skia/MuPDF 绘制对照 | 使用现有原生字体后端，不宣称空 `OpenTypeProgram`/`Type1CProgram` 是通用已验收解析器；不支持 CFF2、变量/彩色字体或所有封装组合 |
| TrueType/子集 | 简单 glyf、静态 H/V、复合字形、原 GID 保留与新增字符编辑复验 | Rust TT cmap 解码为 0/4/12；其它格式按现有拒绝/跳过策略，不新增所有格式或子集器 |

公开 `UnitaryMethod.pdf` 在兼容模式仍缺少 234/296 个 Unicode 映射，严格模式拒绝不合规 object 0 代次，不能改标为通过。既有粤语维基百科和 Scanner-test 在本次同 hash 复验中均严格打开、完整提取并严格保存重开；粤语文件的旧 v0.3 严格拒绝结论已由本次结果取代。缺字体、缺映射和替代字体继续显式区分。

同整数但不同长度的字符码在项目单元中按原字节区分。试验中 MuPDF 对 `<41>`/`<0041>` 的 CID 选择发生数值别名；多个 code 共享一个 CID 而声明不同 Unicode 时，其提取也发生覆盖。这两个组合不纳入跨阅读器正向矩阵，原失败证据保留。正向多字节样本用互异源码与 CID；不同 CID 可以共享同一 GID，独立核对 Unicode 而不是只看像素。

## C 阶段显式字形运行

新增 `GlyphRun`/`PositionedGlyph` 和 `overlay_page_glyph_run[_with_budget]`。每项是一个已有 PDF 编码字符，带显式文字原点、可选 GID 断言及 Unicode 断言；每个字形独立 Tm/Tj。位置为 run.matrix 前的用户单位，不是 em；竖排仍应用 W2。不会写入新的 ToUnicode/CIDToGIDMap，不将任意 GID 当作 PDF 码。

11 项写入专项覆盖水平/静态竖排子集、继承状态重置、矩阵、共享页及同名 Form 字体隔离、外层事务回滚、配额邻居失败释放/重试、全量/增量严格重开、R6 权限及签名源保护。八页独立门禁核对显式定位、GID、Unicode、W2 和像素。详细契约、示例、预算排除项及迁移说明见 [字形运行指南](../glyph-runs.md)。Type3 写入、缺程序、替代字体、.notdef、越界 GID、错误 Unicode 和不可表达映射明确拒绝。
