## API migration

`Document` remains the non-generic owned facade; legacy `PdfDocument<R>` remains available. Default constructors use Compatible; default save and incremental output remain Classic. Existing exhaustive `SaveOptions` and `IncrementalSaveOptions` literals remain valid because layout selection uses separate enums/methods. `Public ObjectInfo` fields and constructor signatures are unchanged.

Full layouts: Classic, XrefStream, XrefStreamWithObjectStreams. Incremental layouts: Classic and XrefStream. Layouts do not authorize version upgrades, change encryption identity/permissions, expose signed-file rewriting or enter a prepared signature plan. See [advanced saving](../advanced-saving.md) for runnable calls and the [frozen boundary](v0.12-boundaries.md) for version/protection rules.

`structure_diagnostics()` and `read_provenance()` are additive. Fixed reason enums and provenance/layout enums are non-exhaustive; callers should include a fallback match arm. Reports are bounded and lazy, separate from content events. No new fields are required in ParseOptions/Limits.

Explicit recovery returns a different `RecoveredDocument`, not a relabeled `Document`. The profile forces Strict object grammar regardless of ParseOptions.mode. Do not migrate existing `Document` variables by unwrapping or casting: the read-only type intentionally has no such operation. Render through its detached DisplayList, or read detached Info/raw metadata. See [recovery guide](../file-recovery.md) and `render/examples/v012_recovery.rs`.

## Failure and output contracts

Full/incremental serialization does not commit the source or alter its immutable baseline. A later append must reopen output bytes. Exact no-op retains source bytes without a new revision or random identity. Failed edits roll back storage/allocator/commit state, although old snapshots/tokens can invalidate and should be reacquired.

Writer/file save methods serialize first. A caller-owned writer can still contain partial bytes after host I/O failure; file methods use the existing independent-output atomic replacement strategy, not in-place append. Example generators use create-new paths. Recovery creates no PDF output at all; the rendering example creates its directory only after successful interpretation and refuses an existing directory.

Tracked OperationBudget bytes, policy object/work limits and process RSS are distinct. The benchmark records tracked peak and timing; `/usr/bin/time -l` records macOS process peak RSS separately. Neither is a universal memory/performance guarantee. The coverage index and support matrix retain unsupported profiles; v0.12 completion does not imply API stability or a v1.0 release.
