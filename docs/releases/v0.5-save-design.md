# V05-00：保存架构决策草案

状态：保存架构及 V05-A 限定增量 writer 已实现并通过阶段验收（`c7ed23a`）；B/C 候选继续复用该边界，整版状态以验收记录为准。日期：2026-10-14。

关联：[v0.5 实施与验收计划](v0.5.md)。本文确定增量保存所需的内部边界，并逐切片登记实现证据。

## 现状与首要缺口

`parse_xref` 找到末次 startxref 后合并历史引用表，但调用者当前主要拿到合并后的 `CrossRefTable`。`PDFContext` 持有可选 parser、源对象缓存和 `DocumentState`；变更在 `DocumentStore` 的 Upsert/Deleted 中。全量 writer 会 materialize 全部对象，不能原样作为增量 writer。

首先补齐的是“可验证的源保存基线”，而非先写一个追加 xref 的函数。没有可靠源字节和末次偏移，写出的 Prev 即使能被本库恢复，也不能证明追加结果正确。

## 决策 1：保存不改变文档基线

本版保留 `save_to_bytes` 的全量默认行为；增量用显式入口，不能因为全量路径不支持某个对象便自动切换模式。

保存是只读操作：成功和失败都不清空 Store、不改变 identity/revision/commit_revision、不重置 parser 或源缓存。同一个文档每次保存都相对同一源。需要在上次输出后继续追加历史时，调用者重开输出文件。

这避免了保存成功后源句柄、缓存、对象号和编辑令牌同时 rebase 的复杂事务。以后若新增原位提交 API，另立设计，不隐式改变旧语义。

## 决策 2：不可变源快照与变更快照分离

建议内部职责（名称待实现时确定，不是承诺的 public API）：

| 职责 | 保存的数据 | 不负责 |
|---|---|---|
| SourceBaseline | 精确源内容/稳定读取方式、长度、末次 xref 偏移、解析模式与有效性 | 编辑对象与解密后的缓存 |
| ChangeSnapshot | 稳定排序的 Upsert/Deleted、当前 trailer、revision | 修改文档或更新源 |
| SavePlan | 模式、版本/保护策略、输出和临时内存预算、预检结果 | 密码学原语、磁盘原子替换 |
| ObjectEncoder | 对象编码、字符串转义、流编码与预算 | 遍历整棵对象图来决定保存模式 |
| IncrementalWriter | 原前缀复制、变更对象、xref/trailer/EOF | 源恢复、原地改写、默认处理签名 |

优先对 owned bytes 源实现可验证基线；泛型 Read+Seek 输入必须有明确快照/稳定性策略。仅保存长度或不带约束的句柄不足以防止外部源内容变化。预算不足时拒绝，不为便利无界复制原文件。

首次输出仍返回完整 PDF 字节，不承诺零拷贝；后续流式输出可以复用相同 SavePlan，但必须公开部分 Write 失败可能已写出前缀的语义。

## 决策 3：两种 writer 共享编码，不共享对象遍历

全量 writer 仍枚举全部需保存对象；增量 writer 只枚举编辑覆盖层。源缓存中“曾经被读取”不等于“被修改”，不得进入追加对象列表。

实现时先抽小范围编码辅助函数，保留旧全量输出测试。不得为增量保存顺带重构内容、字体或渲染模块。

增量偏移统一按最终输出的绝对字节位置计算，算术使用 checked 操作；传统 xref 位宽不能表示的偏移明确拒绝，不截断。预算包含原字节输出、快照、xref 及临时对象编码空间，分别记录。

## 决策 4：先支持传统 xref，再逐项扩输入矩阵

首批实现：严格读取、非线性化、未加密、未签名、传统 xref 的文档。追加传统 xref 表，生成正确 Prev，保留 Root/Info/ID 等语义，不把原 trailer 中 XRefStm/Prev 原封不动拷进新 trailer。

继而扩展 xref stream/对象流、已有增量链和 hybrid 输入。不能在输入矩阵尚未通过独立工具验证时宣布通用支持。xref stream 转成传统追加链的行为也必须有单独 fixture。

新建无源文档显式走全量保存；无修改的合法增量请求返回原字节。新增后删除、删除已有对象、非零代次、源中空闲对象分别测试。首期禁止对象号复用，删除必须维护正确 free 条目/代次并排除悬空引用。

## 决策 5：安全和签名是显式策略层

加密对象在 parser 解码边界只解密一次；写出前按明确保护策略加密。保存选项不能在未授权时把保护文档转成明文。安全 handler 不能通过普通 Crypt filter 的 Identity 分支冒充完成。

签名准备必须基于已经定稿的保存字节。准备结果绑定文档 identity/revision，完成签名只能替换预留区域。默认拒绝已签文件编辑；低层 API 与保存入口都须考虑绕过检测，不能只在高层便利函数加检查。

本期不把“字节没改”报告为“证书可信”，也不把外部验证工具的存在包装成本库已经实现完整验证服务。
